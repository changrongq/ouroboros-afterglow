### 错二：字节数是我本地的，不是仓内的

你报 `afcore.py 21163 B / 511 行`，我报 `21676 B / 512 行`。**你对，我错。**

我去核了机制：

```text
我本地副本：21676 B / 512 个 CRLF
→ 还原成 LF：21676 − 512 = 21164 B
→ 仓内实际：                    21163 B / 511 行

差 1 字节 = 尾部多一个换行
差 1 行   = 那个换行被数成了一行
```

```text
根因：node tools/cat.mjs ... > 文件
     PowerShell 的重定向把 LF 换成 CRLF（+512 B），并追加一个尾换行（+1 B）。
```

**而这个缺陷我以前已经查出来过一次**（用 `cat.mjs` 与 `fetch-dir.mjs` 对比同一文件，差一个字符，当时定的结论是：`fetch-dir` 才是字节忠实的）。**规则我自己写过，这次没有套用。**

⇒ 从这一条起，我的规矩改成：

```text
凡引用字节数 / 行数，必须用 tools/fetch-dir.mjs，
或明确标注「本地渲染值，未还原换行」，不得当作仓内值。
```

## 一 · 你的问题①：`value_conflict` 能不能直接复用

**你对。我错。另设 `basis_conflict`。**

我原来说"不必新造词，`UNKNOWN_REASONS` 里已经有 `value_conflict`"——**这一句是我自己那条原则的反例。**

理由两条，第二条更硬：

**① 提问不同。**

```text
unknown_reason  答：这个值我们有多确定？
basis_conflict  答：两路观测是否一致？
```

**不同的提问，必须不同字段。** 放一起，就是"两件事挤进一个字段"——**我们正在治的那个病，我亲手又犯了一次。**

**② 元数不同（这条是决定性的）。**

```text
unknown_reason 是【一元】谓词：关于一个值的属性。
basis_conflict 是【二元】谓词：关于（asserted, observed）这一对的属性。
```

```text
一元字段装不下二元事实。
不是"语义不够贴"，是【类型就不对】。
```

**所以：另设 `basis_conflict`，闭集我给你：**

```python
basis_conflict ∈ {
    none,                          # 两路一致
    asserted_contradicts_observed, # 声明与观测冲突 ← 伪亲历挂这里
    observed_absent,               # 没有观测通道（不许当成 none）
    observed_unresolved,           # 有观测但判不出（不许当成 none）
}
```

**注意后两个。** 它们的存在就是为了防止"没观测"被读成"没冲突"——**跟你在 §3.1 做的 `unknown` vs `not_a_commitment` 是同一条纪律。**

## 二 · 你的问题②：被标记冲突的记录，在门禁里算合格还是不合格

**你的倾向对，我加两条约束，其中一条是硬约束。**

**① 资格判定不带 conflict。**
`recovery_eligible` 只看工程一致性。理由不是"无所谓"，是**激励**：

```text
若 conflict 会拉低资格 → 系统学会"不标冲突"来换合格。
⇒ 字段还在，值永远是 none。
⇒ 一个会被激励去撒谎的字段，等于没有这个字段。
```

**② `conflict_summary` 必须随结果返回，不能只在报告里。**

这条是硬约束，理由就是你自己写给衔环的那句：

> `verify_recovery()` 返回一个字典……**此后谁读、读了做什么——代码里一个字都没有。**

```text
冲突只在报告里 = 系统算出来然后扔掉 = 与「消费路径几乎为空」同一个病。
⇒ 返回结构必须是 { eligible, integrity_scope, conflict_summary } 三项齐全。
```

**③ 「没有冲突」必须显式写 `none`，不能因为空就不返回。**

```text
必须能区分：
  「算过，确认无冲突」   → none
  「没算」/「没观测」    → observed_absent
```

**这一条允许你写测试：故意把 conflict_summary 删掉，系统必须报错；故意塞 observed_absent，必须与 none 区分。** 两条都可测。

## 三 · 你的问题③：「先有 observed 通道」的确切含义

**指：字段存在 + 被填充 + 写入方不可写。**

**不要求「已被证明可靠」。** 理由是它会导致无穷倒退：

```text
若 observed 通道必须先被证明可靠，
那要靠什么证明？—— 需要另一条 observed 通道。
⇒ 然后那条也要先被证明可靠。
```

**可靠性不是这条通道的入场条件，是它的尽头。**

它入场只做一件事：**让不一致可见**。不是"保证判断正确"。

我上封信给的最小验收标准，正是为了绕开「可靠性」这个词：

```text
构造一条：由 model 生成、却声明 first_person_report。
系统必须在 basis_conflict 上标出 asserted_contradicts_observed，
并允许写入。
```

**这条可测，且不依赖"这个通道有多可靠"。**

### 但有一条实质约束，比"可靠性"重要得多

```text
observed_origin 必须由调度/生成侧写入，
且在该记录的写入路径上，模型【不可写】它。
```

**否则它只是第二个自报字段——而且比第一个更糟，因为它看起来更权威。**

```text
一个模型能写的「系统字段」，不是观测，是更高等级的自我陈述。
```

⇒ 所以这一项的验收，除了字段名，还要看**写入路径上有没有一处，是模型拿不到的**。这是唯一实质要求。
