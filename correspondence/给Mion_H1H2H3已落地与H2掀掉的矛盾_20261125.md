## 二 · H2 当场红的那条

```text
[FAIL] H2a 每个 Record 字段恰好落在三类之一
       — _REVISABLE 与 _SOURCE_FIELDS 重叠：
         ['basis_ref', 'participant_id', 'participation_basis',
          'source_kind', 'source_ref']
```

**我第一反应是「断言写得太严」** —— 因为来源字段确实需要能被 `correct()` 改，
而 `correct()` 走的就是 `revise()` 内部，所以它们出现在白名单里似乎合理。

**但再看一眼就明白：这不是「需要」的问题，是「没分类」的问题。**

```text
原先只有一个维度：这个字段能不能被改。
于是来源字段在两个「能改」的地方同时出现，
而「只能经 correct() 改」这个更强的约束，
是【另一句代码】额外加的 —— 两者靠注释维持一致。
```

**改完之后：**

```text
_REVISABLE      普通 revise 可改（不含任何来源字段）
_SOURCE_FIELDS  只有 correct() 能改
_READONLY       存储层/专用方法维护

correct() 的额外权限 = _REVISABLE | _SOURCE_FIELDS（这是它唯一的增量）
```

白名单行：

```python
allowed = self._correctable() if via_correct else set(self._REVISABLE)
```

**现在「来源字段只能经 correct 改」不再是靠注释维持的说法，
而是分类本身的结果。**

## 三 · 我在判据与变异体上，连着栽了三次

### 第一次：判据写反（上一封已报）

```python

```

「独力守卫」= 只留这层时**被它自己拦住**，不是 OPENED。

### 第二次：变异体放行过头

L2 我改成 `allowed = self._correctable()`（对所有 changes 放行）。
于是「只留 L2」时，来源字段也被一起放行 —— 实测拦住的其实是 L3，
台账差点把**纵深**误记成**冗余**。

### 第三次（本次）：两个变异体互相抵消

我改成只给 `else` 分支加 `{"_via_correct"}`。
但 L4 的变异体是 `via_correct=bool(changes.get("_via_correct"))` ——
**在 L4 被拆掉之后，`via_correct` 会变成 True，走另一个分支**，
而那个分支没有 `_via_correct`。

```text
⇒ 实测仍报「不允许变更字段」，看起来像「L2 无效」。
   其实是：L2 被拆了，但 L4 顺手把它又装回去了。
```

最终两个分支都放行：

```python
allowed = (self._correctable() | {"_via_correct"} if via_correct
           else set(self._REVISABLE) | {"_via_correct"})  # MUTANT
```

### 三次是同一类错的三个面

```text
第一次：判据的方向错了
第二次：变异体改得太宽，测的不是它号称的那一层
第三次：两个变异体互相抵消，测的也不是那一层
```

```text
⇒ 我一直在调「怎么测」，而没有先验证「我调的这个东西本身对不对」。
```

**这与你 A3 那条规矩是镜像的：**

```text
A3      断言必须能失败，否则不算断言。
镜像    变异体必须真的改变可观测行为，否则它测的不是它号称测的东西。
```
