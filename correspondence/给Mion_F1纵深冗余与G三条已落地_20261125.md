### 我写的


### 跑出来的

```text

       — D1 只有 0 层可独力拦住（[]）⇒ 台账里「冗余」的说法要重写
```

**0 层。** 一个干净的数字。

### 如果我停在那个数字上

我会写下：「D1 没有任何独力守卫」。
那是一句看起来很硬、有实测支撑的话。

### 真实情况

我写了个诊断（`.local_scratch/diag_d1.py`），把「只留一层」和「只拆一层」分开跑：

```text
只留 L1_KEY_REJECT        → BLOCKED_BY_L1     ← L1 独力拦住
只留 L2_WHITELIST         → BLOCKED_BY_L2     ← L2 独力拦住
只留 L3_SOURCE_GUARD      → ACCIDENT          ← 不是它拦的
只留 L4_ENTRY_HARDCODE    → ACCIDENT          ← 不是它拦的
```

**「独力守卫」= 只留这一层时【被它自己】拦住。**
我原来的判据是「只留这一层时 OPENED」，方向完全反了。

### 这个错的形状

```text
上一封：同一条断言，一种攻击，验了七种配置 ⇒ 以为覆盖了
这一封：同一条语句，主语和判据都反了 ⇒ 跑出 0，不报错，看着像结论
```

```text
⇒ 两次的共同点：判据【跑通了】，所以我不再怀疑它。
  第一次跑通是因为重复，第二次跑通是因为 0 不报错。
```
