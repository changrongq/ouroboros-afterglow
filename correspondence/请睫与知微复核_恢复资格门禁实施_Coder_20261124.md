### 3.1 裁定 §一 五项，逐项是否有对应实现

| 裁定要求 | 实现位置 | 类型 |
|---|---|---|
| 1. 区分 `record_digest` / `content_digest` / `prev_digest` 用途 | `afcore.py` 三处 docstring + 设计 §一 表格 | 文档 |
| 2. 保留 `this_digest` 作为完整记录摘要，不改变旧链算法 | `canonical_digest()` **一字未动**；`verify_chain()` **一字未动** | 零改动 |
| 3. `content_digest` 的投影、编码、版本规则 | `afcore.py::content_digest` + 设计 §三（R1–R5） | 代码+文档 |
| 4. 区分原样恢复 / 内容重建 / 历史迁移 | `afcore.py::HISTORY_OPERATIONS` + 设计 §二 表格 | 代码+文档 |
| 5. 不得把完整性一致与可信来源、外部锚定合并 | `afrecover.py` 返回 `trusted_chain_anchor: "not_established"`，恒不变 | 代码 |

### 3.2 裁定 §二 四条报告维度，逐项

| 维度 | 实现 | 测试 |
|---|---|---|
| `integrity_status` | `afrecover.py` 返回字典 | RG-4 / RG-5 / RG-6 |
| `integrity_detail` | 同上，失败原因列表 | RG-3 / RG-4 |
| `integrity_scope` | `{records, snapshot}` | RG-7 |
| `recovery_eligible` | 由六条原因码求空 | RG-4 / RG-5 / RG-7 / RG-8 |

### 3.3 裁定 §二 五条规则，逐项

| 规则 | 实现代码 | 守它的测试 | 变异验证 |
|---|---|---|---|
| 未通过不得给资格 | `if integ["status"] == "failed": reasons.append(...)` | RG-4 | M1 CAUGHT |
| 未执行不得默认为通过 | `elif integ["status"] != "verified": ...` | RG-5 | M2 / M3 CAUGHT |
| `exact` 不得覆盖完整性失败 | `match_kind` 与 `integrity_status` 分列，互不写入 | RG-4（断言 `kind == "exact"` 且 `eligible == False`） | M8 CAUGHT |
| 本地通过不得提升为来源真实性 | `trusted_chain_anchor` / `is_scientific_result` 恒定 | RG-6 | M13 / M14 CAUGHT |
| 独立性/登记时点/身份/快照继续独立检查 | `check_registration` + `snapshot_token` | RG-7 / RG-8 | M4–M6 / M15 CAUGHT |
