### ② denominator_attrition 与 cause 归因

**这段是本轮改动最多、也是凌翼两次找出缺陷的地方。请重点看。**

**改动**（`afimportance.py`，构造 attrition 的循环）：

```text
denominator_attrition = len(attrition_ids)
denominator_attrition_ids      = 被移出分母的记录
denominator_attrition_cause    = {记录: 该次纠正引用的依据记录 id}
denominator_attrition_unknown  = 无法归因的记录清单

算法（按历史版本逐步比对）：
  for h in history(rid):
     if prev_basis == first_person_report and this_basis != first_person_report:
         n_new = len(this_edges) - len(prev_edges)
         cause = this_edges[-n_new].to_id if n_new > 0 else None
     prev = this
  ⇒ 不在第一处跃变 break（记录可退出→恢复→再次退出）
  ⇒ 不用 to_id 集合差（重复引用同一依据会误判）
```

**两次失效方式（凌翼在静态读代码时发现，我均已复现）**：

```text
第一次：取当前 relation 列表【第一条】correction_of 就停。
        而 correct() 是【追加】边 ⇒ 多条时首条属于最早那次。
        反例：R →(A 纠正，仍 first_person) →(B 纠正，退出分母)
              旧给 A，正确 B。

第二次：用【to_id 集合差】判断新增边。
        同一依据被重复引用时，两次 to_id 相同 ⇒ 集合差为空 ⇒ 误判无新增边。
        反例：R 第 1 次引用 A（A 当时 first_person）→ R 仍在分母
              A 自身被纠正为 record_only
              R 第 2 次仍引用 A → R 退出分母
              此时确有新边 ('A','cite #2')，旧判据报 ATTRIBUTION_UNKNOWN。
```

**测试**：`test_attrition_preflight.py` **15/15**（其中归因 8 条）

```text

AP-2   三次纠正 → 取真正跃变那次
AP-3   退出→恢复→再次退出 → cause 跟最后跃变
AP-4   单次纠正不退化
AP-5   缺边 → ATTRIBUTION_UNKNOWN 且列入 unknown（不静默给 ID）
AP-6   反证：旧算法给 'A'，新算法给 'B'
AP-13  凌翼反例二（同依据重复引用）→ cause='A'，不误报 UNKNOWN
AP-14  反证：集合差给 []（误判），边数差给 1 条（正确）
```
