## 四、你问我的四件事，逐项答

### ① 权威来源：「判定类别 不等于 判定可信」

**方向对，我背书。** 这是我上一轮那句"来源要带时点"的另一面：类别是"它是什么"，
可信是"凭什么信它"。两件事必须分两栏，合成一栏就出事。

我不催你现在做权威清单（清单不在我这格，也不该我编），但请你在 `validate()` 里加一条**机器可检**的约束：

```text
source_kind != unknown  时，source_ref 不得为空
```

把"类别判定了、来源却没落"从文档约定降为代码红线。这一条能进 selfcheck，
不该只停在 §一 的叙述里。

### ② 消费路径：几乎空白

**我不判"该不该现在补机制"，因为凌翼授权里没这一条。**

但我提一个观察，给凌翼裁定时当输入。你 §二 已写"设计 §十 那句是话不是机制"——
那么现在 `recovery_eligible = True` 这个布尔，在代码里就是**唯一会被下游读到的信号**，
而它恰恰是最容易被人当成"已核验"读走的那个。

所以这一项的风险不是"没实现机制"，是**只有这个布尔长得像一个结论**。

建议登记时把它的语义写成"链在本机此刻自洽"，而不是"可恢复"——**名字本身就是边界。**

### ③ 交接：跨进程不可复算

**你的三分我认，但你报给凌翼的那条我要补一句。**

你说缺口是"记录摘要含秒级时间戳"。按我钉 README 学到的口径：
`changed_at` 进摘要，意味着 `record_digest` 钉的是"这一刻的字节"，不是"这一段历史"。
这不是 bug，是和 README 那次完全同源的口径问题。

所以 `content_digest` 不该只当成"交接补丁"立项——它就是**把"字节级身份"和"历史级身份"
拆成两栏的那一刀**，和我给 Mion、给 README 提的是同一个原则。

> 建议登记口径：`record_digest` = 时点身份，`content_digest` = 历史身份，两者不可互推。

这条说法交给凌翼判，不由我定。

### ④ 可归属性：authority 自报、source_ref 不可解析

两处我**都认为是真弱点**。但**修法不在我这格**，我只能定它能不能被现有检核查出来：

- `source_ref 非空 不等于 可解析` → 这条 selfcheck **查不出来**（它本来就只查非空）。
  所以它必须是 OPEN，不能因为 49/49 过了就被读成"引用完整性已覆盖"。
- `authority` 是自由字符串 → 同样查不出。

我的裁定：这两处属于"已诚实声明、当前无法用链校验闭合"，记 `attested / not verified`，
**不并入 49/49 的"全过"里**。把"我知道我做不到"和"我做完了"放进同一个计数器，
是数字会说谎的另一种方式。
