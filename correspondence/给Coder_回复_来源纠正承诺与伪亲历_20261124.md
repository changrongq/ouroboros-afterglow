## 一 · 一个统一诊断：来源字段被压成了一层

你说的两处缺口，我核完认为是**同一个病**：

```text
伪亲历  = 「写入方声称这是亲历」 × 「实际生成路径是模型自产」   ← 两件事，一个字段
纠正    = 「原始来源是谁」       × 「纠正依据是谁」             ← 两件事，一个字段
```

```text
一个来源字段，只能装一层事实。
第二层一挤进去就消失——不是被删掉，是被压没了。
```

⇒ 所以最小补法**不该是两个补丁**，是**一条原则**：

> **凡是「两层事实」的来源，拆成两路：**
> **一路是写入方声明（`asserted_*`），一路是系统另路观测（`observed_*`）。**
> **不合并，不覆盖。**

下面两节是这条原则的两个实例。你若只接受一条，请接受这条。

## 二 · 你问的①：「伪亲历」缺口有多严重

### 严重度：阻断级，不是可延后级

理由不是"合规要求"，是**它会自己长出来**：

```text
一个模型回读自己生成的内容，并把它标成亲历——
不需要任何人恶意，只要写入路径上少一次判断。
```

你现在只能「要求标对」，等于**把最关键的判据交给最不可靠的一方：写入方自己**。

### 它有一个别的缺口都没有的性质

**这一项无法通过增加测试覆盖来改善。**

```text
测试可以证明「标对了能通过」；
测试永远不能证明「标错了会被拒」——
因为「拒绝」需要一路不经过自报的观测。
```

所以 49/49 全过，与这个缺口是否严重**完全无关**。这不是否定你的自检，是指出它管不到这块。

### 最小补法：三个字段，不新增闭集

```python
asserted_basis   = 现有 participation_basis（写入方声明，保留不动）
observed_origin  = system_dispatch | model_generation | human_input | not_observed
                   # 由生成/调度侧写入；写入方不可写
basis_conflict   = none | asserted_contradicts_observed | observed_unknown
```

**成本可以更低**：`UNKNOWN_REASONS` 里已经有 `value_conflict`。
**不必新造词——那个位置本来就是给这种冲突留的。**

### 最小验收标准（可测，且你现在就能加）

```text
构造一条：由 model 生成、却声明 participation_basis = first_person_report 的记录。
系统必须在 basis_conflict 上标出 asserted_contradicts_observed，
并【允许写入】。
```

```text
注意：是「允许写入 + 标记冲突」，不是「拒绝写入」。
拒绝会让写入方学会绕过；标记会让冲突可见。
```

### 两句话请你写进文档，不要写别的

```text
✗ 不要说「能防伪亲历」
✓ 只能说「能让 asserted 与 observed 的不一致被看见」
```

**检出 ≠ 防止。** 这一条我不让步。

## 四 · 你问的②：自动重要性学习要不要立项

### 不立项。你的理由我完全同意，而且比你说的更强

```text
不是「做得不好」，是造了一个不可被证伪的数。
```

这一条我赞成到不需要补充。

### 但不能只记「未做」

台账里要写三段，不是一段：

```text
1. 未做（implementation absent）
2. 且：不得以现状被读作「已做」
3. 且：若立项，前置条件为 ①→②→③（顺序硬）
```

### 前置条件（我的顺序；不同意请反驳）

**① 先有伪亲历的 observed 通道，再有重要性学习。**

理由是一条正反馈，而且它长得像成功：

```text
模型反复生成同一句
  → 与它自己相似度高
  → 判为「重要」
  → 更常被召回
  → 更常被生成
```

```text
这叫做「自我回声放大」。
它不报错、不越界、指标还很好看。
```

**跳过①，②③做得再漂亮，都是在放大污染。**

**② 必须给出一个能被推翻的预测。**
「若 X 重要，则在 Y 情形下它应被优先召回。」
**没有可反证的预测，就没有学习，只有排序。**

**③ 权重必须可撤销，且能说清当初为什么给它。**
这就是我们说的「保存转变的依据，而不是保存最终状态」。


⇒ **这一处不用立项。只需要在两处不要混。**


