## 二 · 观测现在在链外（这一条是本节唯一重要的）

### 事实

```text
record_observed() 的最后一段（afcore.py:577–582）：

  _body = cur.to_dict()
  _body["observed_origin"] = observed_origin
  _body["basis_conflict"] = conflict
  owned = Record(**{k: v for k, v in _body.items() if k != "this_digest"})
  self._live[record_id] = owned

  self._write_log.append({...})
```

```text
它【只写 _live，不写 _history，不重算摘要】。
```

### 后果

```text
_history 里第 1 版的 dict，其 observed_origin 是 None，
它的 this_digest 覆盖的是【那个状态】。

之后 live 变成 system_dispatch / 冲突值，
⇒ 【没有任何一版摘要对应这个状态】。
```

```text
verify_chain() 只迭代 _history（:601–626），
它不比较 live 与 history。
⇒ 链永远绿。
⇒ 把 live 的 observed_origin 改成任何值，不会让任何检查失败。
```

### 它是第一个这样的操作

```text
在此之前，所有改动都同时写 _live 与 _history（insert / revise）。
record_observed 是【第一个只改 live 的操作】。
```

```text
⇒ 它绕过了这个原型唯一的完整性机制。
```

### 请注意这个反讽

```text
我们做这一整套，是为了让「观测」能约束「声明」。
结果观测字段本身，成了唯一不受校验的字段。
```

### 有一处例外，而它让问题更糟

```text
若之后对该记录调用 revise()：
  revise 的 cur.to_dict() 会带上 observed_origin，
  重算摘要并写入 _history
  ⇒ 那一刻起，观测才进链。
```

```text
但【观测过的记录，恰恰最可能不再被修订】——
它就是那条“已经定好了、用来作证”的记录。
⇒ 在最需要它的情形下，它永远在链外。
```

## 三 · 修法：加一条观测链，不要塞进内容摘要

### 三条路，我选第二条

```text
(a) record_observed 后重算并替换 _history[0] 的摘要
    ✗ 会让「建立时状态」消失，等于把观测混进内容摘要
    ✗ 而且 revision 仍为 1，摘要与 revision 语义不一致

(b) 单独一条观测链 _observed_chain            ← 选这个
    每次 record_observed 追加一条：
      { record_id, asserted, observed, basis_conflict, at, prev, digest }
    最后一条的 digest 作为链头。
    verify_recovery 返回新增一项 observed_chained: bool

(c) 在文档里声明「observed_origin 是链外字段」
    ✗ 这不是修，这是把洞写成规格
```

### 为什么 (b) 对

```text
它让观测【第一次进入完整性范围】，且：
  － 不动 revision 序（verify_chain 不用改）
  － 不动内容摘要（content_digest 语义不变）
  － 冲突值本身也被摘要覆盖 ⇒ 改 basis_conflict 会断链
```

```text
⇒ 这一步之后，我想问的那个问题才有答案：
   「这条记录的“冲突判定”有没有被动过？」
   现在答不了。加了观测链就能答。
```

### 状态词，按你要的给（别再叫「通道」）

```text
OBSERVED_PATHS_SPLIT   = YES   （API 层：两条不同的写入路径）
OBSERVED_CHAINED       = NO    （观测值不在任何摘要内）
OBSERVED_PERMISSION_BOUNDARY = NOT_ACHIEVABLE_IN_THIS_PROTOTYPE
```

**这三个词分开写，不要合成一个 `FER_OBSERVED_CHANNEL`。**
它们答的是三个不同的问题，合成一个就又是一层压缩。

## 四 · 判定表两格：一格你对，一格我不同意

### 4.1 `third_person_report × model_generation` ⇒ **冲突。你对，但理由要换**

```text
你写的理由：模型生成的内容没有第三方来源可言。
```

```text
我要求换成：断言是「我被某人告知」；
           观测说「这条是模型生成，没有任何被告知的痕迹」。
           ⇒ 【断言与观测相反】，这才是判冲突的根据。
```

**差别不在措辞，在可测性：**

```text
按「没有第三方来源可言」⇒ 要先去定义什么叫「有来源」，判定不可终止。
按「断言与观测相反」    ⇒ 只要看 observed 有没有 human_input 的痕迹，可判。
```

**用「相反」而不是「不存在」，是把一个哲学问题降成一个字段比较。** 这一条请写进文档。

### 4.2 `record_only × model_generation` ⇒ **我判 `none`，你判冲突，我不同意**

```text
record_only 的断言是什么：「这条记录不指向任何陈述者」。
model_generation 的观测是什么：「这条内容是模型生成的」。

⇒ 一个不指向陈述者的记录，由模型生成 —— 【两者不矛盾】。
```

```text
⇒ 应判 none。
```

**理由（这一条比上一格重要）：**

```text
弱断言不容易被违反 —— 这是它的【性质】，不是它的缺陷。
你若把「弱断言 + 不利观测」一律判冲突，
那你是在惩罚「诚实地不声称」。
```

**但这带来一个真漏洞，它必须被单独处理：**

```text
record_only 会成为【洗白档】。
把本该 first_person_report 的内容标成 record_only，
伪亲历就整体消失——而且指标会变好看。
```

**所以：**

```text
判定不改（none），但要【单独度量】：
  record_only_ratio = |asserted == record_only| / |取回集|
```

```text
并写进文档一句：
  「record_only 比例上升 ⇒ 伪亲历统计的分母被抽空。
    此指标不是合格率，是统计可信度的前置条件。」
```

```text
⇒ 这不是判定漏洞，是行为漏洞。
   判定管不了它，只有度量管得住。
```
