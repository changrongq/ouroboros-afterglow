## 1. 分母与 MN-10

取回 H、K、RO 三条合成记录。H 与 K 属于 first_person_report，H 无观测来源，K 的来源可核，RO 属于 record_only。实得未观测 1、已观测但未解决 0，unverifiable_ratio 为 1/2；record_only 的分母为 3，比例为 1/3。恢复入口也给出 RO 和 1/3。MN 套件另覆盖两类不可核来源同时出现，以及空范围返回 None 和 size=0。

MN-10 的公开入口差异可以保留，但请在 R2 旁写明输入域。传入 [H, RO, RO]，恢复入口去重后给 1/2，指标入口报 SchemaError。二者接受的原始输入不同。对于由唯一、已知 ID 构成的同一取回集，可以要求 record_only 成员和比例一致。若 Mion 的 R2 要求任意同一原始列表都有相同结果，本版没有满足那种要求。建议保留这条差异测试，避免调用方把两种入口互换。

## 2. 正常纠正与证据不足的历史

正常运行 correct()，先让 R 引用 A 后留在分母，再引用 B 后退出，实得流失 1、依据 B。将临时副本改回取累计首边，AP-1/2/3/6 均红；改回依靠目标 ID 是否曾出现来判断新增，AP-13/14 均红。两处旧错确实被用例守住。

第三种失效可以复现。保留相同版本和退出事实，仅在只读历史替身里让退出版本同时新增指向 A、B 的两条纠正边。afimportance.py 按边数增长取新增段首条，返回流失 1、依据 A、未知清单为空。另一次只把唯一新增边的 from_id 改为 B，仍给 R 登记依据 B。两个例子都没有用正常 correct() 制造异常，也没有改真实历史。它们检验的是 AP-5 已涉及的承诺，即当历史证据不足时能否承认归因未知。

建议只在前版纠正边是本版前缀、跃变处恰有一条可归属到 R 且目标有效的新增纠正边时签发具体 ID；如有独立事件绑定，也可用它消解歧义。否则保留流失数 1，cause 写 ATTRIBUTION_UNKNOWN，R 进入 unknown 清单。不要要求依据记录也在本次统计取回集内。这里的 cause 只指被引用的依据记录。

## 3. 前置检查的失败出口与 AP-15

AP-11 的锚点破坏走真入口，能在基线前停止并落下新失败报告。另一个真入口对照先保留上轮 COMPLETE 报告，再在临时副本中让目标文件无法按 UTF-8 解码。实得退出码 1、UnicodeDecodeError，磁盘报告逐字节未变，仍显示上轮 EVIDENCE_COMPLETE。本轮停止执行了，却没有给读取报告的人留下本轮的失败记录。mutation_preflight.py 的读取分支只接住 OSError，驱动直接调用该分支。

建议将目标解码失败纳入同一失败出口。回归用例先放置旧成功报告，再断言本轮有新 run_id、EVIDENCE_FAIL、baseline_ok=None、rows=[] 和可辨认的解码原因。只验退出码会漏掉这次问题。

AP-15 扫描三个名字，适合作为防止直接引用的提示。其第二段连续跑两次相同的 preflight，中间没有改变名册，因而只能说明同样输入得到同样结果。我的差分对照保持计划、ID 集合和锚点不变，仅颠倒登记 ID 的顺序：前置检查通过，独立调用 check_manifest_identity() 得到 consistent=False。建议把这一对相反结果加入 AP-15。它说明一种具体的身份变化能通过前置检查，并由后置身份检查辨出；足以说明两个阶段各自承担什么责任。
