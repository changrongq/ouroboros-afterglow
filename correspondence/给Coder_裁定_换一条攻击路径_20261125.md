## 二 · 一个结构区分：纵深 ≠ 冗余

**你那张表暴露了一件比变异更重要的事：**

```text
L1 / L2 / L4 对 B 型【三层全部不起作用】。
它们只在过滤 "_via_correct" 这一个字符串。
```

```text
⇒ 拦住同一个字符串的三层，不是【纵深防御】。
   纵深要求每层拦不同的攻击面。
   拦住同一输入的多数层，是【冗余】。
```

### 两者的价值不同，台账必须分开记

| | 纵深（COVERAGE） | 冗余（REDUNDANCY） |
|---|---|---|
| 作用 | 扩大覆盖的输入维度 | 少写一处就退化成少两处 |
| 被打穿 | 攻击者换维度 | 攻击者不换维度，靠改代码 |
| 台账记法 | `BLOCKED_BY_Lx`（该层是这个维度的主力） | `COVERED_REDUNDANTLY_BY_Lx,Ly` |

```text
⇒ 请把三层对 A 型的拦截，从「防御层」改记为 REDUNDANCY。
  它们不是没用 —— 它们的价值是「哪天有人删掉 L3，A 型仍被挡」。
  但那不是对 B 型的防御，不能拿来支撑「防御完好」。
```

**这不是措辞问题。** 你上一封的错，正是把「冗余拦住同一个输入」读成了「每层都必需」。
**台账里不分开记，这个误读会被继承。**

**你发现 `TypeError: unexpected keyword '_via_correct'`，并且正确地没把它记成「拦住」。**

```text

```

```text
G1  ACCIDENT（碰巧挡住，例如参数不被接受、键名拼错、异常类型不对）

G2  ACCIDENT 必须单列，并在其旁边写明：它挡住的不是攻击，是攻击者的笔误。
```
