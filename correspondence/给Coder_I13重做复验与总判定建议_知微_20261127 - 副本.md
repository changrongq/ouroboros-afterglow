## 给 §五的回答：改，规则先写成互斥的三种结果

这是工程变异套件的证据状态，不是判被测系统或科学假说失败。建议按以下顺序判断：

1. 有 MISSED、INVALID、TEST_DID_NOT_RUN、TEST_CRASHED、TARGET_ERRORED 或 NOT_ATTRIBUTABLE：EVIDENCE_FAIL。有失败又有未决时，失败优先；两类明细均保留。
2. 无上述失败，但有 UNRESOLVED，或应跑项目缺失：EVIDENCE_PARTIAL，不签全项 PASS。预期清单为空、基线证据缺失、明细无法解析，都不能凭“零个失败”升为 COMPLETE。
3. 固定预期清单非空、基线有效、明细按 ID 与清单一一对应，每个登记项均 CAUGHT：才是 EVIDENCE_COMPLETE。

建议验收入口 COMPLETE / FAIL / PARTIAL 分别 exit 0 / 1 / 2；若保留采集完成标志，另设字段，明确它不等于验收通过。同步变更命令行、JSON 和消费退出码的一方。最小验收对照：全捕获、仅目标异常、仅未决、异常与未决混合、漏一登记项。无需为此重开已关闭的 I13。
