## 一 · 为什么两个都不对

```text
你问的那两件事，都依赖一个你【还没有验证】的前提：
   「这五个字段确实同属一条护栏，且没有第二条路能写它们」。
```

**而这个前提，正好是两类真风险所在：**

```text
风险 a  某字段没进 _SOURCE_FIELDS
        拼错 / 漏加 / 改名后忘同步 / 后来新增的 origin_* 忘了归类

风险 b  某字段有另一条写入路径
        correct() 里单独处理 / insert 允许从构造参数带进来 /
        某个新方法绕过去
```

```text
⇒ 把同一个集合表达式测五遍，查不出 a)，也查不出 b)。
   因为 a) 和 b) 的问题【不在表达式内部】，
   而在【集合本身】和【路径本身】。
```

**所以：**

```text
(甲) 测五遍 ⇒ 成本 ×5，但只测了同一个表达式，a/b 仍然没查。
(乙) 标代表抽样 ⇒ 借了「集合完整」这个前提，却没把它变成断言。
                  ⇒ 又是一次「看起来有覆盖」。
```

**你上一封那个错的形状，正好是 (乙) 的思路：因为「同属一集」，所以类推。**

## 二 · 第三种：三条断言，成本低于 (甲)，覆盖强于 (乙)

### H1 · 集合内容断言（三行）

```python
assert set(_SOURCE_FIELDS) == {
    "source_kind", "source_ref", "participant_id",
    "participation_basis", "basis_ref",
}
```

```text
⇒ 一字不差。防漏加、防拼错、防改名后忘记同步。
⇒ 这一条第一次让「代表抽样」的前提有了检查。
```

### H2 · 字段分类全覆盖（一个集合运算）

```text
遍历 Record 的全部字段名，断言每一个恰好落在三类之一：
    可改（_REVISABLE） / 来源（_SOURCE_FIELDS） / 只读
落在三类之外的字段 ⇒ 红。
```

```text
⇒ 这是风险 a 的【通用形式】：
   以后任何人新增一个字段却忘了归类，测试立刻红。
   不需要有人记得「还有个字段没测」。
```

### H3 · 入口唯一性（五次探针，但只断言「变没变」）

```text
对五个来源字段各跑一次探针，断言：
    除了 correct()，没有任何公开方法能改动它们。
```

```text
⇒ 这一条不是「重复测护栏」，是测【路径唯一】。
⇒ 这是风险 b 的通用形式。
⇒ 与你已经立的那条一致：断言外部状态，不断言内部走哪条路。
```

**三条加起来：**

| | 成本 | 查 a | 查 b |
|---|---|---|---|
| (甲) 五字段各跑完整攻击 | ×5 | 部分 | 部分 |
| (乙) 代表抽样 | ×1 | ✗ | ✗ |
| **H1+H2+H3** | **≈×2** | **✓** | **✓** |

```text
⇒ H1 三行，H2 一个集合运算，H3 五次只断言结果的探针。
⇒ 比 (甲) 便宜，覆盖比 (乙) 强，因为查的是【前提】而不是【表达式】。
```

## 三 · 而且：`REPRESENTATIVE_SAMPLING` 这个标签不要用

```text
代表抽样的合法性依赖「集合完整」。
集合完整必须被断言，不能靠声明。
```

```text
⇒ 若标了 REPRESENTATIVE_SAMPLING 而没有 H1/H2，
   那这个标签本身变成了一次「看起来有覆盖」。
⇒ 这正是我们从 P1 那条不可能失败的断言开始、一路在治的病。
```

**可以保留的替代标签（H1/H2/H3 都齐之后才可用）：**

```text
SAMPLING_JUSTIFIED_BY = {H1: 集合内容一致, H2: 字段分类全覆盖, H3: 入口唯一}
```

```text
⇒ 标签必须指向【断言编号】，不指向【理由】。
   理由会被遗忘，断言会红。
```
