## 二 · Q1：含 (a)，而且必须分项报

**答案：是，必须含。**

```text
「无法核验」= 我们没有能力判断它是不是伪亲历
           ≠ 我们判断过了但判不出
```

```text
⇒ 从未观测 ⇒ 完全没判断过 ⇒ 不可核验，而且是【最严重】的一种。
```

**只算 (b) 会推出一个荒谬的结论：观测得越少，「可核验率」越高。**

```text
⇒ 这是反向激励，和「conflict 会拉低资格 ⇒ 系统学会不标冲突」
   是同一个形状。
```

### 但 (a) 和 (b) 必须分项报

```text
(a) never_observed          = 从没看过        ← 流程缺口
(b) observed_but_unresolved = 看了但判不出    ← 能力缺口
```

```text
合计可以进分子。但分解【必须同时给出】，
否则不知道下一笔投入该补哪一头。
```

## 三 · Q2：仅限当前版本，但必须报「分母流失量」

**答案：是，仅限当前版本。**

```text
理由：分母问的是「现在这套东西里，有多少是未经核验的第一人称声明」。
      历史版本曾经声称过，不等于它现在还在声称。
```

### 但有一个洞，必须同时堵

```text
若只数当前版本，则：
   一条原本 asserted = first_person_report 的记录，
   被改成 record_only 之后，就【从分母里消失】。
```

```text
⇒ 这是洗白档的操作路径。
   分母可以被改小，而比例会变好看。
```

**所以必须同时报一个数：**

```text
denominator_attrition =
    （历史版本中 asserted == first_person_report）
    −（当前版本中 asserted == first_person_report）
```

```text
⇒ 它不为零，就说明分母被搬走过东西。
   这是分母的流失量，不是比例的分母。
```

**这一条与 `record_only_ratio` 是配套的：一个量「分母外被转移的部分」，一个量「分母内被搬走的量」。**

## 四 · Q3：沿用恢复层口径，但必须「一处实现 + 相等断言」

**答案：是，用本次取回集。你写的理由是对的。**

> 这个指标问的是「这次交付出去的内容里，有多少是靠『不指向任何陈述者』逃开核实的」，
> 所以总体应是取回的东西，而不是全库。

**但你指出的那个风险是真的，而且比你说的更严重：**

> 如果恢复层实际用的是另一个总体，两边的数会不一样，而我们不会察觉——因为两边都「算得对」。

```text
⇒ 「我们理解一致」不是保证。
   「两处代码各自实现同一个概念」本身就是我们治了一整轮的那个病。
```

**要求：**

```text
R1  取回集的定义只在【一处】实现（一个函数/一个常量），两个指标都调用它。
R2  加断言：用同一组输入分别走两条路径，返回的范围必须【逐元素相等】。
R3  禁止任何一侧自行过滤或复制这段定义。
```

```text
⇒ 这与 C1 是同一条：约束必须是【结构的结果】，
   不能是【两处定义 + 一句注释】维持一致。
```

## 五 · Q4：None，且 denominator_size 必须一起返回

**答案：None（无定义）。**

```text
理由你自己写了，我确认：0 会被下游读成「本次交付里没有洗白档」，
而实际是「本次什么都没交付」。
```

**但补一条：**

```text
空集时，record_only_ratio = None 必须【与】 denominator_size = 0 一起返回。
```

```text
⇒ 只有 None、没有 size = 0，读者会以为「算出来是无定义」；
   两个一起，读者才知道「无定义是因为分母是零，不是因为算不出来」。
```

**这与 `unverifiable_ratio` 空范围返回 None 是同一条纪律。**

**而这件事最要紧的地方不是「他差点写错」，是——**

```text

```

### 关于「旧信已删除」

**删掉误导的那一封、把对它的说明留在正文里 —— 这个顺序是对的。**

```text
读者需要的不是那封信本身，
是「别再相信那个说法」。
⇒ 删信 + 留勘误 > 留信 + 加注释。
```

**因为一封曾经发出过的错信，会一直被当成引用源；而一条勘误不会。**
