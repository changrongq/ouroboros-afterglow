## 二 · 但这条边界必须写死，否则它是后门

### 危险在哪

```text
「这条变异无效」是【解释】。
任何一次 MISSED，都可以用这句解释掉。
⇒ 若没有判据，「无效变异」就会变成 A3 的逃生门：
   每一次 MISSED 都能被重新叙述成「变异无效，不算失分」。
```

```text
那样 A3 就从「断言必须能失败」退化成「断言失败时我可以说它不算」。
```

### 边界：一句，且可执行

```text
「无效变异」必须由【直接观测到行为未变】证成，
不得由【目标测试未报】推断。
```

**展开成可执行的三条：**

```text
E1  对每一个判为「无效」的变异，必须在同一次运行里，
    独立打出【被变异点的实际结果】——
    例：你 diag_m37b.py 里的 BLOCKED 逐层消息矩阵。
    这一栏不能来自目标测试的红绿。

E2  若无法独立观测（该层无法单独表达其结果），
    则该变异【不得】判为无效，只能记为 UNRESOLVED，
    并保留在台账里。
    ⇒ UNRESOLVED ≠ MISSED ≠ CAUGHT。三个状态，不许合并。

E3  「无效变异」的结论必须附【它被哪一层拦住】。
    例：M37 -> BLOCKED by ② _REVISABLE 白名单。
    说不出被谁拦住的，不算无效，算没查清。
```

## 三 · 你改断言的方向对了，但理由可以更硬

你把

```python

```

改成


**这一步是对的。而它比「守措辞」强的原因，我想说得更准一点：**

```text
「守措辞」断言的是【内部走了哪条路】。
「守机制结果」断言的是【外部可观察的状态】。
```

```text

⇒ 断言内部路径，任何重构都会假红 —— 那才是测试脆。
```

**一句话：断言该断「结果不变」，不该断「怎么拦的」。**
**你写的那句「只要机制守住了，从哪条路拦下的不算事」，就是这个意思。我确认。**
