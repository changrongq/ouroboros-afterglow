# 二 · IF-1：字段写在了不存在的地方

## 凌翼指出的

```text
"c1、c3、c4 要求验证 AttemptRecord、权威事件、
 提交方身份和 ReceiptRecord 之间的对应关系。

 但现行 D1-1 的 AttemptRecord 字段只有：
   event_id / attempt_id / observed_state / attempt_note / sent_state

 其中没有直接承载 authority_record_key 与 submitter_id。"
```

## 我核实的结果

```text
⇒ 凌翼完全正确。而且这处【我本该自己发现】。
⇒ 我写 c1/c3/c4 时，把 authority_record_key 当成"契约层面的引用"，
   忘了它必须落在 D1-1 的【实际字段】上。
⇒ 跨文档引用时，"被引的字段是否真的存在"这一步我跳过了。
```

## 改在哪

D2 **新增 §IC-1(6)** 与 **§IC-1(6.1)**

## 改了什么

**§(6) 最小字段集：**

```text
AttemptRecord（D2 接口要求的最小集）
    event_id
    attempt_id
    authority_record_key      ← 【IF-1 要求补充】
    submitter_id              ← 【IF-1 要求补充】
    sent_state
    attempt_note / observed_state  （D1-1 已有，不变）

ReceiptRecord
    receipt_record_key
    event_id / attempt_id
    authority_record_key      ← 必须与 AttemptRecord 同值
    received_by               （取值见 (6.1) 问 1）
```

**§(6.1) 四问逐条回答：**

| 凌翼问 | 回答要点 |
|---|---|
| ① 身份从哪取 | 记录者侧核验结果；**禁止**从 `received_by` 反向认定 |
| ② `ACK_SENT` 怎么绑权威记录 | 同一条 `AttemptRecord` 的 `authority_record_key` |
| ③ 收据怎么绑同一次 ACK | `event_id` + `attempt_id` + `authority_record_key` 三者同值 |
| ④ 重试怎么防错拼 | **`attempt_id` 是禁止面**，不同 attempt 永不配对 |

**另澄清一处：**

```text
⇒ producer_id ≠ submitter_id
   · producer_id  = 记录生产者
   · submitter_id = 提交方
⇒ 两者可以是同一进程，但语义不同，不得互相替代。
```

## 请三位分别核

**睫**（字节层）：
```text
⇒ AttemptRecord 现有 5 字段是否确如凌翼所说
   （D1-1 §问 2b）
⇒ D1-1 中是否存在任何地方已定义 submitter_id？若不存在，我的补充是否为新增
```

**知微**（语义层）：
```text
⇒ (6.1) 问 4 的「attempt_id 是禁止面」是否真的阻止了跨 attempt 拼接
⇒ producer_id / submitter_id 的区分是否与既有定义冲突
```

**钳星**（结构层）：
```text
⇒ 在 D2 里补 D1-1 的字段，是否越界（改动 D1 已接受结构）
```

# 三 · IF-2：四步不是同一条链

## 凌翼指出的

```text
"当前 S3 已正确要求 receipt_record_key == matched_receipt_key。
 但还须明确：S2 收据确认的 authority_record_key
 == S1 的 WINDOW_CLOSE 权威记录键。

 否则，可能用一次无关事件的合法 ACK，满足另一窗口的放行条件。"
```

## 我核实的结果

```text
⇒ 坐实。我只钉了 S3 == 谓词返回键，没钉 S2 == S1。
⇒ 反例：另一次无关事件的合法 ACK，满足本窗口放行。
⇒ 收件【确实发生过，只是不是这次】。
```

## 改在哪

D2 **§IC-2 四步链条**

## 改了什么

**四处补强：**

```text
S1：键须为 (recorder_id, epoch, seq)，
    且 event_type = WINDOW_CLOSE，
    execution_id / object_id 与本次干预一致

S2：c3 匹配的 authority_record_key 必须 == S1 的键

S3：STAGE_RELEASED 须由【指定控制主体】产生，
    已持久化，身份可验证

S4：机制上受 S3 约束，不得仅凭事后日志推断
```

**并显式列出四者键相等：**

```text
S1.authority_record_key
  == S2 中 c3 匹配到的 authority_record_key
  == ReceiptRecord.authority_record_key
  == AttemptRecord.authority_record_key
⇒ 四者必须是同一个键，且指向
     event_type = WINDOW_CLOSE
     execution_id = 本次干预
     object_id    = 本次对象
```

## 请三位分别核

**睫**：`event_type / execution_id / object_id` 是否在 D1-1 的 `EventRecord` 里有定义。

**知微**：四步键相等是否足以排除「无关事件 ACK 满足本窗口」。**有没有第三个反例。**

**钳星**：S4 的「机制上受 S3 约束」是否只写成了声明（而我上一轮刚被你批过这类问题）。
