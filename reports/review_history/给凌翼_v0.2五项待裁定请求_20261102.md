# 一 · 五个问题，逐个摊开

## T-1 · `authority_record_key` 是否纳入 `content_digest` 覆盖范围？

```text
背景：
  v0.1 §3.1b 已把 content_digest 的覆盖范围定死。
  现在要加一个字段，问题是它进不进去。

本草案已写死的部分：
  authority_record_key 由【记录者】产生，
  提交方只得【引用】，不得【构造】。

问题：这个字段本身要不要被摘要覆盖？

选 A · 纳入
  好处：键被篡改 ⇒ 摘要变 ⇒ 篡改可被检出。
  代价：权威记录的摘要里包含一个指向【权威记录自身】的键。
        需处理自引用——是摘要该键的什么？
        （键的字节？被指记录的摘要？别的东西？）
        若不慎，可能与 content_digest 的既有定义冲突。

选 B · 不纳入
  好处：无自引用，不改 v0.1 §3.1b 的语义。
  代价：该键可在摘要不变的情况下被篡改，
        即「指向权威记录的引用」本身不受完整性保护。
        攻击者可把键改指向另一条记录，而摘要仍合法。

我不选的理由：
  这不是风格问题。选 B 等于承认「引用本身可被掉包而不被检出」，
  这个后果必须由您判断是否可接受。
```

## T-2 · 跨实例唯一性如何建立？

```text
本草案当前声明：
  AUTHORITY_UNIQUENESS_SCOPE       = SINGLE_INSTANCE_ONLY
  AUTHORITY_UNIQUENESS_CROSS_INST  = NOT ESTABLISHED

问题：多个权威记录层实例之间，谁权威？

选 A · 本版不定义，保留 NOT ESTABLISHED
  好处：不引入尚未设计的机制，债留得明白。
  代价：只要存在多实例，authority_record_key 的「唯一」就不完整；
        D2 的 IC-1 c1「符合该 event 的唯一权威绑定」在多实例下无法判定。

选 B · 本版定义「实例选举」机制
  好处：唯一性跨实例闭合。
  代价：需要引入一个新的机制（选举依据是什么？谁有投票权？
        脑裂怎么办？），这已超出「字段承接」的范围，
        且会重新触碰架构层，可能与「不重新打开 D1」的约束冲突。

选 C · 本版声明「仅支持单实例，多实例明文不支持」
  好处：把假设变成约束，比含糊的 NOT ESTABLISHED 更强。
  代价：等于给系统加一条使用限制，需您认可。

我不选的理由：
  三个选项对应三种系统边界，不是文字措辞。
```

## T-3 · `submitter_id` 可信路径选哪一条？（本组最重）

```text
背景：
  submitter_id 由【提交方自填】。
  因此该值【本身】不构成身份证明。
  SUBMITTER_IDENTITY 当前 = NOT ESTABLISHED（不变）。

三条可能路径（本草案三条都描述了，一条都没选）：

选 A · 记录者侧独立观测并绑定到该 attempt
  含义：提交方说「我是 U」，记录者独立看到「确实是 U 发来的」。
  代价：要求记录者具备观测提交方身份的能力。
        而 WRITER_ATTRIBUTION_CHAIN = NOT ESTABLISHED，
        记录者本身尚不存在。⇒ 路径依赖一个未建立的组件。

选 B · 提交方身份经密码学绑定（签名 + 信任根）
  含义：不靠谁观测，靠密钥证明。
  代价：需引入信任根、密钥分发、吊销机制。
        本仓库此前已判「提交方身份的密码学绑定」需信任根，
        且【未授权】设计（见 D2 §五 明确不设计第 1 条）。

选 C · 由受信控制主体核验，并【绑定到对应 AttemptRecord】
  含义：第三方核验身份，把结果绑进记录。
  代价：需定义控制主体是谁、凭什么可信、核验结果如何绑定。
        您在 D2 收口裁定 §一 已特别指出：
        「必须使核验结果能够绑定到对应的 AttemptRecord，
          不得仅凭收到方自填身份成立」
        ⇒ 所以选 C 必须同时回答「如何绑定」，
          否则这个选项是空的。

我不选的理由：
  这不是技术选型。【它决定信任根放在哪里】，
  进而决定原型要证明什么、能证明什么。
  这是设计与治理判断，归您与船长。
```
