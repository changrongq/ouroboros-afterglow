## 一、BD-76（BLOCKING）—— **成立,fail-open 通道已关闭**

### 复现（修复前）

- `q3_provenance.py:63`（定义）、`221`（selftest）
- `q3_adversarial.py:294`（对抗 A34）

⇒ 任何"它有没有被调用"的存在性检查都会答"调用了两次",**而它该守的门(生成 digest 的那一刻)一直开着**。
⇒ **命中通往'事后改判据'的通道,fail-open 方向**（尚无人走，但不能等人走进去才关）。

### 修复（凌翼裁的"集合不可为凑数而改"落到实处）

- `write_detached_record()` 入口：同样先守卫；违例 ⇒ **raise** ⇒ **不写记录**。

### 负向回归（证明守卫"真的守门",不只是"存在"）
```
[PASS] BD-76: mutated set (RC12 folded) -> q3_lineage_digest RAISES
[PASS] BD-76: mutated set -> write_detached_record RAISES
[PASS] BD-76: record NOT written on violation
[PASS] BD-76: 9-role set -> q3_lineage_digest RAISES
[PASS] BD-76: original set restores and generates
```
⇒ 从此**集合一改,digest 生成立刻失败,而不是悄悄变一个数**。`q3_provenance` selftest **18/18**。

## 二、① "旧 worker 确已退出"——谁确认的？

**如实答**:当前是 **controller 侧传入 `old_worker_pid`（非 worker 自报,钳星确认）**,
并由 `_terminate_and_confirm()` 在 controller 进程内**同步观察该 pid 终止**（`OpenProcess` + 等待 + 退出码）。
- **是 observer（controller）侧的独立确认**,不是靠"新 worker 起得来"间接推定。
- **但一个诚实的边界**:controller 是"受信观察者",不是"第三方 observer"。
  当前**没有**一份由**独立进程**签署的"旧 worker 已退出"见证（没有像 access witness 那样的封条）。
- ⇒ 这一格我标 **PARTIAL / NOT_ASSESSED**（与睫的"退出这一格还没人报"一致）。
  **不夸大成"独立见证"**。若要升级,需 controller 之外的角色对旧 worker 终止留一份可核见证——待凌翼裁定是否需要。
