## 第 1 条：holding→release 握手，是否确保"隔离验收前业务代码不处理真实输入"？
**结论：源码层面成立，运行层面 NOT_ASSESSED。**

- worker 启动即写 `READY_HOLDING` + pid，进入循环，**只 poll `.afterglow_release` 里的 release token**；
- 只有 token 对上 `--release-token`，才置 `released=True` 且 `processing=True`；
- **holding 期间 worker 唯一做的事是"响应 access-request / 证明隔离"，不做任何真实业务负载**。
- `release_into_execution()` 只在 `_stage_persistent_isolation()` 里、且**只有 `prove_persistent_isolation()` 返回 True 之后**才被调用。
- ⇒ 顺序对：先证明隔离，再 release。真实业务负载目前是骨架（与 Coder 自报边界 #3 一致）。

## 第 2 条：BusinessWorkerSupervisor 是否"真实持有并核验 OS 身份"，而非布尔即合格？
**结论：真实，不是布尔。**

- `process_token_sid(pid)` = `OpenProcess → OpenProcessToken → _sid_of_token`，从 OS 读真实 token SID；
- `witness_ok()` 要求 `token_sid ≠ current_process_sid()`（真·跨账户身份比对）；
- 还二次核验 `_process_times(pid)`：进程活着、create_time 一致（<1e-6）。
- ⇒ 不是"收到 `identity_bound=True` 就宣布合格"。符合凌翼 I-2。

## 第 3 条：terminate() 幂等 + 无残留活进程；_fail() 单一失败契约？
**结论：源码层面成立。**

- `terminate()` 开头 `if self._proc is None and self._handle is None: return "NOT_STARTED"`（幂等）；跨账户路径 `TerminateProcess` + `WaitForSingleObject` + 二次 `_process_times` 确认 `exit_now`，仍在返回 `"STILL_ALIVE"`（**不是假装成功**）。
- `_fail()` = 置 `TX_FAILED` → `_cleanup()`（幂等 terminate）→ 抛 `NotIsolatedError`。单一失败出口，cleanup 不清失败原因。
- `_cleanup()` 用 `_cleaned` 打标幂等；terminate 异常进 `_audit["terminate_error"]`，不掩盖主失败。
