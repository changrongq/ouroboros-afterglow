```text
⇒ 【协议摘要的重算规则（给实现者）】

     原写「剥离后余下部分即为 OBJECT_TYPE ‖ header_fixed ‖ fields_encoding」，

   ⇒ 【实测证据（任何人都可复算）】：以 TV2-05 的 157 字节 b 为例

       = 5e73da838d16fa244b46069e67eae1f67bf45911c5b94c6db45fb7cde5df8b7e
     · 按 §2 2.4 正确拼接：SHA256(b[10:11] ‖ b[8:-4])
       = d57fc78b690c1ef8d7a91462ca28d46066e81fc7392ae54cb99ac714dd1f0125
     ⇒ 【两者不同】。原步骤会让读者算出自洽但错误的一套摘要。
```

```text
⇒ 【正确的重算步骤（逐步可执行）】：

   ① 取完整字节 b（长度 L）
   ② 切出头尾：
        MAGIC      = b[0:8]        （不参与摘要）
        TOTAL_LEN  = b[L-4:L]      （不参与摘要）
   ③ 切出各头部字段：
        FORMAT_VER  = b[8:10]
        OBJECT_TYPE = b[10:11]
        RESERVED    = b[11:12]
        FIELD_COUNT = b[12:14]
   ④ 切出字段区：
        FIELDS = b[14:L-4]
   ⑤ 组装 header_fixed：
        header_fixed = FORMAT_VER ‖ OBJECT_TYPE ‖ RESERVED ‖ FIELD_COUNT
   ⑥ 【组装摘要输入，注意 OBJECT_TYPE 出现两次】：
        digest_input = OBJECT_TYPE ‖ header_fixed ‖ FIELDS
                     = b[10:11] ‖ b[8:10] ‖ b[10:11] ‖ b[11:12] ‖ b[12:14] ‖ b[14:L-4]
   ⑦ digest = SHA-256( digest_input )

   ⇒ 【步骤 ⑥ 是原文件漏掉的那一步】：
     第一次 OBJECT_TYPE 是【域分离前缀】，第二次在 header_fixed 内是【编码自描述】。
     §2 2.4 明写这是刻意冗余。
```

```text
⇒ 【一个更短的等价写法，可作交叉验证】：
   digest = SHA-256( b[10:11] ‖ b[8:L-4] )
   ⇒ 因为 b[8:L-4] = FORMAT_VER ‖ OBJECT_TYPE ‖ RESERVED ‖ FIELD_COUNT ‖ FIELDS
   ⇒ 两条路径必须得到同一个值；若不同，说明拼错了。
```
