## 2 · 第 1 项：偏移错误 — 我实测定位了，但与你描述的位置不完全一样

### 2.1 我先测的是错的地方

我最初怀疑 `q3_handle_audit.py` 的句柄结构体偏移。**实测证明那里是对的**：

```text
sizeof(SYSTEM_HANDLE_TABLE_ENTRY_INFO) = 24
  UniqueProcessId        offset=0   size=2
  CreatorBackTraceIndex  offset=2   size=2
  ObjectTypeIndex        offset=4   size=1
  HandleAttributes       offset=5   size=1
  HandleValue            offset=6   size=2
  Object                 offset=8   size=8
  GrantedAccess          offset=16  size=4
```

端到端验证：我造一个 `EVENT_MODIFY_STATE` 事件句柄，冻结读取器读回 `0x001f0003`——**权限位正确**。

我还一度断言 `ctypes` 会把 `TOKEN_PRIVILEGES.Privileges` 放在 offset 8（以为 ABI 是 4）。**实测推翻了我：ctypes 放的就是 4，和 Windows ABI 一致。** 我的假设错了。

### 2.2 真正的错误在 cast，不在结构体

`q3_handle_audit_diagnostic.py` 原代码：

```python
full = ctypes.cast(buf, ctypes.POINTER(LUID_AND_ATTRIBUTES * max(1, arr.PrivilegeCount)))
la = full.contents[i]
```

**这个 cast 从 `buf` 的字节 0 开始读**，于是把 `PrivilegeCount`（DWORD）当成了第一个 `LUID_AND_ATTRIBUTES` 的开头——**偏移 4 字节**。

### 2.3 实测证据

```text
PrivilegeCount = 24

从 offset 4（正确）读：
  [0] LUID=0x0:0x000005 attributes=0x0     ← SeShutdownPrivilege
  [1] LUID=0x0:0x000008 attributes=0x0
  [2] LUID=0x0:0x000009 attributes=0x0

从 offset 0（缺陷读取）：
  [0] LUID=0x5:0x000018 attributes=0x0     ← 高半部被 PrivilegeCount 污染
  [1] LUID=0x8:0x000000 attributes=0x0
  [2] LUID=0x9:0x000000 attributes=0x0

LUID 高半部，正确 : ['0x0', '0x0', '0x0', '0x0', '0x0']
LUID 高半部，缺陷 : ['0x5', '0x8', '0x9']      ← 0x5 == PrivilegeCount
```

### 2.4 一处我自己的误判，要报告

我第一次判断"缺陷存在"用的是 **attributes 列**，断言"缺陷读取会产生不合理 attributes"。**那个断言不成立**——这台机器上几乎所有权限都不是 `0x0` 就是未持有，两种读法都得出 `0x0`，**看不出差异**。

**我的判据无效，不是缺陷不存在。** 换成 LUID 高半部对比后，缺陷才明确可证。

### 2.5 已修

```python
base = ctypes.addressof(buf) + TOKEN_PRIVILEGES.Privileges.offset
full = ctypes.cast(base, ctypes.POINTER(LUID_AND_ATTRIBUTES))
for i in range(arr.PrivilegeCount):
    la = full[i]
```

**修复前 → 修复后**（本机实测）：

```text
修复前：SeDebugPrivilege = （错误 LUID 比对下的结果）
修复后：{"SeDebugPrivilege": "enabled",
         "SeBackupPrivilege": "present-disabled",
         "SeRestorePrivilege": "present-disabled"}
```

**这说明修复是有实际后果的**：这个诊断此前一直无法正确报告 `SeDebugPrivilege` 状态，而它正是判断"权限够不够"的依据——**这与你第 1 项"权限数组偏移"的关切完全对上。**
