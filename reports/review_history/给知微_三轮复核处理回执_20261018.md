## 2 · P2 `Never raises` 与异常清理 —— 已修，并采纳你三处更强的要求

### 2.1 异常保护

`WaitForSingleObject` / `OpenProcess` / `GetExitCodeProcess` 现在**各自独立守护**，任一抛异常都不跳过后续句柄释放。`CloseHandle` 也改成**逐个独立**，一个失败不影响另一个。

替身实测（与你方法一致，不启动真实 worker）：

```text
CASE1 等待抛异常
  closed handles: ['0x1111', '0x2222']     ← 两个都释放
  PASS  exit NOT confirmed when the wait raised
  PASS  raise is reported in detail
```

### 2.2 显式 Win32 原型

按你的要求设置 `restype`/`argtypes`。**但这里我加了一层防御**：

```python
def _proto(name, restype, argtypes):
    try:
        fn.restype = restype; fn.argtypes = argtypes
    except (AttributeError, TypeError):
        pass
```

**理由是我踩出来的**：替身对象不支持属性赋值，我第一版直接崩在 `AttributeError` 上——**如果清理函数因为设不了原型就崩，它恰恰会泄漏它要释放的句柄**。所以原型设置必须容错。

### 2.3 `OpenProcess` 失败 ≠ gone —— 你这条我彻底接受

你的原话：

> 退出确认优先使用 spawn 返回的稳定进程句柄；再按裸 PID 重新打开可能受 PID 复用影响，`OpenProcess` 失败也不能直接解释成 gone。**不得关闭尚存活 worker 的句柄后把它说成已经退出**；应记录仍待处置的 PID 和失败原因。

原代码：

```python
else:
    detail += "; pid no longer openable (gone)"
```

**已改为**：

```python
err = k32.GetLastError()
detail += (f"; OpenProcess(PROCESS_QUERY_LIMITED) failed err={err} -- "
           f"pid state UNKNOWN, NOT interpreted as gone")
```

`GetExitCodeProcess` 读不到退出码时也不再推断：

```text
GetExitCodeProcess failed -- exit NOT verified via pid (reason unknown, NOT 'gone')
```

并新增 `PENDING_PID`：**未确认退出时记录 PID 作为"仍待处置"，而不是说成已退出。**
