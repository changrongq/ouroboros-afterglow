## 一 · 什么叫"独立于业务恢复域"

```text
⇒ 【定义必须先精确，否则验证无从下手】：

   设 B 的业务历史所在位置为 Loc(B)，
   设 TSU 所在位置为 Loc(S)。

   【恢复域】R = 在"一次恢复操作"中会被一起回退的位置集合。

   ⇒ 【独立】= Loc(S) ∉ R，且该关系在【下列全部恢复操作类型】下成立：
```

| 恢复操作类型 | 会回退什么 | 独立要求 |
|---|---|---|
| R-1 数据库级还原（从备份文件还原 B） | Loc(B) 的库文件 | Loc(S) 不在该备份内 |
| R-2 目录级快照还原 | 整个目录树 | Loc(S) 不在该目录树内 |
| R-3 卷/分区级快照（VSS 等） | 整个卷 | Loc(S) 不在该卷内 |
| R-4 虚拟机快照/还原 | 整机所有磁盘 | Loc(S) 在快照之外（如外部挂载）|
| R-5 系统还原点 | 受监视的系统卷 | Loc(S) 不在受监视卷内 |
| R-6 应用自带"重置到初始状态" | 应用声明的全部数据 | Loc(S) 不在其声明范围内 |

```text
⇒ 【关键】：独立不是【一个属性】，是【六种情形下的合取】。
   ⇒ 只要有一种情形下 Loc(S) 被一起回退，
     就不能说"独立于业务恢复域"。
   ⇒ 这也解释了为什么"同盘第二个文件"不够 ——
     它在 R-3/R-4/R-5 三种下都会被一起回退。
```

## 二 · 验证方法：六个检查，逐项可执行

### 检查 1 · 路径分离（必要条件，非充分）

```text
⇒ 【做法】：
   记录两个绝对路径：
     Loc(B) = 业务库文件所在目录
     Loc(S) = TSU 文件所在目录
   判断二者是否同一目录 / 是否互为父子。

⇒ 【命令（PowerShell）】：
   (Get-Item $B).DirectoryName
   (Get-Item $S).DirectoryName
   ⇒ 比较字符串；再做一次规范化（解析 8.3 短名、符号链接）

⇒ 【判定】：
   · 同一目录 ⇒ 独立【不成立】
   · 一个是另一个的前缀 ⇒ 独立【不成立】
   · 否则 ⇒ 仅【通过必要条件】，继续检查 2–6
```

### 检查 2 · 卷分离

```text
⇒ 【做法】：确认两者是否在同一卷（不只是不同目录）。

⇒ 【命令】：
   (Get-Item $B).PSDrive.Name
   (Get-Item $S).PSDrive.Name
   Get-Volume -DriveLetter <letter>

⇒ 【判定】：
   · 同一卷 ⇒ R-3/R-4/R-5 下会被一起回退 ⇒ 独立【不成立】
   · 不同卷 ⇒ 通过本检查
   ⇒ 【注意】：不同卷仍在同一物理磁盘时，
     R-4（整机快照）下仍会一起回退 ⇒ 见检查 4
```

### 检查 3 · 备份策略归属

```text
⇒ 【做法】：确认 Loc(S) 是否被业务备份任务覆盖。

⇒ 【要查的】：
   · Windows Server Backup / 第三方备份的任务定义
   · 备份任务的"包含项"列表
   · 是否有"整盘备份"包含 S 所在卷

⇒ 【命令（视工具而定，示例）】：
   Get-WBPolicy | Select-Object -ExpandProperty ProtectedItems
   # 或查看备份工具的配置文件

⇒ 【判定】：
   · S 被同一任务覆盖 ⇒ 还原该备份会一起回退 ⇒ 独立【不成立】
   · 需要人工确认（无法完全自动化）⇒ 标 `VERIFICATION_MANUAL_REQUIRED`
```

### 检查 4 · 快照范围

```text
⇒ 【做法】：确认卷影副本/虚拟机快照是否会捕获 Loc(S)。

⇒ 【要查的】：
   · vssadmin list shadowstorage —— 哪些卷启用了卷影
   · 若在虚拟机中：宿主快照是否包含 S 所在磁盘

⇒ 【命令】：
   vssadmin list shadowstorage
   vssadmin list volumes

⇒ 【判定】：
   · S 所在卷启用了卷影副本，且业务还原走卷影 ⇒ 独立【不成立】
     （但注意：卷影还原通常只还原指定文件，
       故需要看【实际还原操作的范围】而非仅"启用了卷影"）
   ⇒ 这一项【必须结合实际的还原操作** 看，不能只看配置。
```

### 检查 5 · 账户与权限分离

```text
⇒ 【做法】：确认 W 无法写 Loc(S)。

⇒ 【命令】：
   (Get-Acl $S).Access |
     Where-Object { $_.IdentityReference -match 'W_ACCOUNT' }
   # 应无 Modify / Write / FullControl

   # 反向：确认 S 账户对 Loc(S) 有写权限
   # 确认 W 账户对 Loc(B) 有写权限（对照）

⇒ 【判定】：
   · W 对 S 有写权限 ⇒ 写入独立【不成立】（承 Q3 第 1 项）
   · W 与 S 同账户 ⇒ 权限层【不成立】⇒ 标 `PERMISSION_DEPENDENT`
```

### 检查 6 · 实测回退（唯一能真正证明的检查）

```text
⇒ 【做法】：在【隔离环境】中，对 B 执行各类恢复操作，
   观察 Loc(S) 是否变化。

   ⇒ 这是唯一能证明的方法。前五项都是【静态检查】，
     它们只能排除，不能确认。

⇒ 【步骤】：
   ① 记录 S 的基线：文件哈希 + HWM 值 + 最大 commitment_seq
   ② 对 B 执行 R-k（k = 1..6）
   ③ 重新记录 S 的三个量
   ④ 比较
   ⇒ 若 S 完全不变 ⇒ R-k 下独立成立
   ⇒ 若 S 变回旧值 ⇒ R-k 下独立【不成立】

⇒ 【判定表】：
   | R-k 结果 | 结论 |
   |---|---|
   | S 不变 | 该类型下独立 |
   | S 回退 | 该类型下不独立 |
   | 无法执行该类型 | `NOT_TESTED`（不得当成立）|

⇒ 【必须六种全测才算"独立于业务恢复域"】。
   少一种 ⇒ 只能声明"在已测类型下独立"，并列出未测类型。
```

## 四 · 一个必须写明的逻辑限制

```text
⇒ 【检查 6 的循环问题】：
   要测"R-k 下 S 是否回退"，需要执行 R-k。
   ⇒ 但执行 R-k 本身就会回退 B。
   ⇒ 在【生产环境】做这件事会毁掉业务历史。

⇒ 【故】：检查 6 只能在【隔离的测试环境】做。
   ⇒ 而测试环境的备份/快照配置，未必与生产环境相同。
   ⇒ 这是【验证的固有局限】：
     测得的是"测试环境的独立性"，
     不是"生产环境的独立性"。

⇒ 【这一条不能靠更仔细的测试解决】，只能：
   · 要求测试环境的恢复配置与生产一致，并【记录该一致性本身作为假设】
   · 或接受"生产独立性未经验证" ⇒ `NOT_ESTABLISHED`
```

## 五 · 六种情形下的可检出性（与 RE 矩阵衔接）

```text
⇒ 若独立性成立（六项全过），则：
   R-1..R-6 中任一发生 ⇒ B 回退而 S 不变
   ⇒ 表现为 A < H ⇒ **可检出**（RE-4）

⇒ 若独立性不成立（任一项失败），则：
   ⇒ 该情形退化为 RE-6（共同回滚）
   ⇒ `MUTUAL_ROLLBACK_UNDETECTABLE`

⇒ 【即】：RE-6 是否覆盖某种恢复操作，
   【完全由本文件的六项检查决定】。
   ⇒ 本文件是 RE-6 边界的【定义来源】，不是补充说明。
```
