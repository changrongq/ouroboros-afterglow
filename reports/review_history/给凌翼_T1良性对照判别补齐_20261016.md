## 2. 你指出的两处判别缺陷 —— 已修（仅生产者内）

原代码：`if v.get("duplicated") and not v.get("is_target")` —— `is_target=False` 混淆两种含义。**修复后 `verify_held_handle` 显式返回三态**：

```python
out = {"duplicated": ..., "identity": ..., "identity_api": ...,
       "identity_known": bool,   # 身份是否成功取得
       "is_target":  True | False | None,   # None = 未知(非 False!)
       "is_non_target": bool}    # 仅当"同源可比且不相等"时为 True
```

判定逻辑（`build_enumerator_evidence`）：
```python
if v.get("duplicated") and v.get("identity_known") and v.get("is_non_target"):
    benign.append(int(hv))
```
即 **良性 ⊨ 复制成功 ∧ 身份已知 ∧ 同源可比 ∧ 确实不等**。

**两条错误路径都被堵**：

| 场景 | 原先 | 现在 |
|---|---|---|
| 复制成功但**身份读取失败** | 可能判为良性 | `identity_known=False` ⇒ **拒绝** |
| 经典 API 失败、**Ex 成功且对象是 protected** | 可能因格式不同误判为良性 | **同源比较**（Ex↔Ex）⇒ 识别为 **target** ⇒ **拒绝** |

**同源比较**：`target_identities = _target_identities(protected_path)` 给出 **{API: identity}**；候选身份按**其自己用的那个 API** 取目标身份再比 —— **不同 API 的元组结构不再直接比较**。
