# 一 · 为什么这不是措辞,而是"尺子会说谎"

把知微的问题分三层,只有第三层动到成败:

```text
第一层 纯文档/导航 —— 不影响成败
  · VERIFY.md 仍写 RC6 hash、22904 bytes;README lineage 未更新
  ⇒ 改字即可

第二层 绑定/证据链严谨性 —— 重要，但不是"科学性"
  · manifest_bind.py 运行时参与判定却未受绑定；空组件清单被当"无漂移"
  · ledger 混臂（B 的 J 见证 + C 的 reset 摘要接在一起）
  · V4b wrapper 仍能用参数选 ON/OFF
  · reader 只读 B 臂（q=0）
  ⇒ 方法学诚实性缺陷：证据链不能独立复算、不能强制拒错

第三层 判定逻辑本身 —— 直击成败
  · §3 V5 没真正跑 Basic L1/C1 门槛；pre 参照点用 T_j_after 而非 T_write；
       【失败默认回填成 C3】
  · §2 j_timing_ok 没做 INVALID 门禁；执行 oracle 与冻结 oracle 不同源
  ⇒ 无效/失败条件，被误判成 PASS 或 tier
```

**第三层 = "该失败的系统拿到了 PASS" = 正是 harness 存在的意义所在的反面。**
