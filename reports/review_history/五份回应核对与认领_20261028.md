# 一 · 成立且我错的（7 处）

## 错误 1 · `__all__` 不是权限白名单 —— 我把机制说错了

**知微与凌翼都指出，且他们是对的。**

```text
Python 的 __all__ 只影响 from package import * 的通配导入
它【不影响】from package import name 这种显式导入
它【不是】访问控制机制
```

**⇒ 而我写的是：**

> 「包层有 `__all__` 白名单（说明作者想过这件事）」→「但白名单不含 evaluator」→「且实际调用方走顶层绝对导入，**绕过了白名单**」

**⇒ 错在"绕过"二字。**

**⇒ 白名单根本管不到显式导入，所以不存在"绕过"。它是一个导入风格提示，不是一道门。**

**⇒ 我上一版说"它看起来像一道门，但不锁，也不记账"——这句话本身也错：它不是门，所以谈不上锁不锁。**

**⇒ 正确表述：**

```text
__all__ 存在，但它是【通配导入的名称清单】，不是权限控制。
它与"谁能调用 evaluate_basic_l1"无关。
因此它不能作为"旁路是否封闭"的证据，无论哪个方向。
```

**⇒ 连带：T-18 `MODULE_EXPORT_CONTROL` 这个命名本身错了。**
**⇒ 知微的表述更准：「真正需要建立的是正式科学结果的签发和消费授权边界。函数是否可被普通 Python 代码导入，是另一个层次的问题。」**

**⇒ 我接受把 T-18 改为：`T-18_FORMAL_RESULT_CONSUMER_AUTHORIZATION = NOT ESTABLISHED`，并注明"与函数可导入性无关"。**
