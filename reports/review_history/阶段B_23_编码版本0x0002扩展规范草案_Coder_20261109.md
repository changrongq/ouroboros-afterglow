## 一 · 版本身份定义

```text
FORMAT_VER 是编码单位自描述的一部分，且参与摘要计算（§2 2.4）。
⇒ 故 v1 与 v2 的同字段记录，其摘要输入【不同】，
  在抗碰撞假设下【预期】得到不同摘要。

⇒ 【但这里必须停住，不能多走一步】（B23-R2）：
   ✗ 不能说"摘要必然不同" —— 理论上可能碰撞
   ✗ 不能说"密码学上保证不可互相解释" —— 保证有前提

   ⇒ 正确表述：
     "在 SHA-256 抗碰撞假设成立时，两版本同字段记录
      的摘要【预期】不同；故把一条解释为另一条
      需要该假设失效。"
   ⇒ 【这不是文字游戏】：写成"必然"后，
     实现者会以为不需要任何前提就安全，
     从而跳过"预期摘要必须来自可信来源"这一条。
```

| 来源文件 | §2（不可改） | 本文件 |
| 生效状态 | 现行 | **未生效（草案）** |

```text
⇒ 【版本身份的不可混淆性（B23-R2 修正，凌翼三节第二项）】：

   ⇒ 【我原来写"不可伪造"，表述过强，撤回】。

   ⇒ 【原写法错在哪】：
     我写「摘要立即不符 ⇒ 无法靠改两个字节伪装成 v1」。
     ⇒ 这只在【校验方重算摘要，且预期摘要来自可信来源】时成立。
     ⇒ 而"不受信写入者"可以【同时重算字节与摘要】，
       写出一条自洽的伪造记录。
     ⇒ 更根本地：不同输入理论上可能发生摘要碰撞。
       ⇒ 我不能声称"必然不同"。

   ⇒ 【正确的限定表述】：
     在以下三项【同时成立】时，
     版本替换不能被当成原对象的合法延续：
       ① 抗碰撞性假设成立（SHA-256 未被攻破）
       ② 预期摘要来源可信（不是记录自己携带的值）
       ③ 验证确实被执行（不是"存了摘要但从不比对"）

   ⇒ 【任一项不成立，则不能声称此保证】。
     ⇒ 特别是 ②：若预期摘要来自记录自身，
       则该保证【完全失效】——那只是自洽，不是可信。

   ⇒ 【术语也随之收紧】：
     "不可伪造" ⇒ 改为 "在限定条件下不可混淆"。
     前者是绝对命题，后者是有前提的条件命题。
```

### 3.4 三层分离（Q-V2-03 裁定的落点）

```text
⇒ 【凌翼原文】："不把步骤 10 纳入纯字节解析的成功条件"。
```

| 层 | 名称 | 输入 | 输出 | 不得声称 |
|---|---|---|---|---|
| **L1** | 结构解析 | 仅字节 | `STRUCTURALLY_VALID` / 拒绝码 | **不表示**可信、不表示已提交 |
| **L2** | 内容绑定验证 | 字节 + **可信来源的预期摘要** | `BOUND` / `UNBOUND` / `UNDETERMINABLE` | 不得因"重算值与记录自带值相等"而宣告成功 |
| **L3** | 权威消费与提交判定 | L1 + L2 + §5 C1–C5 等 | 提交 / 拒绝 / 挂起 | 不得跳过 L2 或 L3 |

```text
⇒ 【L1（结构解析）】：
   执行版本、类型、长度、TAG、顺序、字段取值检查。
   ⇒ 成功仅输出 `STRUCTURALLY_VALID`。
   ⇒ 【明确】：`STRUCTURALLY_VALID` 不代表可信，不代表已提交。

⇒ 【L2（内容绑定验证）】：
   重算协议规定的 SHA-256，与【具有明确可信来源】的预期摘要比较。
   ⇒ 【三种结果，必须区分】：
     · `BOUND` = 重算值与可信预期摘要一致
     · `UNBOUND` = 重算值与可信预期摘要不一致
     · `UNDETERMINABLE` = 预期摘要不存在，或来源无法核实
   ⇒ 【关键】：`UNDETERMINABLE` 【不是】`BOUND`，也【不是】`UNBOUND`。
     它表示"无法判定"，不得被当成通过，也不得被当成篡改。
   ⇒ 【禁止】：把"重算值 == 记录自己携带的摘要字段"当作可信。
     ⇒ 那是【自洽】，不是【可信】。
       不受信写入者可以同时重算字节与摘要，使二者自洽。
     ⇒ 这正是 R-V2-11 存在的理由，也是它【不能属于 L1】的理由。

⇒ 【L3（权威消费）】：
   继续执行 §5 C1–C5、身份授权、历史顺序与恢复规则。
   ⇒ 权威消费者【不得】跳过 L2 与 L3。
```

```text
⇒ 【R-V2-11 的重新定位】：
   原：`R-V2-11 | 摘要重算不符 | v2 新增（解析层）`  ← 【错】
   现：`R-V2-11 | 内容绑定验证失败（L2）| 不属于结构解析错误`  ← 【对】

   ⇒ 【含义变化】：
     · 它【不是】解析格式错误 ⇒ 不受 L1 的拒绝码管辖
     · 它是 L2 的失败结果 ⇒ 只在权威消费路径上判定
   ⇒ 【因此】：一个字节串可以【同时】
     `L1 = STRUCTURALLY_VALID` 且 `L2 = UNBOUND`。
     这在旧写法下无法表达（因为步骤 10 在解析路径里）。
```

```text
⇒ 【§5 C2 不受影响】：
   凌翼裁定"§5 的 C2 信任根终止及独立写权要求保持不变"。
   ⇒ 本文件【不改】C2。
   ⇒ 但 L2 的可信预期摘要来源，正是 C2 所依赖的信任根。
     ⇒ 故 `TRUSTED_EXPECTED_DIGEST = REQUIRED_FOR_C2`。
```

## 五 · 跨版本引用与摘要


### 5.1 摘要公式（v2 沿用，不改）

```text
digest = SHA-256( OBJECT_TYPE ‖ header_fixed ‖ fields_encoding )
header_fixed = FORMAT_VER(2) ‖ OBJECT_TYPE(1) ‖ RESERVED(1) ‖ FIELD_COUNT(2)
```

```text
⇒ 【v2 不改公式】。理由：
   FORMAT_VER 已在 header_fixed 内 ⇒ 版本自动参与域分离。
   ⇒ 若另立公式，会造成"两套摘要算法"，反而增加歧义。
```

### 5.2 跨版本引用的三条规则

```text
⇒ CR-1 【记录内不得隐含版本】：
   一条 v2 记录引用另一条记录时，被引用者的
   (FORMAT_VER, OBJECT_TYPE, 摘要) 三元组必须【整体】可比对。
   ⇒ 只比对摘要不足以判定，因为摘要已含版本；
     但【必须记录被引用者的 FORMAT_VER】，
     否则无法判断"这条摘要来自哪个版本"。

⇒ CR-2 【禁止跨版本等同】：
   同一逻辑内容在 v1 与 v2 下是【两个不同对象】。
   ⇒ 任何"这两条是同一个"的判断都必须显式声明
     它用的是【内容等价】还是【编码等价】。
   ⇒ 二者不等价：编码等价 ⇒ 内容等价，反之不成立。

⇒ CR-3 【迁移必须留痕】：
   把 v1 记录迁移为 v2 时，
   必须同时保留 v1 原始字节、v1 摘要、迁移原因。
   ⇒ 不得原地改 FORMAT_VER 两个字节了事
     （那会同时破坏摘要与"当时记录了什么"）。
```

### 5.4 跨版本引用合同（Q-V2-02 裁定落实）

```text

⇒ 【故本文件【不】登记任何 v2 引用类型号】。
   ⇒ `V2_REFERENCE_TYPES_0x01_TO_0x03 = NOT_REGISTERED`
   ⇒ `V2_NESTED_REFERENCES = OUT_OF_SCOPE`
```

**引用合同 CR-V 的强制要求**

| # | 要求 | 不得满足时的处置 |
|---|---|---|
| CR-V-1 | 引用必须绑定三元组 `(FORMAT_VER, OBJECT_TYPE, digest)` | **不得**接受该跨版本引用 |
| CR-V-2 | 三元组必须具备**可信来源**（不能只靠记录自述） | **不得**接受该跨版本引用 |
| CR-V-3 | 若现有字段只保存 `digest`，必须提供**外部受保护的**类型与版本绑定 | **不得**接受该跨版本引用 |

```text
⇒ 【CR-V-3 是最容易被我含糊过去的一条，必须写死】：

   ⇒ 【问题】：如果我们只有一个 `digest` 字段，
     它能证明"某条记录的摘要"，但【不能】证明
     "这条摘要来自哪个版本、哪个类型"。
     ⇒ 因为同一个 digest 可能来自不同 (版本,类型) 组合吗？
       ⇒ 理论上：不同输入可能碰撞（低概率）；
         更重要的是：攻击者可以【构造】一条内容相同、
         (版本,类型) 不同的记录，使其 digest 相同吗？
       ⇒ 若域分离有效，则不同 (版本,类型) 的相同内容
         会得到【不同】digest。
       ⇒ 但"digest 相同"仍不能【反推】出 (版本,类型)——
         它是单向的。

   ⇒ 【所以】：仅凭 digest 无法判定版本与类型。

```

```text

   ⇒ 若系统只存 digest 且无受保护的类型/版本记录，
```
