## 一 · 版本身份定义

```text
FORMAT_VER 是编码单位自描述的一部分，且参与摘要计算（§2 2.4）。
⇒ 故 v1 与 v2 的同字段记录【摘要必然不同】。
⇒ 这在密码学上保证了两版本【不可互相解释】。
```

| 属性 | v1（现行基线） | v2（本草案） |
|---|---|---|
| `FORMAT_VER` | `0x0001` | `0x0002` |
| 允许 OBJECT_TYPE | `0x01` `0x02` `0x03` | 白名单，见第二节 |
| 是否允许 `≥0x80` | **否**（N3 原文） | **仅已登记者** |
| `0x80` | 保留 | **仍保留，不启用** |
| 来源文件 | §2（不可改） | 本文件 |
| 生效状态 | 现行 | **未生效（草案）** |

```text
⇒ 【版本身份的不可伪造性】：
   FORMAT_VER 参与摘要 ⇒
     把 v2 记录的 FORMAT_VER 改成 0x0001，
     摘要立即不符 ⇒ 无法靠改两个字节伪装成 v1。
   ⇒ 前提：校验方【必须真的重算摘要】。
     若只比对存储的摘要值而不重算，则此保证不成立。
```

## 三 · v2 解析规则（逐条编号，可与 §2 步骤 0–9 对照）

```text
⇒ 【凌翼三节要求："完整解析步骤，包括版本拒绝和类型拒绝的规则编号"】。

⇒ 【设计原则】：v2 解析步骤与 §2 步骤 0–9 【结构完全一致】，
   只在步骤 2 与步骤 3 内部增加版本分派。
   ⇒ 这样实现者可复用同一骨架，减少分叉。
```

| 步骤 | v2 行为 | 失败规则 |
|---|---|---|
| 0 | 输入总长 `L ≥ 18` | R-V2-07 |
| 1 | MAGIC == `AFGLREF\0` | R-V2-02 |
| 2 | 读 `FORMAT_VER`：`0x0001` → 进入 v1 分支；`0x0002` → 进入 v2 分支；其他 → 拒绝 | R-V2-03 |
| 3 | v1 分支：`OBJECT_TYPE ∈ {0x01,0x02,0x03}`，否则拒绝（**即 §2 N3**）<br>v2 分支：`OBJECT_TYPE ∈ 白名单`，否则拒绝 | R-V2-04 / R-V2-05 |
| 4 | `RESERVED == 0x00` | R-V2-06 |
| 5 | 读 `FIELD_COUNT`，仅记录 | — |
| 6 | 逐字段读 `TAG(1)+LEN(2)`；读前检查「剩余 ≥ 3+4」；读 VALUE 前检查「剩余 ≥ LEN+4」 | R-V2-07 |
| 7 | 读 `TOTAL_LEN(4)`，之后必须无剩余 | R-V2-08 |
| 8 | `TOTAL_LEN == L` | R-V2-08 |
| 9 | `FIELD_COUNT == 实读数 == 该类型规定字段数`，并校验 TAG/顺序/长度/取值 | R-V2-09 / R-V2-10 |
| 10 | （v2 新增）计算摘要并与存储值比对 | R-V2-11 |

```text
⇒ 【步骤 10 是 v2 新增的，必须说明】：
   ⇒ §2 步骤 0–9 只校验【结构】，不校验【摘要是否重算一致】。
   ⇒ 凌翼 D-1 第 7 项要求跨版本"摘要绑定"，
     故 v2 把摘要校验明确纳入解析路径。

   ⇒ 【这不是可选的，已实测证明】：
     把 v1 字节的 FORMAT_VER 改为 0x0002，整条 SHA-256 必变
     （见 8.2）。若校验方【不重算】摘要、只比对存储值，
     则"v2 字节谎称 v1"这类篡改无法被发现。
   ⇒ 故步骤 10 是摘要绑定的【唯一落地点】。
```

## 五 · 跨版本引用与摘要

```text
⇒ 【凌翼 D-1 第 7 项："跨版本引用必须保留版本身份及摘要绑定，
   禁止把 v1 与 v2 记录解释为同一编码对象"】。
```

### 5.1 摘要公式（v2 沿用，不改）

```text
digest = SHA-256( OBJECT_TYPE ‖ header_fixed ‖ fields_encoding )
header_fixed = FORMAT_VER(2) ‖ OBJECT_TYPE(1) ‖ RESERVED(1) ‖ FIELD_COUNT(2)
```

```text
⇒ 【v2 不改公式】。理由：
   FORMAT_VER 已在 header_fixed 内 ⇒ 版本自动参与域分离。
   ⇒ 若另立公式，会造成"两套摘要算法"，反而增加歧义。
```

### 5.2 跨版本引用的三条规则

```text
⇒ CR-1 【记录内不得隐含版本】：
   一条 v2 记录引用另一条记录时，被引用者的
   (FORMAT_VER, OBJECT_TYPE, 摘要) 三元组必须【整体】可比对。
   ⇒ 只比对摘要不足以判定，因为摘要已含版本；
     但【必须记录被引用者的 FORMAT_VER】，
     否则无法判断"这条摘要来自哪个版本"。

⇒ CR-2 【禁止跨版本等同】：
   同一逻辑内容在 v1 与 v2 下是【两个不同对象】。
   ⇒ 任何"这两条是同一个"的判断都必须显式声明
     它用的是【内容等价】还是【编码等价】。
   ⇒ 二者不等价：编码等价 ⇒ 内容等价，反之不成立。

⇒ CR-3 【迁移必须留痕】：
   把 v1 记录迁移为 v2 时，
   必须同时保留 v1 原始字节、v1 摘要、迁移原因。
   ⇒ 不得原地改 FORMAT_VER 两个字节了事
     （那会同时破坏摘要与"当时记录了什么"）。
```

### 5.3 我需要指出的一处张力

   v2 白名单【不含】0x01–0x03（见 2.4）。
   ⇒ 那么 v2 的 11 类对象若需要"引用权威记录"（如 KEY_TRIPLE），

     若将来某类需要嵌套引用，v2 无 KEY_TRIPLE 可用。
   ⇒ 记入 Q-V2-02。
