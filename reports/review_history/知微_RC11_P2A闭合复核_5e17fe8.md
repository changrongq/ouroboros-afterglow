结论：支持将此前保留的 P2-A 标记为闭合。身份阶段的错误路径已统一显式返回，独立反例没有再出现默认 True 或前一条 arm 的状态冒充通过的情况。P2-B 的说明文字也已收窄到实际证据范围。本轮复核范围内没有新增待修项；此前四项 P1 的闭合结论保持不变。

## 1. 实现核对

`afterglow_harness/evidence_bundle.py` 的 `_validate_reset_object_identity` 已移除原先全置 True 的初始化：缺记录、缺字段、stored restored 缺失、字节格式错误和身份不一致均汇入同一个 `id_fail` 返回口：

```python
return True, False, False, UNEVALUATED, id_fail
```

preserve 的失败与全部通过路径分别显式返回，未再携带跨 arm 的局部状态作为结论。

这里的闭合是对已审实现与列明反例的工程判断，不是对所有未来修改的无条件保证。

## 2. 独立复测

从正常 V5a 账本复制原始证据，经实际 `adjudicate_fixture_from_ledger` 判定链，在 4 个 member × 3 条 arm 的每个位置，分别注入：

- 缺失 verified_restored；
- 缺失 q_raw；
- 缺失 literal；
- q_raw 格式错误；
- literal 格式错误；
- verified_restored 为 null；
- verified_restored 与 stored S_restored 的字节不一致。

**共 84 个用例全部符合预期：**

```text
protocol = INVALID
L2 = INVALID
reset_identity_ok = False
preserve_rule_ok = UNEVALUATED
reader_ok = UNEVALUATED
```

覆盖后面的 member/arm，是为了验证前面检查成功后仍不会把已通过状态带入当前失败路径。

另直接测试 helper 的 `S_restored` 缺失分支，12 个位置均返回 `(True, False, False, UNEVALUATED, code)`。这 12 项是 helper 单独测试：完整判定链通常会先由结构检查拒绝该缺失，不能把它们表述为完整链到达了这个分支。

对照结果保持正确：

| 情形 | reset_identity_ok | preserve_rule_ok |
|---|---|---|
| 正常 V5a | True | True |
| 身份不一致或身份证据不可用 | False | UNEVALUATED |
| 身份相符、纯 preserve 字节违例 | True | False |

P2-B 的计数包装再次观察到真实调用 `['EXTRA_CONTENT', 'OFF']`。源码 docstring 现明确限定为“两种调用形式均被接口接受”，不再声称已比较写入效果，符合此次要求。
