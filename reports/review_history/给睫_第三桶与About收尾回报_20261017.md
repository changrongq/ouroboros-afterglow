## 一 · 第三桶（照裁实现）

```text
unresolved_operational    # OpenProcess / Duplicate / 枚举 —— 可修
unresolved_no_identity    # 操作成功，对象本无可读文件身份 —— 不可修
unresolved_incomparable   # 身份已读到，但无可比的 target 身份 —— 【待定】
unresolved                # = 三者之和（您的规矩，未破）
```

`CAUSE_IS_ONTOLOGICAL` 触发条件已改为**三个合取项**：

```text
operational == 0  ∧  no_identity > 0  ∧  incomparable == 0
```

少一个 ∧，那句话就会撒谎——这一点我照您的原话写进代码注释了。

新增常量 `CAUSE_IS_ONTOLOGICAL_REQUIRES`，把这三个条件固化进模块，由断言校验，防止日后被单方面放宽。

同时新增 `CAUSE_IS_INCOMPARABLE`：`incomparable > 0` 时**不借用**那句话，而是明写

> 这是仪器的一个事实，不是 N 个独立的句柄缺陷；不要把它读成关于目标隔离的证据。

## 二 · target 侧短路（按您说的"比第三桶更该先做"）

`_target_identities` 现在返回 `(identities, reason)`：

```text
OK | CREATEFILE_FAILED:<err> | OPENED_NO_API
```

**`reason != OK` ⇒ 整个审计短路为 `V2_INCOMPARABLE`**，逐句柄计数**不执行**，`counts['short_circuited']=True`。

您给的理由我照抄进 docstring，不转述：

> 这不是一次"逐句柄判定"，这是一次"仪器没拿到基准"。
> 一个没拿到基准的仪器，不该输出 12 条逐句柄结论。它该输出一句话：我没拿到基准。

来路也挂上了您指的那条：**T1 契约第一条 `UNKNOWN != NON_TARGET`，只是此前没被用到 target 那一侧。** 现在用到了。

`V2AuditResult` 新增字段 `target_identity_reason`，短路的 `detail` 明写可修性：

- `CREATEFILE_FAILED` ⇒ **FIXABLE**（operational，加权限可能解决）
- `OPENED_NO_API` ⇒ **ONTOLOGICAL**（加权限不能解决）
