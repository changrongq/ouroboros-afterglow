## 二 · 五条不变量各自的可执行形式

> 每条四栏：**观测量 / 观测点 / 断言 / 不可判定边界**

### S1 · 同一时刻最多一个主体拥有有效执行权限

```text
【观测量】
  V_S1 = 在时刻 t，由【独立观测者】读到的"可签发持有者集合"

  ⇒ 关键在【独立观测者】。两实例各自的自报日志
    不构成 V_S1（理由：两声自称 ≠ 一次并存）。

【观测点】
  · t = 任一签发动作发生之前
  · 以及 t 落在 [T1, T2] 区间内（承 F-3-2 的时点定义）
  · 观测必须由非被测方执行

【断言】
  ASSERT_S1: ∀t ∈ 观测区间：|V_S1(t)| ≤ 1

  可执行形式：
    for each observed_timestamp t in trace:
        holders = independent_observer.holders_at(t)   # 非自报
        if holders is UNKNOWN:
            → INCONCLUSIVE（不得判通过）
        if len(holders) > 1:
            → VIOLATED（确定违反）
    if no UNKNOWN and all |holders| <= 1:
        → HOLDS

【不可判定边界】
  · 若独立观测者在某区间【没有覆盖】，该区间为 UNKNOWN
    ⇒ 整体结论最多是「在已覆盖区间内成立」
  · 若两个持有者的持有区间【不重叠】，则不违反 S1 ——
    但要求能证明不重叠，而证明依赖同一观测者的连续覆盖
  · 【永久不可判定】：若观测者与被测方共享时钟，
    则"同一时刻"本身无法确定（承 §0 B-3：clock_ns 不参与排序）
    ⇒ 须用登记侧顺序，不得用时间戳
```

### S2 · 已分配 epoch 不得再分配

```text
【观测量】
  E_committed = 全部已 COMMITTED 的 epoch 集合
  e_new       = 本次分配拟用的 epoch
  scope_digest = 本次计算 E_committed 所依据范围的摘要（0x88）

【观测点】
  · 校验动作执行时（持久化之前）
  · 以及恢复时重算

【断言】
  ASSERT_S2a: e_new ∉ E_committed
  ASSERT_S2b: E_committed 的【范围完整性已确认】
              （即有 HWM/N5 支持，不是业务历史自证）
  ASSERT_S2c: e_new = max(E_committed) + 1
              （若规则如此规定，见 §5 六 (d)）

  ⇒ 【S2 成立 = S2a ∧ S2b】。S2c 是【生成规则】，不是不变量。

  可执行形式：
    scope = rebuild_scope(scope_digest)        # 按 0x88 规范
    if scope is INCOMPLETE:
        → STOPPED（不是 VIOLATED —— 无法确认）
    if e_new in scope.committed_epochs:
        → VIOLATED
    if scope.head_digest != trusted_hwm.last_commitment_digest:
        → STOPPED（范围与承诺不符）
    → HOLDS

【不可判定边界】
  · 若 E_committed 的范围完整性不可确认 ⇒ 结论是 STOPPED，
    【不是】VIOLATED，也不是 HOLDS
  · 「同一 max 不同来源」：必须核 scope_digest 与
    实际参与计算的记录一致（承知微 N99-01），
    否则"算对了但来源错"检不出
```

### S3 · 不得仅因历史缺失或身份不可读就创建新身份

```text
【观测量】
  A_auth       = 是否存在有效的创建授权
  A_uninit     = 目标域"未初始化"是否已验证
  A_nocompete  = 是否存在竞争授权

【观测点】
  · 前置校验时点（身份产生之前）

【断言】
  ASSERT_S3: 创建新身份 ⇒ (A_auth ∧ A_uninit ∧ A_nocompete)

  ⇒ 【注意方向】：这是【蕴含】，不是等价。
    三项全满足【不保证】必须创建（可以拒绝）。
    创建了但三项不满足 ⇒ 违反。

  可执行形式：
    if action == CREATE_IDENTITY:
        if not (A_auth and A_uninit and A_nocompete):
            → VIOLATED
    if any of A_* is UNKNOWN and action == CREATE_IDENTITY:
        → STOPPED
    → HOLDS（本观测窗口内未发现违反）

【不可判定边界】
  · A_uninit 的"已验证"不能靠空文件推断
    （承 P4-2.5(e)：不得把空文件自动认作合法初始状态）
  · 若 A_* 任一为 UNKNOWN 且未创建 ⇒ 无法判 S3 成立，
    只能判"未观察到违反"
```

### S4 · 引用完整性/身份来源/绑定验证未通过时不得产生有效执行许可

```text
【观测量】
  V_ref   = 引用完整性校验结果（C1/C2 及 §2 解析）
  V_src   = 身份来源校验结果（§3 五 判据①–⑤）
  V_bind  = 绑定验证结果（§5 二 (r3) 显式绑定）
  Perm    = 是否产生了有效执行许可

【观测点】
  · 许可产生时点

【断言】
  ASSERT_S4: ¬(V_ref ∧ V_src ∧ V_bind) ⇒ ¬Perm

  ⇒ 等价形式：Perm ⇒ V_ref ∧ V_src ∧ V_bind

  可执行形式：
    if Perm and not (V_ref == PASS and V_src == PASS
                     and V_bind == PASS):
        → VIOLATED
    if Perm and any(V == UNKNOWN):
        → STOPPED（不得判通过）
    → HOLDS

【不可判定边界】
  · 三个 V 都是【外部判据】，各自有自己的不可判定边界
    ⇒ 组合后的边界是三者的并集
  · V_bind 依赖 (r3)，而 (r3) 的"预先登记"依赖登记侧顺序证据
    ⇒ 若该证据缺失，V_bind = UNKNOWN ⇒ 整体 STOPPED
```

### S5 · 崩溃/冲突/损坏/权限不确定时不得绕过检查继续执行

```text
【观测量】
  H_state ∈ {COMMITTED, NOT_COMMITTED, PENDING, UNKNOWN}
  Entry_open = 签发入口是否开放
  Check_bypassed = 是否存在"跳过了某项检查"的证据

【观测点】
  · 每个 STOPPED 入口（§6 说"九个"，须逐一枚举）
  · 任何 Entry_open 的区间

【断言】
  ASSERT_S5a: H_state == UNKNOWN ⇒ ¬Entry_open
  ASSERT_S5b: 任一 STOPPED 条件成立 ⇒ ¬Entry_open
  ASSERT_S5c: 不存在 Check_bypassed

  ⇒ 【UNKNOWN 不归类】是 S5 的核心：
    UNKNOWN ≠ NON_TARGET，UNKNOWN ≠ 良性。
    ⇒ 这是既有恒等式"UNKNOWN != NON_TARGET"的落地。

  可执行形式：
    if state == UNKNOWN and entry_open:
        → VIOLATED
    if any_stopped_condition_true and entry_open:
        → VIOLATED
    if check_bypassed_evidence:
        → VIOLATED
    if state == UNKNOWN:
        → STOPPED（不是 HOLDS）
    → HOLDS

【不可判定边界】
  · "九个 STOPPED 入口"必须【逐一列出并编号】，
    否则 ASSERT_S5b 无从执行
    ⇒ 【本轮我尚未列出这九个】，这是待补项
  · Check_bypassed 需要控制流证据（轨迹），
    仅凭结果正确【不能】证明未绕过
```

## 三 · 统一的判定结果类型

```text
⇒ 四条不变量共用同一套结果枚举，避免各自发明：

  | 结果 | 含义 | 可作 Gate 依据？ |
  |---|---|---|
  | `HOLDS` | 在【已覆盖区间】内未观察到违反，且无 UNKNOWN | 可（限于该区间）|
  | `VIOLATED` | 有确定的违反证据 | 可（阻断）|
  | `STOPPED` | 证据不足，按 fail-closed 处理 | 可（阻断）|
  | `INCONCLUSIVE` | 已进入验证但未完成（资源耗尽等）| **不可**（需重验）|

  ⇒ 【INCONCLUSIVE 与 STOPPED 的区别】（承凌翼二节）：
    · STOPPED = 已确定"不能判通过"
    · INCONCLUSIVE = 还没判完
    ⇒ 前者是结论，后者是状态。
```

## 四 · 判定函数的公共部分

```text
⇒ 四条断言共用的三段逻辑：

  (F1) 【证据充分性前置】
       若任一必需观测缺失/不可验证 ⇒ 不是 HOLDS
       ⇒ 先判 STOPPED 或 INCONCLUSIVE，再判违反

  (F2) 【违反优先于不确定】
       若既有确定违反证据、又有未覆盖区间 ⇒ 判 VIOLATED
       （承凌翼：已确认违反不得降级为 INCONCLUSIVE）

  (F3) 【区间限定】
       任何 HOLDS 必须附带【覆盖区间】。
       不带区间的 HOLDS 视为无效。
```
