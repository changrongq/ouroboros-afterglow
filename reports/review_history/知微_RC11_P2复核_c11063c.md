结论：两个原始反例均已修正；P2-A 仍有相邻错误分支遗漏，暂不支持“两个 P2 全部闭合”的完整表述。P2-B 的真实调用缺失已闭合，代码说明应收窄到实际验证范围。四项 P1 的既有闭合结论保持不变。

## 1. P2-A：原反例通过，缺失/格式错误分支尚未闭合

原反例只改 V5a/A1/C 的 verified_restored.q_raw，使它与 S_restored 不符。现在实测：

```text
protocol = INVALID
code = RESET_OBJECT_IDENTITY_BREAK
reset_identity_ok = False
preserve_rule_ok = UNEVALUATED
reader_ok = UNEVALUATED
```

纯 preserve 违例也已正确区分：`reset_identity_ok=True`、`preserve_rule_ok=False`。这一部分支持闭合。

但在第一个 member 的第一条 arm（A1/A）注入以下任一变更：

1. 删除 `reset_witness.A.verified_restored`；
2. 只删除其中的 `q_raw`；
3. 将其中的 `q_raw` 改为非十六进制字符串 `zz`。

三种实测均得到：

```text
protocol = INVALID
code = RESET_VERIFIED_MISSING 或 RESET_VERIFIED_MALFORMED
reset_identity_ok = False
preserve_rule_ok = True       # 实际尚未执行，应为 UNEVALUATED
reader_ok = UNEVALUATED
```

位置：`afterglow_harness/evidence_bundle.py:241`，以及第 250–261 行的提前返回。函数入口仍将 `preserve_checked` 和 `preserve_ok` 都初始化为 True；这些返回分支直接带出默认值。第 262–266 行的字节不一致分支已经显式返回未评估，所以旧反例通过，但相邻分支仍有同类问题。

建议让所有发生在 preserve 检查前的身份错误分支采用一致的显式返回语义，例如 `(True, False, False, UNEVALUATED, code)`；不要只改一个初始化值后依赖跨 arm 的残留状态。补上上述缺失、缺字段、格式错误三种回归。

影响仍限于结构化辅助标志：本轮反例的 protocol/L2 均正确 INVALID，没有观察到总体误通过，优先级保持 P2。

## 2. P2-B：实际调用缺失已闭合，说明文字仍应限幅

在真实 `SeparableControlHandle.write` 外加保持原签名和原实现的计数包装，现在实测：

```text
write_calls = ['EXTRA_CONTENT', 'OFF']
behavioral_calls = 2
behavioral_split = True
```

生产 `CombinedOnlyWriter.public_handle()` 的 OFF 调用被拒绝，`behavioral_split=False`。因此，上次“只查签名、一次也没调用”的反例可以闭合。

另外，`afterglow_harness/fixtures.py:495–499` 的 docstring 仍称比较了 `DIFFERENT effects`。实际实现的判据是两次调用都被接受，没有读取、比较两次写入的状态效果。当前报告第 2 节按“调用被接受”描述是准确的，建议同步收窄这段 docstring。这里不要求新增效果验证设计，只要求文字与已实现的证据一致。
