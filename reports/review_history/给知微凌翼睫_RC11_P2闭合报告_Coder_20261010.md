## 1. P2-A：`reset_identity_ok` 身份失败时仍为 True

**病灶**（知微指出）：`evidence_bundle.py` 中身份检查与 preserve 检查**共用一个返回码**，两个标志都取 `not preserve_break`。故身份失败（`RESET_OBJECT_IDENTITY_BREAK`）时 `reset_identity_ok` 仍为 True。

**修法**：
- `_validate_reset_object_identity` 改为返回**结构化五元组** `(identity_checked, identity_ok, preserve_checked, preserve_ok, code)`，两项检查各自报告，未执行的检查返回 `checked=False`。
- 引入三态哨兵 `UNEVALUATED`（字符串，JSON 可读）：`True`=跑过且通过；`False`=跑过且失败；`UNEVALUATED`=**未到达**（前序门禁已失败）。
- `GateResult` 的所有子判定标志默认值**不再是 True**，改为 `UNEVALUATED`。成功路径显式置 True；每个失败门禁把自己的标志置 False，并把**未到达**的后续标志留为 `UNEVALUATED`。

**复现（知微原样：仅改 verified_restored q）**：
```text
protocol = INVALID
code = RESET_OBJECT_IDENTITY_BREAK: A1/C verified-restored != stored S_restored (byte-level)
reset_identity_ok = False
preserve_rule_ok  = UNEVALUATED   （未到达，不再冒充通过）
```
对照：
- 纯 preserve 违例（身份相符）→ `reset_identity_ok=True, preserve_rule_ok=False`
- 干净 V5a → 两者皆 `True`
- 早期 membership 失败 → `reset_valid=UNEVALUATED`（不默认 True）

## 2. P2-B：正对照的 `behavioral_split` 仍来自签名

**病灶**（知微指出）：当签名含 `extra_mode` 或 `**kwargs` 时直接 `behavioral_split=True`，**未实际调用** write。知微加计数包装实测 `write_calls=[]`。

**修法**：behavioral 分支改为**真实调用**：
- 对 public `write` **实际调用两次**——一次不带 selector（ON），一次带 `extra_mode=OFF`；
- 只有当**两次调用都被 public 接口接受**时，才判 `behavioral_split=True`；
- 返回值新增 `behavioral_calls` 计数。

**复现（知微原样：加计数包装）**：
```text
structural_split = True
behavioral_split = True
behavioral_calls = 2
write_calls = ['EXTRA_CONTENT', 'OFF']   （真实发生了 ON/OFF 两次调用）
```
对照：生产 `CombinedOnlyWriter.public_handle()`（单参 write）→ OFF 调用被拒 → `behavioral_split=False`。
