# 二 · 裁定项 A：BD-52 的语义强于其实现

## A.1 机制原文

`evaluator.py` L117-130：

```python
@dataclass
class JTimingWitness:
    s_write_digest: str
    j_after_digest: str
    s_handoff_digest: str

    @property
    def timing_valid(self) -> bool:
        return self.j_after_digest == self.s_handoff_digest
```

`evaluator.py` L135-141：不等则抛 `J_TIMING_VIOLATION`，fixture 判 INVALID。

## A.2 声称

`evaluator.py` L112-113 注释：

```text
# fixture is INVALID (not PASS). This makes "a legal J" and "an injected
# post-handoff fault" machine-distinguishable by TIME, not by wording.
```

即：**合法 J** 与 **handoff 之后注入的故障**，**由时间**可机器区分。

## A.3 实测

直接构造 dataclass，未修改任何文件，未执行任何科学运行：

```python
JTimingWitness("sw", "alpha", "beta").timing_valid   -> False
JTimingWitness("sw", "beta",  "alpha").timing_valid  -> False
```

```text
两种【完全相反】的先后关系，得到【同一个】结果。
⇒ == 是对称谓词。
⇒ 它能回答「是不是同一刻」，不能回答「谁在前」。
```

## A.4 旁证：负向见证脚本自己承认了

`bd52_timing_witness_check.py` L35-42：

## A.5 我认为 A 项成立的部分，与不成立的部分

**成立（我不否认 BD-52 的价值）：**


## A.6 根因（我认为这条最重要）

```text
digest 是【内容】的身份，不是【时刻】的身份。

· 无写入时，两个不同时刻可以有相同 digest ⇒ 无写入时 digest 区分不了时刻；
· digest 上【没有定义序】⇒ 无法写 <，只能写 ==。

⇒ BD-52 用 == 不是疏忽，是材料所限。
⇒ 所以任何「照抄三元组」的做法都会继承同一限制。
```

**核过源码后已撤回**。原因是照抄会连带继承「只能判等值」这个天花板。

# 四 · 需要一并裁定的前置问题：有序列选哪条

若 A 选「选项2」或 B 选「选项1」，都会立刻撞到同一个问题：**序从哪来。**

| 候选 | 有序 | 跨进程可比 | 缺口 |
|---|---|---|---|
| 写入计数器（单调递增） | 是 | 需共享存储 | 计数器自身可被回绕/伪造 |
| 单调时钟 `perf_counter_ns` | 是 | **否**（进程基准不同） | 跨进程不可比 |
| 外部见证者签发序号 | 是 | 是 | 在阶段 ⑥，**事后**，不能用于事前判定 |

```text
⇒ 三条各有各的前提，没有一条是「加上就能用」。
⇒ 单调时钟被「跨进程不可比」直接否掉 —— 这是最自然的选择，也是最先错的选择。
⇒ 选哪条是您的裁定，不是我的设计自由。
```

## 四之一 · 一个我认为不该被忽略的边界

```text
进程崩溃 ⇒ 窗口永不关闭 ⇒ 「写入在窗口内」永远无法判定。
⇒ 而崩溃恰恰是最需要证据的时刻。
⇒ 所以「窗口关闭」必须是【外部可观察事件】，
```
