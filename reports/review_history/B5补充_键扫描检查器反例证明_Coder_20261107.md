## 零 · 为什么这一项必须做

```text
⇒ 凌翼这句指向的，正是我上一轮【真的犯过】的错：

   ⇒ 为了让"冲突 = 0"好看，我把检测脚本改了三次，
     每次改完都得到 0。
   ⇒ 那不是检查通过，是把检查改到不会失败。

⇒ 一个从不失败的检查器，和一个恒返回"OK"的常量，
   在输出上【无法区分】。
   ⇒ 所以证明"它能输出 0"没有意义。
     有意义的是证明"在应当输出非 0 时，它确实输出非 0"。
```

## 一 · 检查器口径（先固定，再测）

```text
⇒ 【口径定义】：

   正则      ：`^\s*([A-Z][A-Z0-9_]{2,})\s*=\s*(.*)$`
   排除      ：以 `|` 开头的表格行（Markdown 表格，不是记录）
   唯一键    ：所有匹配到的 KEY 集合，|集合|
   跨文件键  ：{ k : |files(k)| >= 2 }
   状态声明  ：缩进为 0 的 KV 行
              + 例外：紧接「不因本检查而升级」之后的缩进块
   同键异值  ：在【状态声明】范围内，同一 KEY 出现两个以上不同值
   值规范化  ：截到第一个空白或中文标点/括号（用于判"同值"）

⇒ 【输入范围】：§0–§7 + 绑定表 + CHECK 结果件 = 十文件
```

## 二 · 五个反例（每个都针对一种具体失效）

> 以下反例均在**临时副本**上制造，不在正式文档中注入。
> 每次注入后恢复，并核对恢复后的哈希与原文件一致。

### C-1 · 同键异值的直接冲突

```text
⇒ 【制造】：在 §6 状态块加一行 `TEST_RUN = PASS`
   （原值为 `NONE`）

⇒ 【应当失败】：检查器输出 CONFLICT，且指名 `TEST_RUN`，
   并给出两处位置。

⇒ 【若检查器输出 0】：说明"值比较"根本没生效。
```

### C-2 · 缩进导致的假阴性（我最容易犯的那种）

```text
⇒ 【制造】：在 §7 某段说明里插入一行
   「   TEST_RUN = PASS」（缩进 3）

⇒ 【应当】：
   · 唯一键计数【不变】（TEST_RUN 已存在）
   · 同键异值【不增加】（因为缩进 3 ⇒ 非状态声明）

⇒ 【若检查器报冲突】：说明它没有正确区分状态声明与引述，
   ⇒ 这正是我上一版 E1/E2/E3 的毛病（把整个状态块误判）。

⇒ 【这条反例的用途】：证明检查器【不会过度报警】。
   只证明"会报错"不够，还要证明"不会乱报"。
```

### C-3 · 键名漏计（正则阈值错）

```text
⇒ 【制造】：在 §5 加一行 `XY = 1`（键名 2 字符）

⇒ 【应当】：按正式正则 `{2,}`，`XY` 长度 2 不满足
   （`[A-Z][A-Z0-9_]{2,}` 最少 3 字符）
   ⇒ 【不计入】。
   ⇒ 再制造 `XYZ = 1`（3 字符）⇒ 【应当计入】，唯一键 +1。

⇒ 【用途】：证明阈值确实起作用，不是"见大写就收"。
   ⇒ 我上一轮正是把阈值写成 `{5,}`，导致 137 vs 139。
```

### C-4 · 表格行被误当键值

```text
⇒ 【制造】：在某文件加一行
   `| TEST_RUN | PASS | 备注 |`

⇒ 【应当】：被排除规则拦住，【不产生任何键值】，
   唯一键与冲突数均不变。

⇒ 【若检查器报冲突】：说明排除规则失效，
   ⇒ 而所有六格表、校准表都是表格，失效会引入大量假冲突。
```

### C-5 · 跨文件计数漏项（知微 N99 指出的那种）

```text
⇒ 【制造】：把 `SIX_CELL_BINDING_VERIFIED = NO` 从 §7 状态块
   复制到绑定表状态块（两处都有）

⇒ 【应当】：`SIX_CELL_BINDING_VERIFIED` 出现在跨文件键集合，
   且值相同 ⇒ 【计数 +1，冲突不变】

⇒ 【若跨文件数不变】：说明"文件集合"统计有 bug。
   ⇒ 这正是我上轮漏算它的原因。
```

## 四 · 执行记录

```text
⇒ 【已实际执行】。方法：把十份文件复制到临时目录，
   逐个注入反例，每次注入前恢复原文件，注入后比对哈希。
   ⇒ 【正式文档未被修改】（恢复校验：十份哈希全部一致）。
```

### 4.1 基线

```text
⇒ 未注入时：
   唯一键 = 139
   跨文件 ≥2 = 16
   同键异值 = 0
   ⇒ 【与凌翼裁定的 KEY_NAME_COUNT = 139 / CROSS_FILE_KEY_COUNT = 16 一致】。
```

### 4.2 逐个结果

| 反例 | 注入内容 | 实测变化 | 判定 |
|---|---|---|---|
| **C-1** | §6 状态块加 `TEST_RUN = PASS` | 同键异值 **0 → 1**，且**指名 TEST_RUN** | **PASS** 检查器能失败 |
| **C-2** | §7 说明段插缩进 3 的 `TEST_RUN = PASS` | 同键异值 **0 → 0** | **PASS** 未误报 |
| **C-3** | §5 加 `XY = 1`（2 字符）与 `XYZ = 1`（3 字符） | 唯一键 **139 → 139 → 140** | **PASS** 阈值生效 |
| **C-4** | §6 加表格行 `\| TEST_RUN \| PASS \| 备注 \|` | 同键异值 0→0，唯一键 139→139 | **PASS** 排除生效 |
| **C-5** | 绑定表注入 `SIX_CELL_BINDING_VERIFIED = NO` | 该键文件集 `['BT','S7']` 保持正确 | **PASS** 跨文件统计正常 |

```text
⇒ 【汇总：5 / 5 PASS】

⇒ 【最要紧的是 C-1】：它证明这个检查器【确实会失败】。
   在 §6 里塞一个 `TEST_RUN = PASS`（原值 `NONE`），
   它立刻报出 1 个同键异值并指名该键。
   ⇒ 故 `CHECK_ALIGNMENT_CONFLICTS = 0` 这个结论，
     【不是】一个恒输出 0 的检查器给出的。

⇒ 【C-3 顺带复现了我上一轮的错误】：
   `XY`（2 字符）不计入、`XYZ`（3 字符）计入 ——
   说明阈值确实是 3。
   ⇒ 我上轮用 `{5,}` 才会少算 2 个键（137 vs 139）。
```

### 4.3 恢复校验

```text
⇒ 五次注入后，把十份文件从正式目录重新覆盖回临时目录，
   重新计算十份 SHA-256，与注入前基线【逐份比对】：
   ⇒ 【全部 SAME】。
   ⇒ 即：本次反例测试【没有污染任何正式文档】。
```

### 4.4 这次执行【没有】证明的

```text
⇒ ① 不证明检查器对【第六类我没想到的失效】有效
   ⇒ 5 个反例覆盖的是：值冲突、缩进误判、阈值、表格排除、跨文件集合。
     这不构成穷举。

⇒ ② 不证明在真实文档上的输出【本来】就正确
   ⇒ 反例是人为注入的。它证明"注入能被抓到"，
     不证明"没注入时确实没问题" —— 后者仍是独立复核的事。

⇒ ③ 不改变 `CHECK_ALIGNMENT_VERIFIED = NO`
   ⇒ 我是检查器的作者，也是测试的设计者。
     两者同源，不能自证。
```

## 五 · 一个必须说清的限制

```text
⇒ 即使五个反例全部通过，也只证明：
   「该检查器能检出【我想到的】这五类失效」。

⇒ 【不证明】：
   · 它没有第六类没想到的失效
   · 它在本轮真实文档上的输出是对的
     （反例是在副本上造的，不等于真实文档无误）

⇒ 【这正是为什么 B-5 要独立复核】：
   我能设计出针对我自己错的测试，
   但设计不出针对我"不知道自己不知道"的测试。
```

## 六 · 一句

```text
⇒ 上一轮我把检查器改到不会失败，然后引用它的输出证明"冲突=0"。
   ⇒ 那一步的错误不在数值，在【顺序】：
     我先有了想要的结论，再去找能产生它的口径。

⇒ 这份反例集的用途，是把那个顺序扳回来：
   先固定口径，再造应当被抓住的东西，
   然后看它抓不抓得住。
   ⇒ 抓不住，就说明前几轮那些 0 都不能用。
```
