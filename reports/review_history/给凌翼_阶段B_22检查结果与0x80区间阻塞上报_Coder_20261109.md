## 二 · 检查中发现的问题（按严重度）

### 2.1 【阻塞】`0x81–0x8B` 全部落在 §2 拒绝区间

```text
⇒ 【§2 原文，两处并存】：

   L124: `0x00  保留（不得使用）`
   L125: `0x80-0xFF 保留给后续版本（本节不得出现）`

   L461: `| N3 | OBJECT_TYPE = 0x00 或 ≥ 0x80 | 拒绝 | 2.2 |`
   L516: `步骤 3  读 OBJECT_TYPE（1） —— 非法取值拒绝（N3）`

⇒ 【冲突】：同一份 §2 里，
   一处说"保留给后续版本"（暗示将来可用），
   另一处是【解析时的硬拒绝规则】。

   ⇒ 若 N3 有效 ⇒ 任何 0x80–0xFF 记录【在任何版本下】都被拒。
   ⇒ 若"保留给后续版本"有效 ⇒ N3 的写法定错了，
     应当是"拒绝【本版本】未登记的 ≥0x80"。
```

```text
⇒ 【受影响范围（实测，不是估计）】：

   | 对象 | OBJECT_TYPE | 是否 ≥ 0x80 |
   |---|---|---|
   | 全部 11 类业务对象 | 0x81–0x8B | 是 |
   | TV-01 | 0x88 | 是 |
   | TV-02 | 0x89 | 是 |
   | TV-05 | 0x8B | 是 |
   | TV-06 | 0x8A | 是 |
   | TV-07 | 0x8B | 是 |

   ⇒ 即：B2-2 以来【所有】非引用类对象与其全部向量，
     都建立在 §2 明文拒绝的字节值上。
```

```text
⇒ 【我是怎么绕过的（如实交代）】：
   B2-2 一节写的是：
   「不给最终类型编号（§2 已把 0x80–0xFF 保留给后续版本，
     但【启用哪些、按什么顺序启用】须复核后定版）」

   ⇒ 我把「保留给后续版本」解释成「可以启用」，
     并【没有回去核对 N3 拒绝规则】。
   ⇒ 这是"读到自己想要的那句就停"。
   ⇒ 6 轮复核、3 位复核人、我自己，都没查过 N3 与 0x81 并存。
```

```text
⇒ 【我要明确】：这个解释【是我的】，未经任何裁定。
   ⇒ 它可能对（若"保留"意在允许将来启用），
     也可能错（若 N3 是有意的版本内硬边界）。
   ⇒ 我【不能】自己决定。
```
