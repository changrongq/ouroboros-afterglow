## 1. 四项逐条落地

### 第 1 条 — `PROBE_CLEAN != BUSINESS_CLEAN`（ACCEPTED，BIND SUBJECT + SCOPE TO VERDICT）

`V2AuditResult` 现在**强制携带**：

| 字段 | 值 | 作用 |
|---|---|---|
| `subject` | `PROBE` / `BUSINESS` | 判定是**关于谁**的 |
| `scope` | `POINT_IN_TIME_SINGLE_ENUMERATION` | 判定**覆盖什么** |
| `promotable_to_business_clean` | 恒 `False` | probe 的 CLEAN 不得被并入业务隔离主张 |

`PERSISTENT_BUSINESS_CLEAN = "NOT ESTABLISHED"` 作为模块常量，判定里改不动它。

### 第 2 条 — 两次快照早停（ACCEPTED **AS DIAGNOSTIC ONLY**）

裁决原句我照抄进代码注释，不转述：

```text
E(t1) == E(t2) DOES NOT PROVE QUIESCENCE
E(t1) != E(t2) DOES NOT PROVE SNAPSHOT IMPOSSIBILITY
```

新增 `quiescence_gate()`。它不采集证据、不判断真实进程，只回答"三个定义在不在"：

```text
required:
  OBSERVATION_BOUNDARY
  SNAPSHOT_COVERAGE_SEMANTICS
  TIME_SCOPE_OF_ASSURANCE
```

三者当前**全缺** ⇒ `gate_open=False` ⇒ 返回：

```text
c_feasibility  = NOT ESTABLISHED
exploration    = STOPPED
quiescence_proven = False
two_snapshot_early_stop = DIAGNOSTIC ONLY
```

我在函数 docstring 里写死了一条自律：**传 `True` 是调用方在断言"定义存在"，不是证明其可信；不得为了解封而传 `True`**——那是自我授权。

### 第 3 条 — 不可读目标对照（AUTHORIZED WITHIN EXISTING T1）

常量化，使"永远不 CLEAN"不可被改口：

```text
UNREADABLE_TARGET_CONTROL_RESULT        = UNRESOLVED
UNREADABLE_TARGET_CONTROL_MAY_BE_CLEAN  = False
SIMULATION_IS_COMPLETENESS_PROOF        = False
```

### 第 4 条 — 持续性阻断重述（ACCEPTED）

> REQUIRED IN APPLICABLE REVIEWS AND WIRING DECISIONS

做成**判定字段**而不是报告里的一句话：

```text
PERSISTENT_WORKER_CLEAN_BLOCK = "ACTIVE"
V2AuditResult.persistent_worker_clean_block = "ACTIVE"   # 默认值，每个判定都带
```

这样它无法从任何一个 verdict 里被悄悄省略——漏掉它需要显式删字段，而删字段会被 review 看见。

## 3 · CLEAN 的自我声明（第 1 + 2 条合起来的后果）

V2 现在产出的 CLEAN，`detail` 里必须带这段：

```text
SCOPE=POINT_IN_TIME_SINGLE_ENUMERATION subject=BUSINESS
-- this is NOT a quiescence claim: handles opened after this enumeration
   are outside it; PERSISTENT_WORKER_CLEAN_BLOCK='ACTIVE'
```

也就是说，CLEAN 这个词在这里被**限定**了：它说"在这一次枚举的瞬间，我看到的相关句柄里没有目标"，**不说**"此后也没有"。这正好是裁决第 2 条要求的那层限定，只是落到了判定字符串里，而不是留在我们的对话里。
