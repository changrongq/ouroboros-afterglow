# 二 · 待裁定的两项（D1-1 / D1-2 各自的核心命题）

## D1-1 · 记录不可变性（方案 A）

```text
命题一：commit_state 必须移出 EventRecord
  ⇒ 留在内部会产生 R-2 指出的矛盾：
     要么每次状态变化重算摘要（不可变性失效），
     要么逃出摘要（可被任意改写）。

命题二：不可变性的起算点 = 首次通过校验并 fsync 返回
  ⇒ 不是发送、不是校验、不是分配 seq。
  ⇒ 早了：失败提交也留永久痕迹。
  ⇒ 晚了：fsync 与 ACK 之间可被改写。

命题三：INVALID 分两种来源，不得合并
  ⇒ ① 已观察到确定违反   → 立即处理，不等判定点
  ⇒ ② 已达判定点且缺必需证据 → INVALID（即 L3）

命题四：等待态与 INVALID 不得重叠
  ⇒ 执行中、判定点未到、仅暂时缺证 ⇒ 保持待定，不判 INVALID
```

## D1-2 · WRITE_COMMIT 语义边界

```text
命题五：建议弃用 WRITE_COMMIT 这个名称
  ⇒ 它把四个不同事件压成一个词，
     而当前实现只能产生其中两个。

命题六：四个事件的可产生性
  ⇒ WRITE_OPERATION_RETURNED    可产生
  ⇒ STATE_WRITE_COMPLETED       可产生
  ⇒ STATE_DURABILITY_CONFIRMED  【不可产生】fsync 计数 = 0
  ⇒ EVENT_RECORD_ACKNOWLEDGED   【不能】无记录者

命题七：日志 ACK 不得冒充状态写入或持久化证明
  ⇒ 两者是两个独立的持久化保证。
```
