## 2. 四条 P1 的闭合（含知微原样反例的复现）

### §4 单入口目录错位（最严重：干净快照"假绿"）
- **病灶**：`qualify_phase_a.py` 硬编码读 `RC9_ledgers`，而 suite 写当前版本目录。**干净快照下 `PHASE_A_QUALIFICATION=FAIL`**；本机因残留 `RC9_ledgers` 而假 PASS。
- **修法**：`run_known_answer_suite.py` 撰写 **`RC11_run_manifest.json`**（记录**本次实际** ledger 目录 + 产物身份 + fixture-id 清单）；`qualify_phase_a.py` 读取该 manifest 决定 replay 目录。**不再跨脚本硬编版本目录**，并每次运行前删除旧 manifest。
- **复现**（知微场景：无 `RC9_ledgers`）：
  ```
  clean snapshot entry point: PASS
  aggregator hard-codes a version ledger dir: False
  run manifest ledger_dir: ...\RC11_ledgers
  ```

### §5 V4 关键结果被重算却未比较
- **病灶**：V4.1/V4b 的 `expected_keys` 只含 `(L1, PRE_RESET_CHANGE_CLASS)`；`_recompute_v4_1`/`_recompute_non_separable` 算了特殊结果却被排除在比较外。故改 `C2_ATTEMPT/INVALIDITY_CODE/L2`(V4.1) 或 `C2/C3`(V4b) 仍 PASS。
- **修法**：为 V4.1/V4b 登记各自**完整结果 schema**（V4.1 六键、V4b 四键）；replay 落实 `recomputed_keys == expected_keys` **精确相等**，并校验 actual 必需字段**存在**（缺 ≠ 合法 None）；`_recompute_non_separable` 不再硬编 `False`，而是**读取**注册句柄的能力观察。
- **复现**（知微原样）：
  ```
  [MISMATCH] V4.1 checked=6/6 mism={'C2_ATTEMPT': ('PASS','INVALID'),
             'INVALIDITY_CODE': ('WRONG','CAUSAL_CONTRAST_RULE_MISSING'), 'L2': ('PASS','N/A')}
  [MISMATCH] V4b checked=4/4 mism={'C2': ('ATTRIBUTED','ARCHITECTURALLY_NOT_IDENTIFIABLE'), ...}
  RECOMPUTE_FROM_LEDGER = FAIL   (exit 1)
  ```

### §6 精确 13 集只核对文件名
- **病灶**：完整性与实际选合同分别取自"文件名"与"文件内 fixture_id"，两者无一致性检查。
- **修法**：`assert_exact_fixture_set` 现在核对 **`filename stem == item.fixture_id == ledger.fixture_id`** 三源一致，且内部 ID **唯一**、**精确等于冻结 13 集**。
- **复现**（知微原样）：
  ```
  [FAIL] LEDGER_IDENTITY_MISMATCH: file=V0.json stem='V0' outer='V1' inner='V1'
  exit=1
  ```

### §7 reset preserve 规则未由原始证据重算
- **病灶**：bundle 只查 `reset_valid==True` 且 `verified_restored==S_restored`；未查 `accepted_handoff==verified_restored`（`reset.py` preserve 规则）。故 handoff 后保留字节被改、`reset_valid=True` 时仍 PASS。
- **修法**：门禁从**原始字节**重算 preserve 规则；`reset_valid` 只作**待核对声明**。
- **复现**（知微原样）：
  ```
  S7 PRESERVE-BREAK -> protocol: INVALID l2: INVALID
    code: RESET_PRESERVE_RULE_BREAK: A1/C accepted_handoff != verified_restored (byte-level);
          preserved state changed across reset
  ```

## 3. §8 实现 / 措辞问题

- **单一权威源**：`fixtures._run_reset_suite` 的 `required_pre_class`/`attempted` 现取自 `evidence_contract.get_contract(fid)`，与 replay **同源**；构造参数仍取 `FIXTURE_CONFIGS`（构造 vs 判定职责分离）。
- **结构化派生**：`GateResult` 增加显式子判定字段（`reset_valid` / `j_timing_ok` / `preserve_rule_ok` / `reader_ok` / `membership_ok` …）；生产与 replay 都**读结构字段**，不再从错误消息前缀猜状态。修正了知微指出的"生产匹配 `RESET_INVALID`、replay 匹配 `RESET_`"分歧。
- **V4b BEHAVIORAL 措辞**：探针的 behavioral 分支现为**真实调用尝试**（对 public write 传 ON/OFF selector，观察是否被接受），不再是"只再查签名"。
