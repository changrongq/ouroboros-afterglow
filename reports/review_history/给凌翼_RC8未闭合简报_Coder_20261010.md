# 一 · 我实测复现的硬证据（每条都跑过）

```text
§3  reader 异常不进判定
    恒定 reader（不读 substrate）=> qualifying driver 仍 PASS 13/13，exit 0
    reader_witness 被记录，但没有 gate 消费它

§4  V5 前置 class 不进验收
    V5b + 恒定 extra => PRE=C2（根本没有建立 C3），却仍 L2=PASS/C2，oracle 匹配
    ⇒ 该 profile 声称测"C3→C2 降级"，实际"从未建立 C3"也能过

§5  ledger 重算可零检查 PASS
    翻转 L1 的 V0 ledger      => RECOMPUTE_FROM_LEDGER = PASS
    V5a actual 清成 {}        => RECOMPUTE_FROM_LEDGER = PASS
    正常跑：7/13 fixture matched_keys=0；V4b 根本没存 observations
    ⇒ 比较器只比对"actual 恰好有的 key"；也未从原始 bytes 重算 digest

§6  J 的 handoff 与 reset 的 handoff 未连成同一对象
    在 J 见证后、reset 取 handoff 前，把每个 C 臂 q 加倍
    => 仍 j_timing_ok=True、reset_valid=True、L2=PASS、oracle 匹配
    ⇒ 中间缺"早先 S_handoff == reset 接收的 handoff"这一环

§7  INVALID 支配未覆盖少成员
    冻结四成员集缺 B2 => post_C3=INVALID，但 L2=PASS/C2
    ⇒ 公共 gate 把 protocol INVALID 降成 C2 正结果

§8  绑定角色集不相等
    REQUIRED_RUNTIME_ROLES = 14
    MANIFEST §十三 = 16 个执行角色（parser 还从 BUILD_PROVENANCE 多解析 2 个 => 18）
    漏检：adversarial_regression.py、recompute_from_ledger.py（在表里但不在 REQUIRED）
    ⇒ 给这两个文件加注释 ⇒ 完整 driver 仍 PASS / QUALIFYING / exit 0

§9  V4b 仍暴露可分离写入
    CombinedOnlyWriter.arm 是【公开】的；off.arm.store() 就能造 ON/OFF 对
    实测：on_q=2 / off_q=0 / literal 同 —— 仍输出 ARCHITECTURALLY_NOT_IDENTIFIABLE
    ⇒ ANI 靠"自报 capability tuple"，不是接口事实

        §七 READ_OPERATOR_HASH/LITERAL_CONSUMER_HASH 仍 83cbc20b…，§十三/实际 = 2180f0d9…
```
