## 0. 结论：钳星判断**完全正确**——这不是代码 bug，是**环境前提**

| 组件 | Coder 本机 | 钳星机器 | 我的裁定 |
|---|---|---|---|
| `win32_isolation.py` | 21/21 | **21/21（一致）** | 一致；且证明 rc=1332 bug 已修 |
| `q3_handle_audit.py` | 5/5 | 3/3（一致，旧版计数） | 一致 |
| `win32_worker_process.py` | 4/4 | **FAIL err=5** | **环境前提差异** |
| `q3_reset_chain.py` | 51/51 | **FAIL Errno 13（同根）** | 同根 |
| `q3_qualify.py` | PASS | **FAIL** | 同根 |

**根因**：钳星机器上当前进程跑在 **`nt authority\system`（`OEM-AI$`）服务账户**下。
`CreateProcessWithLogonW` 需要调用方具备所需**登录能力/特权**；服务账户上下文下被 OS 拒绝 ⇒ **err=5**。
Coder 本机跑在 **`oem-ai\administrator`（交互式管理员会话）** ⇒ 成功。

**我本机实测**（证明是账户上下文，不是代码）：当前 token SID = `S-1-5-21-…-500`（内置 Administrator）；`whoami` = `oem-ai\administrator`。

## 1. 钳星的核心建议，我采纳并落地

> "Q3 的资格判定，目前还没有跟'运行账户必须能 CreateProcessWithLogonW'这个前置绑定起来。"

这正是要修的。**修法**：

### (a) 明确分类：环境前提 ≠ 安全结果
新增 `EnvPrereqError`（`win32_worker_process.py`）：`CreateProcessWithLogonW` 返回 **err=5** 时抛此错，
语义 = **"运行上下文不满足前置条件"**，**不是** PASS，**也不是** 安全 FAIL。
（实测：monkeypatch 强制 err=5 ⇒ 正确抛 `EnvPrereqError`。）

### (b) 前置探针 `check_spawn_prerequisite()`
在真正跑测试**之前**，用 `python -c "pass"` 试一次跨账户 spawn：
- 成功 ⇒ 继续；
- 失败 ⇒ 报 **`NOT_APPLICABLE`** + 明确写"调用账户缺少 CreateProcessWithLogonW 所需登录能力"。
（实测：坏账户名 ⇒ `False | err=1326`。）

### (c) driver 与各 selftest 都接前置
`win32_worker_process`、`q3_reset_chain`：前置不满足 ⇒ **退出码 2（SKIP/NOT_APPLICABLE）**；
`q3_qualify.py`：汇总时 **SKIP ⇒ `NOT_EVALUATED`（exit 2）**，并打印：
```
A SKIP here usually means an ENVIRONMENT PRECONDITION was not met
(no credential, or the calling account cannot CreateProcessWithLogonW
 e.g. running as nt authority\system). This is NOT a security result.
```

**效果**：钳星那台机器现在会得到 **`NOT_EVALUATED`（诚实：环境跑不了）**，而**不是**误导性的 `FAIL`，也**不是**假 `PASS`。
