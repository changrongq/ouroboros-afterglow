## 5. 两项 P2 观察

### P2-A：reset_identity_ok 在身份失败时仍为 True

位置：`afterglow_harness/evidence_bundle.py:425–431`。

当前两个标志都取 `not preserve_break`。我只将 V5a/A1/C 的 `verified_restored.q_raw` 改为 4，使它与存入的 S_restored 不一致，实际结果为：

```text
protocol = INVALID
code = RESET_OBJECT_IDENTITY_BREAK
reset_identity_ok = True
preserve_rule_ok = True
```

相反，在上面的纯 preserve 违例中，restored 身份本身相符，`reset_identity_ok` 却为 False。总判定正确拒绝，因此不是四项 P1 的重新打开；但该结构化字段尚不能作为可靠的身份子判定。建议身份检查、preserve 检查分别返回明确结果，并为尚未执行的检查保留“未评估”语义，避免下游将默认 True 当成通过。

### P2-B：正对照的 behavioral_split 仍来自签名

位置：`afterglow_harness/fixtures.py:533–543`。

当签名含 extra_mode 或 **kwargs 时，代码直接设置 `behavioral_split=True`，没有调用 write。我对真实 `SeparableControlHandle.write` 加计数包装，保留其签名和原实现，实测：

```text
write_calls = []
structural_split = True
behavioral_split = True
```

无 selector 的分支确实新增了非法关键字调用尝试，但尚不能将整个探针描述为“已经真实执行 ON/OFF 两种写入并观察效果”。当前冻结正负对照的接口可分离性判定仍符合预期；此项是证据范围与行为标签的问题。建议将这一分支明确标为结构观察，或者补上实际 ON/OFF 调用与状态效果比较，再声称行为验证完成。

两项复现证据均在 `supplement/supplement-results.json`。它们不要求重新讨论 substrate/reader/reset 设计。
