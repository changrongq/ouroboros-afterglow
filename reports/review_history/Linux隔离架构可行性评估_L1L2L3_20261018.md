## 1 · L-1：Linux 是否有适合本目标的直接访问强制机制？

### 1.1 候选：Landlock

**官方原文（`landlock(7)`）**：

> Landlock is an access-control system that enables any processes to **securely restrict themselves and their future children**. Because Landlock is a **stackable Linux Security Module (LSM)** ...

> If the `landlock_restrict_self(2)` system call succeeds, the current thread is now restricted and this policy will be enforced on all its subsequently created children as well. **Once a thread is landlocked, there is no way to remove its security policy; only adding more restrictions is allowed.**

**这一句直接回答了 G-2 的时间不变性问题。**

对照 Windows 候选（受限令牌 / AppContainer）：那边的"worker 不能改边界"是**推论**（worker 无 `WRITE_DAC` / 无能力），而 Landlock 这边是**规范明文**——"no way to remove its security policy"。

**这是 L-1 的核心发现：Linux 把"不可撤销"写进了规范，而不需要我们从权限推断。**

### 1.2 但官方文档同时给出三条限制，必须原样记录

**限制一：创建前的既有 fd 不受约束**

> **Files or directories opened before the sandboxing are not subject to these restrictions.**

⇒ 与 Windows 的"既有句柄不撤销"**完全同构**。
⇒ 结论：**Landlock 也不能挽救"创建前已持有"的问题**。必须靠不继承 + 创建时点纪律（对应 M-1 的配置 (a)/(b)）。

**限制二：并非所有文件相关操作都可限制（原文 CAVEATS）**

> It is currently **not possible to restrict** some file-related actions accessible through these system call families: `chdir(2)`, `stat(2)`, `flock(2)`, `chmod(2)`, `chown(2)`, `setxattr(2)`, `utime(2)`, `fcntl(2)`, `access(2)`. Future Landlock evolutions will enable to restrict them.

⇒ **`stat(2)` 与 `access(2)` 不可限制**——这意味着 worker **可能可以探测受保护对象的存在与元数据**，即使不能读内容。
⇒ 对 AfterGlow 的影响：**是否构成信息泄漏取决于 attempted claim**。若 claim 只依赖"内容是否被读取"，元数据泄漏可能属于"可披露的非阻塞风险"；若依赖"是否曾接触"，则可能阻塞。**这需要睫的证明语义裁定，不是我判。**

**限制三：`LANDLOCK_ACCESS_FS_REFER` 默认拒绝**

> This is the only access right which is **denied by default** by any ruleset, even if the right is not specified as handled at ruleset creation time.

⇒ 这是**有利**的（默认拒绝方向正确），不影响 L-1 结论。

### 1.3 L-1 结论

```text
L1_RESULT = CANDIDATE IDENTIFIED
```

**依据**：Landlock 的"不可撤销"是**规范明文**而非推论，时间不变性比 Windows 的候选更强；且它明确支持"restrict themselves and their future children"。

**但**：既有 fd 不受约束、`stat`/`access` 不可限制 —— 这两条限制必须在下一轮设计中显式处理，不能当作已解决。

## 2 · L-2：fd、IPC、代理与跨 Reset 信息通路能否被可论证地控制？

这是 **G-2 的唯一阻断项**（`G2_INDIRECT_CHANNEL_CONTROL = NOT ESTABLISHED`）。Linux 是否有改进？

### 2.1 IPC scoping：官方明确支持，但范围有限

**官方原文（`landlock(7)`）**：

> **IPC scoping** — Similar to the implicit Ptrace restrictions, we may want to further restrict interactions between sandboxes. Therefore, at ruleset creation time, each Landlock domain can restrict the scope for certain operations, so that these operations can only reach out to processes within the same Landlock domain or in a nested Landlock domain.

可 scoped 的操作（原文列举）：

| Scope 常量 | 引入版本 | 作用 |
|---|---|---|
| `LANDLOCK_SCOPE_SIGNAL` | ABI v6 (Linux 6.12) | 限制向域外进程发信号 |
| `LANDLOCK_SCOPE_ABSTRACT_UNIX_SOCKET` | ABI v6 (Linux 6.12) | 限制连接域外创建的抽象 UNIX socket |
| `LANDLOCK_ACCESS_FS_RESOLVE_UNIX` | ABI v9 (Linux 7.1) | 限制解析路径式 UNIX socket |

**关键限制（原文）**：

> **IPC scoping does not support exceptions via `landlock_add_rule(2)`.** If an operation is scoped within a domain, **no rules can be added to allow access to resources or processes outside of the scope.**

⇒ 这是**全有或全无**：一旦 scope，就无法对个别对端开口。
⇒ 对 AfterGlow 的影响：**若实验需要 worker 与受信任控制器通信（凌翼 §2 明确要求合法通道），scope 会把它一并切断**——除非控制器也在同一/嵌套域内。

### 2.2 但 L-2 的真问题不是"能否限制 IPC"，而是"代理能否绕过"

**必须直说的是**：Landlock 的 scoping **限制的是"连接域外抽象 UNIX socket / 发信号"**，它**没有**声称能限制：

| 通道 | 官方文档是否覆盖 | 我的判断 |
|---|---|---|
| 具名管道（FIFO，文件系统路径） | **部分**——经 `LANDLOCK_ACCESS_FS_*` 文件路径规则可管 | 需在下一轮确认具体 right |
| TCP socket | **ABI v4 起有 `LANDLOCK_ACCESS_NET_CONNECT_TCP`** | 可管连接，**但端口粒度为 "port"，不是对端身份** |
| 域内代理进程 | **不覆盖**——同域内视为可信 | **这是关键缺口** |
| 通过网络的服务 | 部分（TCP connect 可限） | 需实测确认 |
| 继承的 socket fd | **不覆盖**（"opened before sandboxing" 同一条） | 缺口 |

**最关键的缺口**：**同一 Landlock 域内的进程互不设防**。若 worker 与一个能读 $P$ 的辅助进程同域，代理路径成立。

### 2.3 跨 Reset 通路

凌翼 §2 要求覆盖"重置前后信息通路未断开"。Landlock 文档**未涉及** Reset 语义——它只管进程生命周期内的访问，不管**状态留存**。

⇒ Reset 后的信息残留（缓存、临时文件、共享内存）**不是 Landlock 能回答的问题**，需要独立机制。**我未核实是否有对应 Linux 机制**，本轮不声称。

### 2.4 L-2 结论

```text
L2_RESULT = NOT ESTABLISHED
```

**但比 Windows 有实质进展**，理由须写清：

| 维度 | Windows（候选 1/2） | Linux（Landlock） |
|---|---|---|
| IPC scoping | **无对应机制** | **有**（`LANDLOCK_SCOPE_*`，ABI v6+） |
| 域内代理 | 不覆盖 | **不覆盖**（同样的缺口） |
| 端口级网络限制 | 无对应 | 有（`LANDLOCK_ACCESS_NET_CONNECT_TCP`） |
| Reset 残留 | 不覆盖 | 不覆盖（文档未涉及） |

**即：Linux 把"能否限制通信"从"不能"变成"部分能"，但"域内代理"与"Reset 残留"两个核心缺口仍在。**

## 3 · L-3：环境、TCB、独立验证与维护成本

### 3.1 内核版本门槛（官方数据，逐项照录）

| 所需能力 | 最低 ABI | 最低内核 |
|---|---|---|
| Landlock 基础 | v1 | **Linux 5.13** |
| TCP 端口限制 | v4 | Linux 6.7 |
| **IPC scoping（signal / abstract socket）** | **v6** | **Linux 6.12** |
| 路径式 UNIX socket 限制 | v9 | Linux 7.1 |

**关键**：**L-2 需要的 IPC scoping 要求 Linux 6.12+**。这不是"任意 Linux 都能做"。

### 3.2 启用的前提（原文）

> Landlock is enabled by `CONFIG_SECURITY_LANDLOCK`. The `lsm=lsm1,...,lsmN` command line parameter controls the sequence ... It must contain the string `landlock` to enable Landlock.
> We can check that Landlock is enabled by looking for `landlock: Up and running.` in kernel logs.

⇒ **发行版可能编译了但未在启动参数中启用**。这是一个**每台机器都要逐一确认**的前提，不能假设。

### 3.3 TCB 与独立验证成本

| 项目 | 需求 |
|---|---|
| 受信任控制器 | 需要：施加 Landlock 的父进程必须是可信的 |
| 独立验证 | 需要：`/proc/<pid>/status` 的 `Seccomp` 字段**只反映 seccomp**，Landlock 域**无法从 /proc 直接读**（我**未核实**是否有对应接口，本轮不声称） |
| 负向测试 | 需要构造"尝试越界"的用例，且必须在**同一 ABI 版本**下可复现 |
| 维护成本 | 内核 ABI 版本差异需逐一适配（v1→v9 共 9 个版本的能力差异） |

### 3.4 L-3 结论

```text
L3_RESULT = PLAUSIBLE BUT COSTLY
```

**理由**：

- **可实现**：Landlock 是主线内核特性，无需第三方驱动
- **但有硬门槛**：IPC scoping 需 Linux 6.12+，且必须启动时启用
- **可验证性存疑**：Landlock 域是否可从外部独立观测，**我未核实**
- **ABI 碎片**：9 个版本的能力差异，独立复核必须锁定确切 ABI

**"成本是否合理"我不能替凌翼判**——这取决于项目愿意接受多新的内核基线。

## 4 · 与 Windows 的对照（凌翼要求"操作系统中立"）

| 维度 | Windows Q3 候选 | Linux Landlock |
|---|---|---|
| 不可撤销性 | 推论（无 `WRITE_DAC` / 无 capability） | **规范明文**："no way to remove" |
| 既有句柄/fd | 不撤销 | **不撤销** |
| 子进程继承 | 继承受限令牌/容器 | **继承域**（明文） |
| IPC 限制 | **无对应机制** | 有（ABI v6+） |
| 元数据访问 | DACL 可挡 | **`stat`/`access` 不可限制** |
| 域内代理 | 缺口 | **缺口** |
| Reset 残留 | 缺口 | 缺口 |

**结论：Linux 在"不可撤销性"与"IPC 限制"两项上明显更强；在"既有 fd"与"域内代理"两项上与 Windows 同样卡住。**

⇒ **平台迁移不能解决 G-2 的两个核心缺口**，只能改善其中一部分。

## 7 · 需要凌翼/睫裁定的三件事

**一、`stat`/`access` 不可限制，是否构成阻塞？**
Landlock 允许 worker 探测受保护对象的存在与元数据。是否影响 attempted claim，**取决于科学归因的定义**——睫的证明语义范围。

**二、"域内代理"是否可接受为已披露的剩余风险？**
若 worker 只能与同域进程通信，而域内进程受独立控制，则代理风险可能降级为"可披露的非阻塞风险"。**这是威胁模型裁定，不是技术裁定。**

**三、内核基线 6.12+ 是否可接受？**
L-2 的 IPC scoping 需要它。若项目无法承诺该基线，则 L-2 连"部分"都拿不到。
