## 三 · 三处修订的逐条落点

### R-1 前置最小长度 17 → 18

| 项 | 修订前 | 修订后 |
|---|---|---|
| §2 2.5 步骤 0 | `L ≥ 17` | `L ≥ 18` |
| 分量说明 | 罗列六项但写 17 | 六项相加 = 18，并区分固定头 14 + 尾部 4 |
| N16 名称 | 「输入长度 < 头部长度」 | 「输入长度不足【固定框架最小长度】（L < 18）」 |
| N16 描述 | 「连 17 字节都不到」 | 「L < 18，步骤 0 规则性拒绝」 |

**为什么 17 是错的**：裁定指出固定头部本身为 14 字节。核实：
`MAGIC(8) + FORMAT_VER(2) + OBJECT_TYPE(1) + RESERVED(1) + FIELD_COUNT(2) = 14`。
加尾部 `TOTAL_LEN(4)` 得 18。原稿「至少头部 + 末尾 4 字节都要在」这句话是对的，
但它把结论写成 17，与自己的加法不符。

**新增的一句**（按裁定要求）：
「18 只表示通过框架最低长度检查，不表示满足任何对象类型字段要求。」

### R-2 摘要覆盖范围（选 A）

| 项 | 修订前 | 修订后 |
|---|---|---|
| 公式 | `SHA-256( OBJECT_TYPE ‖ header_fixed ‖ fields_encoding )` | 同，但**展开写全**为 `OBJECT_TYPE ‖ FORMAT_VER ‖ OBJECT_TYPE ‖ RESERVED ‖ FIELD_COUNT ‖ FIELDS` |
| 覆盖清单 | 含 `TOTAL_LEN` | **删去**，明确「不覆盖：MAGIC、TOTAL_LEN」 |
| 理由 | 仅说 MAGIC 是定值 | 补：`TOTAL_LEN` 的正确性由解析顺序独立保证（步骤 0 / N9 / N10），不依赖摘要 |

**已发布向量未重算**（依裁定方案 A）。

**新增的边界表述**（按裁定原文）：
摘要只覆盖规定的摘要输入字节，不是对完整编码的逐字节散列；
只有在规范解析、字段长度、MAGIC、版本、尾部长度**检查全部成功之后**，
才能将合法编码与摘要共同用于引用完整性判断。

## 四 · 四条条件的落实

### C-1 消除相关文字矛盾

**发现第二处真矛盾**（原申请未提出，执行中查出的）：

§2 2.1 一边写 `TOTAL_LEN` 是「**含本字段在内**的总字节数」，
同节又写「**所有长度字段【不含自身】**」。两句直接冲突。

**已拆为两类长度语义**：

| 类别 | 字段 | 语义 |
|---|---|---|
| 字段长度 | FIELDS 内每字段的 `LEN(2)` | 表示 VALUE 自身字节数，**不含** TAG(1)+LEN(2) 这 3 字节头 |
| 整个编码单位长度 | `TOTAL_LEN(4)` | 表示**含 MAGIC、含全部 FIELDS、含自身**的总字节数 |

并写明：「不含自身」只适用于字段 `LEN`；`TOTAL_LEN` 恰恰相反。
另补了为什么这样定的理由（放末尾可校验"看起来读完了"；若 `TOTAL_LEN`
不含自身，校验时要额外 +4，而那个 +4 无处体现，反而容易算错）。

`header_fixed` 的准确组成也在 2.4 展开写全（含两处 `OBJECT_TYPE` 的不同作用）。

### C-2 前置解析安全

步骤 6 补两处检查：

```text
步骤 6  逐字段读 TAG(1)+LEN(2)，
        每字段【读 TAG/LEN 之前】先检查
        「剩余字节 ≥ 3 + 4」          —— 不足则拒绝（N17）
        再在读 VALUE 之前检查
        「剩余字节 ≥ LEN + 4」        —— 不足则拒绝（N17）
```

**新增专段**「拒绝必须是规则性的」：
每一处拒绝须表现为可识别的、有对应规则的拒绝结果，
**不得**让 `IndexError` / `ValueError` / `struct` 解包失败成为实际拒绝路径。


```python
# 内层 KEY_TRIPLE("R1", 1, 1)
f_in = (field(0x21, b'R1') + field(0x22, struct.pack('>Q', 1))
        + field(0x23, struct.pack('>Q', 1)))

inner = MAGIC + body_in + struct.pack('>I', len(MAGIC) + len(body_in) + 4)

full = MAGIC + body_out + struct.pack('>I', len(MAGIC) + len(body_out) + 4)
```
