| 独立性依据 | 实际 token / 对象安全描述符 / 句柄 | **留白** |
| 由谁启动 | 受信控制器 | **留白** |

```text
⇒ 【当前合成实现的实测形状（已核代码，非资格）】：

   observer.py:
     class StateObserver:
         def __init__(self, state: RegisteredState): self._state = state
         def snapshot(self): return self._state.snapshot()

   ⇒ 【问题 1】：observer 持有 RegisteredState【同一个对象】，
     而该对象有 write_literal() / write_substrate() 两个写方法。
   ⇒ 【问题 2】：代码注释写 "The observer has no method that writes
     registered state. (No write handles are held here.)"
     ⇒ 这是【没有公开写方法】的包装，不是能力隔离。

   ⇒ 结论（与知微一致）：此包装【不能】提供 OS 写权隔离。
```

```text
⇒ 【Windows 层的候选路径（设计推论，非资格）】：
   独立受限 observer 进程，由受信控制器启动；
   observer 对目标只读，对独立证据区可写，W 对该证据区不可写。
   ⇒ 但是否已建立，【需真实 token / SID / DACL 证据】。
```

## 六 · 哪个规则给出哪种结论

| 规则 | 作用域 | 输出 |
|---|---|---|
| `STATE_DELTA_RULE` | 全部 | `ΔS_registered` / `ΔS_identity_masked` / `ΔS_nonstorage`（三个量） |
| `D_ATTRIBUTION`（§13） | Basic L1 / **C1** | 在 `ΔS_identity_masked` 上给出 attribution_result |
| C1 class rule（§28.1） | C1 | 本 episode 在 registered `LITERAL_STORAGE_COMPONENTS` 中的写入 |
| §16 C2 rule | C2 | 在 `ΔS_nonstorage` 上判定 treatment contrast |
| §19–20 C3 rule | C3 | contrast 随 content class 的异质性 |

```text
⇒ 【本实现（已核代码）的对应】：
   evaluator.evaluate_basic_l1(snap_A, snap_B, registered_payload):
     · 若 q_B != q_A  ⇒ INVALID（ARM_CONFIG_INVALID），不作 topping-up
     · h = _literal_byte_diff_count(A.literal, B.literal)
     · h == 0 ⇒ FAIL（确定否定）
     · h == 1 ⇒ UNRESOLVED（落在冻结不确定区）
     · h >= 2 且 B.literal == registered_payload ⇒ PASS, change_class = C1
     · h >= 2 但 B.literal != payload ⇒ PASS（L1）但 C1 NOT established
   ⇒ 这正是 §13 的 `ΔS_identity_masked` 口径（literal 差分 + payload 匹配），
     【不是】ΔS_nonstorage。
```
