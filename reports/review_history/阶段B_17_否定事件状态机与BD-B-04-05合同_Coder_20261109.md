## 零 · 裁定给定

```text
⇒ A-4：
   「未得到可信外部处置的否定事件，必须阻断权威效果；
    已发生的否定事件永久保留，
    但不意味着系统在任何条件下都永久无法恢复。
    当前没有已复核的外部处置协议，因此任何 0x8A 出现时仍须 STOPPED。
    未来如需恢复，必须另行设计有权限、可验证、可追溯的
    追加式处置记录及状态转换合同。
    禁止删除 0x8A、覆盖旧历史、回退 HWM，
    或让 W 自行宣布矛盾已经解除。」

⇒ BD-B-04：
   「若检测到矛盾，但 TSU 与外部诊断写入均失败，
    下次启动未必能够知道该次检测曾经发生。
    不得仅凭'失败时调用过日志接口'，
    推断恢复过程能够发现 `CONTRADICTION_UNRECORDED`。」

⇒ BD-B-05：
   「0x8B 与 0x8A 的互相一致不等于历史尾部完整，更不等于防整体回滚。
    必须区分：
      1. 事件本身可解析、来源合法。
      2. 本地事件链与本地高水位一致。
      3. 外部独立证据确认应有的最新事件范围。
    只有第三项经过验证，才能主张超出 TSU 单一故障域的尾部回滚检测能力。」
```

# 第一部分 · 否定事件状态机

## 一 · 状态集合

```text
⇒ 【系统整体状态】（关于"能否对外生效"）：
   | 状态 | 含义 | 可对外宣告？ |
   |---|---|---|
   | `CLEAN` | 无任何未处置否定事件 | 可（须其余核验通过）|
   | `BLOCKED` | 存在未处置否定事件 | **不可** |
   | `RESOLVING` | 处置记录已存在但未完成核验 | **不可** |
   | `RESOLVED` | 处置已验证通过 | 可（须其余核验通过）|
   | `UNKNOWN` | 无法判定 | **不可**（fail-closed）|

⇒ 【单条否定事件的状态】：
   | 状态 | 含义 |
   |---|---|
   | `RECORDED` | 0x8A 已写入 TSU |
   | `EFFECT_BLOCKED` | 已阻断对外权威效果 |
   | `DISPOSITION_PENDING` | 已有处置记录，待核验 |
   | `DISPOSITION_VERIFIED` | 处置已验证 |
   | `UNRECORDED` | 【检测到但未能写入】—— 见 BD-B-04 |
```

---

## 二 · 状态转换

```text
⇒ 【转换表】：

   起点状态           事件                          终点状态            允许？
   -----------------  ----------------------------  ------------------  ------
   CLEAN              检测到矛盾                     BLOCKED             ✓
   CLEAN              检测到矛盾但写入失败            UNKNOWN             ✓（见 BD-B-04）
   BLOCKED            0x8A 写入成功（同一受信事务）  BLOCKED             ✓
   BLOCKED            外部处置记录写入                RESOLVING           ✓（未来协议）
   RESOLVING          处置记录核验通过                RESOLVED            ✓（未来协议）
   RESOLVING          处置核验失败                    BLOCKED             ✓
   RESOLVED           出现新矛盾                      BLOCKED             ✓
   BLOCKED            删除 0x8A                       ——                  ✗ 禁止
   BLOCKED            回退 HWM                        ——                  ✗ 禁止
   BLOCKED            W 自行宣布解除                  ——                  ✗ 禁止
   RESOLVED           W 自行宣布解除                  ——                  ✗ 禁止
   UNKNOWN            推定 CLEAN                      ——                  ✗ 禁止
   UNKNOWN            任何向可宣告状态的转换          ——                  ✗ 禁止
```

```text
⇒ 【三条不可逆】：
   ① `BLOCKED → CLEAN` **不存在**。
      ⇒ 只能经 `RESOLVING → RESOLVED`，
        而 RESOLVED ≠ CLEAN（历史上有过否定事件）。
   ② `UNKNOWN → 任何可宣告态` **不存在**。
   ③ 任何删除/覆盖/回退 **都不在状态机里**，
     因为它们不是转换，是越权。
```

---

## 三 · 当前可实现的部分与不可实现的部分

```text
⇒ 【可实现的】：
   · `CLEAN → BLOCKED`（检测到矛盾 + 0x8A 写入成功）
   · `CLEAN → UNKNOWN`（检测到但写入失败，见 BD-B-04）
   · `BLOCKED` 的维持

⇒ 【不可实现的（因无协议）】：
   · `BLOCKED → RESOLVING → RESOLVED`
   ⇒ 裁定明写：「当前没有已复核的外部处置协议，
     因此任何 0x8A 出现时仍须 STOPPED。」

⇒ 【故当前的有效状态机是】：

   CLEAN ──检测到矛盾+写入成功──▶ BLOCKED（终态，无出边）
   CLEAN ──检测到矛盾+写入失败──▶ UNKNOWN（终态，无出边）

   ⇒ 【两个终态都不可对外宣告】。
   ⇒ 这与裁定 A-4 完全一致。
```

## 四 · 处置协议的形状（未来用，本轮不实现）

```text
⇒ 裁定要求未来协议必须有：【有权限】、【可验证】、【可追溯】、【追加式】。

⇒ 【本文件只给形状，不给实现】：

   | 要求 | 落地 |
   |---|---|
   | 有权限 | 处置记录只能由 S 写（与 0x8A 同边界）|
   | 可验证 | 处置记录须引用被处置的 0x8A 摘要，并可独立核验依据 |
   | 可追溯 | 追加式，不删不改；处置本身也是一条链 |
   | 追加式 | 与 0x8A 同构：有自身序号、前驱摘要、纳入统一 EHWM 或独立游标 |

   ⇒ 【一个必须回答但本轮答不了的问题】：
     处置记录是否也进 0x8B 的 EHWM 范围？
     · 若进 ⇒ EHWM 混合两类事件，语义变宽
     · 若不进 ⇒ 处置记录自己的尾部缺失无法检测
   ⇒ 见第七节 Q2。
```

# 第二部分 · BD-B-04 证据合同

## 五 · 缺陷确认

```text
⇒ 【我的原设计】（阶段B_12 2.6）：
   写 0x8A 失败时，「在外部可写位置记录失败事实（如 stdout/系统日志）」
   并在下次恢复时判 `CONTRADICTION_UNRECORDED`。

⇒ 【凌翼指出这不成立】：
   「若 TSU 与外部诊断写入均失败，下次启动未必能够知道该次检测曾经发生。」
   「不得仅凭'失败时调用过日志接口'，
     推断恢复过程能够发现 `CONTRADICTION_UNRECORDED`。」

⇒ 【我错在哪，逐点】：
   ① 我假设"日志接口被调用" ⇒ "日志被持久化" ⇒ "下次能读到"。
      ⇒ 这三步每一步都不成立。
   ② stdout 可能未重定向、可能缓冲未刷、可能被清空。
   ③ 系统日志可能在滚动时丢弃。
   ④ 【最关键】：即使写成功，恢复进程【未必会去读那个位置】。
```

## 六 · 修正：三种证据强度，逐层降级

```text
⇒ 【不能一条路径包打天下】。必须分级并【明确每级能证明什么】。
```

### 层级 E1 · 内存内检测（最弱）

```text
⇒ 【内容】：本次运行检测到矛盾。
   ⇒ 【能证明】：本进程知道。
   ⇒ 【不能证明】：跨启动。
   ⇒ 【失效】：进程一退出，无痕。
```

### 层级 E2 · TSU 内记录（最强，但可能写失败）

```text
⇒ 【内容】：0x8A 写入 TSU，且 EHWM 同事务推进。
   ⇒ 【能证明】：跨启动可读、可核验、有链。
   ⇒ 【失效】：TSU 不可写时无法完成。
   ⇒ 【状态】：`BLOCKED`（可检测）
```

### 层级 E3 · 外部诊断记录（弱，且依赖读取方）

```text
⇒ 【内容】：stdout / 系统日志 / 独立诊断文件。
   ⇒ 【能证明】：【若】写入成功【且】恢复进程主动读取【且】未被滚动丢弃，
     则可能知道曾经发生。
   ⇒ 【不能单独证明】：跨启动可信。
   ⇒ 【裁定三节已定】：「stdout 或系统日志可用于诊断，
     但不得未经验证就视为跨启动可信审计。」
```

## 七 · 修正后的处置合同

```text
⇒ 【E3 失败时的正确表述】：

   ✗ 「下次恢复会发现 `CONTRADICTION_UNRECORDED`」
     —— 这是原设计，裁定已否定。

   ✓ 「若 0x8A 与外部诊断均写入失败，
      则该次检测事实【可能跨启动丢失】。
      此时状态为 `UNKNOWN`（无法判定是否曾检测到矛盾），
      并登记：
        CONTRADICTION_DURABILITY = NOT ESTABLISHED」

⇒ 【这不改变安全行为】：
   ⇒ 权威效果【仍然关闭】——因为关闭是默认状态，
     不依赖记录是否存在（承阶段B_12 2.6 的修正）。
   ⇒ 【但改变了"我们能知道什么"】：
     记录失败 ⇒ 我们【不知道自己曾经知道】。
```

```text
⇒ 【一个必须写的推论】：
   若一次检测事实跨启动丢失，则恢复后的系统可能显示 `CLEAN`，
   而实际上曾经检测到矛盾。
   ⇒ 【这是不可接受的，但当前无法消除】。
   ⇒ 故必须登记：`CONTRADICTION_DURABILITY = NOT ESTABLISHED`
     ⇒ 且【不得】以"日志接口被调用过"为由声明已缓解。
```

# 第三部分 · BD-B-05 三层区分

## 八 · 裁定要求的三层

```text
⇒ 凌翼明写三层，且只有第三层能主张"超出 TSU 单一故障域的尾部回滚检测"。
```

| 层 | 内容 | 能证明 | 状态 |
|---|---|---|---|
| **L1** | 事件本身可解析、来源合法 | 单条 0x8A/0x8B 格式正确、root 可解析 | 可实现（需编码器）|
| **L2** | 本地事件链与本地高水位一致 | TSU 内部自洽（链连续、EHWM 与 event_seq 相等）| 可实现 |
| **L3** | 外部独立证据确认应有的最新事件范围 | 防整体回滚 | **不可实现**（0/6）|

```text
⇒ 【关键】：L2 通过 ≠ L3。这是 BD-B-05 的全部要点。

⇒ 【一个具体反例】：
   整个 TSU（含 0x8A 链与 0x8B）一起回滚到时刻 T。
   ⇒ 回滚后：链连续 ✓、EHWM 等于最新 event_seq ✓
   ⇒ L1 ✓、L2 ✓
   ⇒ 【但事件实际上少了一段】。
   ⇒ L3 是唯一能发现它的。
```
