# 三 · 所以：这不是"回滚 vs 冻结"的等价选择

睫把它写成二选一（回滚 / 重冻 b7ec1dca），但**实机证据使二者不等价**：

```text
"回滚到 1386ba22…" 意味着：
   把锚点设成一个【磁盘上不存在】的字节状态的 hash
   ⇒ 每一条下游 hash 都挂在一枚指不到任何文件的值上
   ⇒ 这就是睫说的"后面每一条 hash 都挂在两枚数字之间"——而且其中一枚根本悬空

"冻结 b7ec1dca…" 意味着：
   锚点 = 磁盘上真实存在的 SPEC 对象（36719 B）
   ⇒ 与冻结记录一致，与睫实机一致
   ⇒ 这正是冻结记录【当初就已经写下】的值
```

**⇒ 唯一自洽的答案是 `b7ec1dca…`。回滚会把锚点永久钉在一枚悬空 hash 上。**
