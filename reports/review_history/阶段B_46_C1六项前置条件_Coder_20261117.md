## 一 · C1 的定义边界（先划清）

```text
⇒ prereg §12 C1 = `STORAGE_WRITE_ESTABLISHED`

   表示：storage write 是目前【最高被正向建立】的 change class
   不表示：reality contains only storage change

   最强允许 claim：REGISTERED_STORAGE_WRITE_OBSERVED
   ⇒ 【C1 是证据断言，不是世界断言。】
```

```text
⇒ 【因此 C1 通过也不能推出】：
   ✗ 记忆已形成
   ✗ 该变化会影响未来行为
   ✗ 变化跨重置保持（那是 L2）
   ✗ 有意义的记忆 / 长期保持 / 主观连续
```

## 二 · 六项前置条件

### P1 · 真实候选架构已确定

```text
要求：
  · 明确 registered system 边界（prereg §5）
  · 明确哪些组件属于 registered storage，哪些不属于
  · 明确 literal-storage 组件清单（§8.3）
  · 明确 storage-pipeline nuisance 组件清单（§8.4）

当前：❌ 未验证
原因：
  · 有 Reference Harness（合成），但【不是真实候选】
  · 真实候选的 STATE_FIELDS（§7.1）尚未在此架构上实例化
  · 无法回答"这条经历改变了哪个注册字段"
不可识别风险：若架构不做显式状态暴露，
             则 C1 也不可测 ⇒ 应记 ARCHITECTURALLY_NOT_IDENTIFIABLE
```

### P2 · 状态身份可计算且冻结

```text
要求：
  · STATE_FIELDS 与 META_FIELDS 分离（§7.1 / §7.2）
  · 各自有独立 digest（§7.3）
  · 状态身份算法在实验前冻结

当前：❌ 未验证
原因：
  · 设计层已有规则，但【未在真实候选上跑出任何一次 state digest】
  · 无基线 S_t，无从计算 S_{t+1}
```

### P3 · `ΔS_nonstorage` 可计算（§9）

```text
要求：
  · 能从 ΔS_total 中掩掉：
      - identity-only components（§8.1）
      - literal-storage components（§8.3）
      - storage-pipeline nuisance（§8.4）
  · 剩下的即 canonical ΔS_nonstorage

当前：❌ 未验证（**这是最关键的一项**）
原因：
  · 规则已定义，实现未实例化
  · 【这正是"影响 vs 偷看答案"的工程入口】
  · 若 ΔS_nonstorage 算不出来，
    则"模型输出变化"永远无法与"复读了字面内容"区分
```

### P4 · 独立观察者可读状态（§11）

```text
要求：
  · 观察者独立于被观察系统
  · 观察者读的是 registered storage，不是日志/审计流（§8.2）
  · 观察者本身不改变状态

当前：❌ 未验证
原因：
  · 无独立观察者实现
  · 且"观察者独立性"在当前单账号架构下难以论证
```

### P5 · 实验结构可归属（§15）

```text
要求：
  · 归因是一个【关系】，不是一个标量
  · 必须能回答"这个变化归因于哪次经历的哪个干预"
  · 若架构无法建立该关系 ⇒ 记 ARCHITECTURALLY_NOT_IDENTIFIABLE

当前：❌ 未验证
原因：
  · 未构造过任何一次带归属的实验
```

### P6 · 负控制与反证套件就位（§27 / §28.1）

```text
要求：
  · 七类假记忆反证进入设计：
      prompt/context 残留、KV/cache 残留、
      外部检索与重新注入、随机漂移、纯时间近因、
      输出貌似记得但无持久状态变化
  · 每条控制须能证明：
     在没有合法记忆形成路径时，测量系统
     【不能】把貌似记得的行为认证成真实记忆

当前：❌ 未验证
原因：
  · 套件设计在 prereg 中已定，实现未做
  · 无任何一次"负控制成功阻止误判"的实测
```

## 四 · 关于 Reference Harness 的严格限制

```text
⇒ 【允许用它做什么】：
   · 验证测量流程能跑通（管道测试）
   · 验证失败判据会触发
   · 验证负控制能否拦住合成假记忆

⇒ 【禁止用它做什么】：
   ✗ 用它的结果补填 P1～P6 的"已验证"
   ✗ 用它的 PASS 声称真实候选架构成立
   ✗ 用它的数据计算任何科学结论

⇒ 【理由】：合成环境里，"写入"是我们自己造的，
   ⇒ 它证明的是"我们能造一个可被测量的写入"，
   ⇒ 不是"这个架构会因经历而产生写入"。
```
