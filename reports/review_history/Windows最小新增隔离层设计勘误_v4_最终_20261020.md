# F-1 · B0 不能通过 `STARTF_USESTDHANDLES` 传递标准句柄

## 1.1 我在 v3 §2.2 写的（错误）

> **若选 B0，则标准句柄传递必须靠 `STARTUPINFO` 的 `STARTF_USESTDHANDLES`（独立于继承开关），而不是白名单。**

## 1.2 凌翼的指正（成立）

> `STARTF_USESTDHANDLES` 传递这些句柄时，句柄须**可继承**，并且 `bInheritHandles` 须为 **TRUE**。

**我读了官方文档措辞，确实如此。** 我把它当成"独立于继承开关的旁路"，**它不是**——它同样依赖句柄可继承 + `bInheritHandles=TRUE`。

## 1.3 勘误：B0 的能力边界

| 模式 | 继承参数 | 标准 IO 受控传递 | 说明 |
|---|---|---|---|
| **B0** | `bInheritHandles=FALSE` | **不可能** | 无继承 ⇒ 无标准句柄继承；`STARTF_USESTDHANDLES` 也不可用 |
| **B1** | `bInheritHandles=TRUE` + `HANDLE_LIST` | **可行** | 列表即白名单 |

**结论：若需要标准输入输出的受控继承，只能选 B1，或另行设计不依赖继承的通信方式。**

**删除 v3 §2.2 中"B0 可独立靠 `STARTF_USESTDHANDLES`"的整段表述。**

## 1.4 不依赖继承的替代（列为候选，未设计）

若必须使用 B0，标准 IO 只能走**非继承**路径。候选：

| 候选 | 说明 | 状态 |
|---|---|---|
| A-1 具名管道（`CreateNamedPipe` + worker 自行 `CreateFile`） | 需 DACL 允许 worker 打开 | **未设计** |
| A-2 文件重定向（worker 自开 stdin/stdout 文件） | 需路径与 DACL 规划 | **未设计** |
| A-3 共享内存 + 事件同步 | 需 DACL 与协议 | **未设计** |

**这些都不是"已成立机制"，只是候选。** 本轮不设计它们（凌翼要求"另行设计"，不在本次勘误范围）。

# F-2 · E-5 必须拆开：Q3 Reset 观察 ≠ RC11 验证

## 2.1 我 v3 §3.4 写的（错误）

把 E-5 写成单个事件「Reset 状态观察」，来源标为「冻结 Q3 `judge_reset` 语义」。

## 2.2 凌翼的指正（成立）

> 实际主流程顺序是：Q3 → 安装边界 → 启动 Worker → 持久隔离证据 → 恢复态快照 → RC11 验证 / 对象身份绑定 → Release → 执行
> 因此，冻结 Q3 的 Reset 观察与后续 RC11 验证**不能合并成同一个 E-5 事件**。

## 2.3 我核实的代码顺序（`run_reset_transaction`，L1061–1069）

```python
self._stage_q3()                        # L1061  Q3
self._stage_boundary()                  # L1062  durable boundary BEFORE business exec
self._stage_business_worker()           # L1063  worker starts but HOLDS
self._stage_persistent_isolation()      # L1064
self._stage_rc11_verify(handoff, restored)   # L1067
self._stage_bind(handoff, restored)     # L1068
self._stage_release()                   # L1069  ONLY after ALL prerequisite gates + ACK
```

**与我 v3 的 E-1..E-7 表不完全一致**：v3 漏了 `_stage_q3` 的位置，且把 `_stage_rc11_verify` 与 Reset 观察混为 E-5。

## 2.4 勘误：拆分为 E-5a / E-5b，并补 E-0

| # | 事件 | 代码阶段 | 时刻 | 观察主体 | 权限身份 | 证据来源 | 边界状态 |
|---|---|---|---|---|---|---|---|
| **E-0** | **冻结 Q3 角色执行** | `_stage_q3`（L1061） | $t_0$ | 冻结 Q3 的 probe 角色 | 按冻结 10 角色 | 冻结 Q3 自身的证据 | **未安装**（尚在 Q3 阶段） |
| E-1 | 边界安装 | `_stage_boundary`（L1062） | $t_1$ | 控制器 | 特权 | `deny_read_for_sid` + `save_dacl` | 正在安装 |
| E-2 | worker 启动（HOLD） | `_stage_business_worker`（L1063） | $t_2$ | 控制器 | 特权 | spawn 返回 + token SID + create_time | 已生效 |
| E-3 | worker 自我尝试读 | 由 `_stage_persistent_isolation`（L1064）驱动 | $t_3$ | **worker** | **受限** | worker 回报（nonce+pid 绑定） | 已生效 |
| E-4 | 控制器独立佐证 | 同上（L1064 内） | $t_3$ | **控制器** | 特权 | **句柄审计 + 目标身份绑定**（**非**控制器自读） | 已生效 |
| **E-5a** | **恢复态快照** | `_stage_rc11_verify` 入参准备（L1067 前） | $t_4$ | 冻结 Q3 的 `restored` 快照生成者 | 按冻结 Q3 | `StateSnapshot`（冻结 Q3 语义） | 已生效 |
| **E-5b** | **RC11 验证** | `_stage_rc11_verify`（L1067） | $t_5$ | RC11 验证链 | 按冻结 RC11 | RC11 证据链 | 已生效 |
| E-6 | 对象身份绑定 | `_stage_bind`（L1068） | $t_6$ | 控制器 | 特权 | canary≠protected 才放行 | 已生效 |
| E-7 | Release（worker 终止） | `_stage_release`（L1069） | $t_7$ | 控制器 | 特权 | worker exit 确认 | 已生效 → **待拆除** |
| E-8 | DACL 恢复 | `_cleanup` → `_rollback_boundary` | $t_8 > t_7$ | 控制器 | 特权 | 见 F-3 | **已拆除** |

**关键修正**：
- **E-0 是冻结 Q3 的独立阶段，不属于持久 worker 的证据链**
- **E-5a（恢复态快照）与 E-5b（RC11 验证）是两个独立事件**，前者供后者消费
- **E-7 从"worker exit 确认"改为 `_stage_release`**，DACL 恢复另立 **E-8**

# F-3 · DACL 恢复：命令成功 ≠ 相等性验证

## 3.1 我 v3 §3.4 写的（错误）

> | E-7 | DACL 恢复 | 控制器 | 特权 | `restore_dacl` + `verify_sd_equal` | 已拆除 |

## 3.2 凌翼的指正（成立）

> 当前适配器的 `_rollback_boundary()` 中，实际调用的是 `restore_dacl()`；而 `win32_isolation.py` 里的该函数依据 `icacls` 返回码判断恢复是否成功，**并不直接进行原始安全描述符的逐项相等验证**。

## 3.3 我核实的代码

**`_rollback_boundary()`（q3_reset_adapter.py L877 起）**：

```python
ok = restore_dacl(self._boundary_target(), self._boundary_saved)
...
self._audit["boundary_restored"] = bool(ok)
```

**只调 `restore_dacl`，没有 `verify_sd_equal`。**

**`restore_dacl()`（win32_isolation.py L268 起）**：

```python
r = subprocess.run(["icacls", str(p.parent), "/restore", str(save_file)], ...)
return r.returncode == 0
```

**判定依据是 `icacls` 返回码。**

## 3.4 勘误：三层必须分开表述

| 层 | 内容 | 现状 |
|---|---|---|
| **L-A 已有机制** | `icacls /restore` **命令成功**（返回码 0） | **已实现**（`restore_dacl`） |
| **L-B 额外要求** | 恢复后的 DACL **与保存的基线逐项一致** | `verify_sd_equal` **存在**（`q3_dacl.py`），但**该适配器路径未调用** |
| **L-C 尚未证明** | 实际执行了相等性验证，且**结果纳入接受条件** | **未实现** |

**E-8 的证据来源必须写成 `restore_dacl`（返回码），不得写 `+ verify_sd_equal`。**

**并把 L-C 列为独立审查要求**：

```text
DACL_RESTORE_EQUALITY_VERIFICATION = NOT IMPLEMENTED_IN_ADAPTER_PATH
REQUIRED_EVIDENCE = 恢复后 DACL 与基线逐项一致的验证，
                    且其结果进入接受条件（而非仅记录）
```

**这不要求现在改冻结代码**，只要求文档与实际机制一致。
