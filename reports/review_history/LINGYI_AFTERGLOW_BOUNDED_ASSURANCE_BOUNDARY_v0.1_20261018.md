## §1 · 总裁定：停止追求无边界的绝对安全

千年舟的 AfterGlow 项目，目标不是建造一个能够抵御所有攻击者、所有漏洞、所有未来技术的保险箱。

我们的目标是：

**在明确注册的系统、实验环境、威胁模型和执行区间内，控制可能影响科学归因的关键混杂因素，并以独立可复核的证据支持有限范围内的结论。**

本轮裁定确立三个原则：

**一、有界不等于随意降低标准。**

保证可以有限，但必须明示限制。对于足以伪造当前科学结论的已知信息通路，不能仅因难以控制就将其忽略。

**二、可信假设可以存在，但必须公开。**

可以假设受信任的内核、宿主管理员和独立实验控制器遵守其注册职责。不能同时把这些主体列为可信，又暗中赋予业务 worker 与它们等价的权限。

**三、实验验收不要求不存在任何漏洞，但必须能够支持所声明的结论。**

没有发现泄漏，不等于证明不存在泄漏。设计约束、独立证据、负向测试和失败收敛应共同支持保证。

## §2 · 第一版保证范围

本版仅针对 AfterGlow MVP 中已注册的实验系统及其测量协议。

**保护对象 P：**

包括当前 attempted claim 所依赖的受保护 substrate、未授权的先前 episode 状态、Reset 后不应继续可达的信息、未经注册的持久存储、缓存及其等效信息来源。

P 的实际成员、对象身份、权限与生命周期，必须在相关结果暴露之前进入固定清单。

**可信计算基础 TCB：**

可包括受信任操作系统内核、具有独立权限的实验控制器、受控的必要服务、状态观察者及证据记录系统。

每个可信主体必须有明确职责。凡能向 worker 提供受保护信息的组件，都不能被假装成无关的外部条件。

**当前威胁范围：**

覆盖意外句柄或文件描述符继承、worker 新获得禁止访问能力、旧状态残留、未经注册的 IPC/代理访问、对象替换与身份混淆，以及重置前后信息通路未断开的情况。

**明确不要求证明：**

任意恶意内核、受信任管理员蓄意破坏、物理攻击或所有未知未来攻击均不可能成功。

这些不属于 v0.1 的无条件防护目标。

但如果某个原本被视为可信的主体实际能够在实验期间造成未受控的信息回流，它就必须进入证据审查；不能仅用"它是可信的"消除已知风险。

## §3 · 直接访问与间接访问分开证明，但最终归因不能只看直接访问

正式采用以下可分离的设计评审维度：

```text
DIRECT_ACCESS_BOUNDARY
INDIRECT_INFORMATION_CHANNELS
TEMPORAL_BOUNDARY
OBJECT_AND_EVIDENCE_BINDING
FAILURE_CONTAINMENT
```

直接访问边界回答：worker 自身能否打开、读写受保护对象，以及已有资源、继承资源和新取得资源是否受限。

间接通道回答：worker 是否能通过父进程、服务、IPC、共享资源、外部检索或其他代理得到禁止信息。

**允许有通信，不等于允许无限制通信。**

每一条供实验使用的合法通道，应事前声明其端点、方向、数据类别、权限与证据记录方式。禁止信息不得沿未获准通路进入 worker。

如果直接访问已经有可信候选机制，但代理通路尚未论证，可记录局部进展；不得宣布端到端保证已建立。

因此保留当前结论：

```text
G2_DIRECT_BOUNDARY          = CANDIDATE IDENTIFIED
G2_INDIRECT_CHANNEL_CONTROL = NOT ESTABLISHED
G2_END_TO_END               = NOT ESTABLISHED
```

## §4 · 时间边界：有限，但不得任意缩短

**第一版不要求证明计算环境在无限未来始终安全。**

要求的是在每个 attempted claim 的实际因果依赖区间内，所需隔离前提持续有效。

该区间必须由可信事件定义：

- 起点：所有必要的隔离、对象绑定、输入通路与进程身份已建立，并且 worker 尚未接触相应受控信息的时点。
- 终点：与该 claim 相关的执行、结果捕获、Reset 后观测及必要的资源回收和证据封存已达到注册的终止条件。

如果一个持久 worker 在多个 episode 间保持运行，且前一 episode 的信息可能影响后一 episode，**不能为方便验收而把中间运行时间排除**。

必须持续维持相应边界，或者通过可信的终止、重建、重新绑定和独立验证，形成可解释的分段保证。

时间保证允许有明确期限，但不得留下未经处理、足以改变结果的时间空隙。

## §5 · 有界保证的最低验收条件

本裁定为新设计规定五项评审门。

| 门 | 必须建立的证据 |
|---|---|
| B-1 · 范围 | 保护对象、威胁、可信主体、合法通道、执行区间与 attempted claim 均已前瞻登记 |
| B-2 · 强制机制 | 有明确的 OS/架构约束，证明相关禁止能力不能仅靠 worker 自律来避免 |
| B-3 · 信息通路 | 涉及结果归因的直接与间接通路均有控制依据或可审查的独立前提 |
| B-4 · 失败收敛 | 关键约束不成立、证据缺失或资源回收未完成时，不输出合格保证 |
| B-5 · 独立验证 | 实现证据、负向对照、固定版本与独立复核相互支持，不由生产者自证完成 |

任何一项尚未建立，均不得声称完整保证通过。

这些是**候选隔离设计评审条件**，不是自动替换冻结 prereg 或 Q3 验收合同的新执行门禁。

## §6 · 精度与剩余风险

AfterGlow 不需要无限精度，但必须记录有限精度。

对实际科学测量，需要按预注册协议定义并验证判别阈值、等价区间、不确定区间、重复性、已知假阳性模式和适用范围。

对安全与隔离保证，不能用一次"没有发现泄漏"的采样结果制造一个无依据的泄漏概率。

剩余风险分成两类：

**可披露的非阻塞风险：** 在已声明可信前提及 attempted claim 范围内，有依据认为其不构成实质性归因混杂；仍须公开限制与理由。

**阻塞性的未控制风险：** 存在可信路径，使禁止信息可能进入本次测量，并足以伪造或改变所声称的结果，且没有足够控制依据。

第二类不能通过降低描述强度或修改 CLEAN 名称自动消失。

同样，受影响的 claim 可能 `INVALID` 或 `NOT ESTABLISHED`，不能直接记成科学上的 `FAIL`。具体分类服从冻结预注册协议。

## §7 · 按科学结论分级，不强求所有实验使用同一把最重的锁

不同科学结论应承担与自身相称的证据责任。

C1 的已注册存储写入，可以依据原预注册中 Basic L1/C1 的独立观察与失败见证规则进行评估；不应自动要求它先建立 C3 全部的非存储对照。

C2、C3 则必须控制足以伪造相应 ON/OFF 非存储对照与内容条件差异的信息通路。

L2 必须针对所声称的 post-reset class，验证 Reset 有效、证据重新建立以及前后身份绑定。

**高层级证据门禁不能倒灌为低层级的无条件阻塞；低层级 PASS 也不能为高层级作证。**

但本段仅定义设计评审原则，不授予任何当前科学运行权限。现行冻结协议与执行门禁仍然有效。

## §8 · Windows 与 Linux 的平台裁定

**第一版保证目标保持操作系统中立。**

Windows 与 Linux 可以采用不同机制实现相同的已注册安全目标，但它们的实现资格不得互相继承。

Windows Q3 十角色冻结及 RC11 继续保持原有权威。

允许进行一次**文档级、范围限定的 Linux 可行性分析**，仅回答：

L-1：Linux 是否有适合本目标的直接访问强制机制？

L-2：文件描述符、IPC、代理访问及跨 Reset 信息通路能否得到可论证的控制？

L-3：所需环境、可信计算基础、独立验证与维护成本是否合理？

本授权仅限一份设计分析及官方文档核对。**不授权新增代码、运行测试、创建业务 worker 或开展科学实验。**

若发现可行候选，须另行申请新实现血统及验证授权。

不得以平台迁移代替证据验收。

## §11 · 最终裁定

AfterGlow v0.1 的任务不是证明系统绝对不会泄漏信息。

它的任务是：

**在清楚说明保证能力、可信前提和测量误差的条件下，为经历引起的注册变化及其 Reset 后证据，提供足够可信的科学测量基础。**

我们不要求完美的保险箱。

我们要求一把知道自己量程、精度与失效条件的尺子。

**可以有边界。不能伪造边界之外的保证。**

**可以有未知。不能用 PASS 掩盖未知。**

**可以承认工程限制。不能用工程困难替代科学论证。**

本裁定至此明确，后续所有新设计评审依照上述边界开展；冻结协议的任何实质变更仍须走其自身适用程序。

*而尺子是为了测量世界，不是为了让千年舟永远停在造尺子的船坞。*
