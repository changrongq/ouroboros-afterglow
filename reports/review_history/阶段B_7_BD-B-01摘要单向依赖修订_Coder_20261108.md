## 零 · 缺陷确认

```text
⇒ 凌翼原文：
   「N5 的 `hwm_digest` 与 HWM 的 `last_commitment_digest`
    不能同时指向本次提交中对方的完整摘要。
    须改成可计算的单向依赖。

    例如：旧 HWM 摘要 → 新 N5 摘要 → 新 HWM 摘要。」

⇒ 【我原设计确实是这样互指的】：
   · B2-2 修订 4.1：N5 增补 `hwm_digest`（指向"引用该承诺时的高水位记录摘要"）
   · B2-2 修订 1.1 / 阶段B_3 1.1：HWM 有 `last_commitment_digest`（指向最后一次推进它的 N5）

   ⇒ 若两者在【同一次提交】中互相指向对方的完整摘要，
     则摘要计算变成：
       digest(N5)    = H( ... ‖ digest(HWM_new) ... )
       digest(HWM_new) = H( ... ‖ digest(N5) ... )
     ⇒ 【循环，不可计算】。
```

```text
⇒ 【我为什么没发现】：
   我写 `hwm_digest` 时想的是"引用当时的高水位"，
   而写 `last_commitment_digest` 时想的是"指向最近一条 N5"。
   ⇒ 两个字段各自看都合理，
     放进同一次提交就构成了环。
   ⇒ 这是【逐字段设计】而非【逐次提交设计】造成的。
```

## 一 · 修正：单向依赖 + 版本错位

### 1.1 核心思路

```text
⇒ 【关键是"错开一代"】：
   · 新 N5 只绑定【旧 HWM】的摘要
   · 新 HWM 绑定【新 N5】的摘要
   ⇒ 于是依赖方向严格单向，无环：

     旧 HWM ──摘要──▶ 新 N5 ──摘要──▶ 新 HWM

   ⇒ 新 N5 【不】引用新 HWM；
     新 HWM 【可以】引用新 N5。
```

### 1.2 修订后的字段

#### N5（0x86）字段变更

| 字段 | 原设计 | 修订后 |
|---|---|---|
| `hwm_digest` | 指向"本次提交时的高水位记录摘要" | **改名为 `prev_hwm_digest`**，明确指向【旧 HWM 记录】 |
| `prev_hwm_value` | 无 | **新增**：旧 HWM 的数值（用于交叉校验） |
| `target_hwm_value` | 无 | **新增**：本承诺所对应的目标高水位（= 本 N5 的 range_end_seq） |
| 其余字段 | 不变 | 不变 |

```text
⇒ 【为什么 `hwm_digest` 要改名为 `prev_hwm_digest`】：
   "hwm_digest" 里的 "hwm" 可以被读成新 HWM 或旧 HWM。
   ⇒ 名字有歧义，就会有人（包括我）读成新 HWM，从而再造出环。
   ⇒ 加上 `prev_` 前缀，把这个方向写死。

⇒ 【`target_hwm_value` 与 `range_end_seq` 是否重复？】
   ⇒ 数值上应当相等（承诺覆盖终点 = 目标高水位）。
   ⇒ 【但保留两个字段是为了让提交后能校验一致性】：
     若两者不等，说明计算或写入有缺陷。
   ⇒ 也可以只保留一个 —— 见第六节 Q1。
```

#### HWM（0x89）字段变更

| 字段 | 原设计 | 修订后 |
|---|---|---|
| `last_commitment_digest` | 指向最后一次推进它的 N5 | **保留**，但明确指向【本条 HWM 所对应的那条 N5 的完整摘要】 |
| `last_commitment_seq` | 该 N5 的 `commitment_seq` | 不变 |
| `hwm_epoch_counter` | HWM 推进次数 | 不变 |
| 其余字段 | 不变 | 不变 |

```text
⇒ 【为什么 HWM 可以引用新 N5，而 N5 不能引用新 HWM】：
   因为 N5 先于 HWM 被确定。
   ⇒ 计算顺序：
     ① 读旧 HWM → 得 prev_hwm_digest, prev_hwm_value
     ② 构造新 N5（含 prev_hwm_digest）→ 算 digest(N5_new)
     ③ 构造新 HWM（含 digest(N5_new)）→ 算 digest(HWM_new)
   ⇒ 全程无环，每步都只用已算出的值。
```

### 1.3 依赖图（修正后）

```text
⇒ 【同一次受信事务 T 内的依赖】：

   旧 HWM ──(prev_hwm_digest)──▶ 新 N5 ──(last_commitment_digest)──▶ 新 HWM
        │                                                                  
        └── 只读，不参与本事务写入 ├──────────────────────────────────────┘

   ⇒ 【旧 HWM 是只读输入】。它不被本事务修改（追加式设计）。
   ⇒ 【新 N5 不引用新 HWM】。这是打破环的唯一地方。

⇒ 【跨事务的链】：
   T1: 旧HWM₀ → N5₁ → HWM₁
   T2: 旧HWM₁ → N5₂ → HWM₂
   T3: 旧HWM₂ → N5₃ → HWM₃
   ⇒ 每个事务内单向，事务间也单向。
   ⇒ 【整条链是一棵有向无环图的特例：一条线】。
```

## 三 · 正反测试向量

> 说明：摘要值用占位符 `H(...)` 表示，

### 3.1 正向向量 TV-BD-B-01-OK

```text
【输入】
  authority_domain = "d0"
  generation       = 1

  旧 HWM（HWM₀）：
    hwm_value              = 100
    hwm_epoch_counter      = 0
    last_commitment_digest = 全零（初始）
    digest(HWM₀)           = H_hwm0

【构造步骤】
  ① prev_hwm_digest := H_hwm0
     prev_hwm_value  := 100
  ② 业务覆盖到 seq 150
     range_start_seq := 101
     range_end_seq   := 150
     target_hwm_value := 150
     head_digest      := D_150
  ③ digest(N5₁) = H( 0x86 ‖ VER ‖ 0x86 ‖ 0x00 ‖ 12 ‖ FIELDS ) = H_n5_1
  ④ 新 HWM（HWM₁）：
     hwm_value                := 150
     last_commitment_digest   := H_n5_1
     last_commitment_seq      := 1
     hwm_epoch_counter        := 1
     predecessor_hwm_digest   := H_hwm0
     digest(HWM₁)             = H_hwm1

【断言】
  A1: digest(N5₁) 的计算【不依赖】H_n5_1 之外的任何本事务产出  ✓
  A2: digest(HWM₁) 的计算【依赖】H_n5_1，方向单向  ✓
  A3: 无环  ✓
  A4: N5₁.range_end_seq == N5₁.target_hwm_value == HWM₁.hwm_value  ✓
  A5: HWM₁.last_commitment_digest == digest(N5₁)  ✓
  A6: HWM₁.predecessor_hwm_digest == digest(HWM₀)  ✓
```

### 3.2 反向向量 TV-BD-B-01-BAD-1 · 试图互指（应被拒绝）

```text
【构造】
  新 N5 的某字段被改成"指向新 HWM 的摘要"（即回到原缺陷）

【检测】
  A1 失败：digest(N5₁) 的计算需要 H_hwm1，
          而 H_hwm1 又需要 H_n5_1
  ⇒ 【计算无法完成】

【判定】
  ⇒ 这不是"能算出一个环"，而是"算不出来"。
  ⇒ 规范层面：【禁止】任何 N5 字段引用本条事务产出的 HWM 摘要。
  ⇒ 编码层面：N5 的 FIELD_COUNT=12，其中不含任何指向"新 HWM"的字段。
    ⇒ 【类型的字段集本身就排除了这种构造】。
```

### 3.3 反向向量 TV-BD-B-01-BAD-2 · prev_hwm_digest 指向不存在的 HWM

【输入】prev_hwm_digest = H_unknown（解析不到任何 HWM 记录）

## 六 · 待独立复核的问题

```text
⇒ (Q1) `target_hwm_value` 与 `range_end_seq` 数值必然相等，
   是否只保留一个？
   ⇒ 保留两个的好处是可校验（不等即缺陷）。
   ⇒ 保留一个的好处是消除冗余。
   ⇒ 我倾向保留两个，请裁定。

⇒ (Q2) 真实测试向量何时补？
   ⇒ 需要先定 FORMAT_VER 与 TAG 分配，并实现编码器。
   ⇒ 本轮无实现，故无法给真实 SHA-256 值。

⇒ (Q3) `commitment_result = CONTRADICTED` 的记录，
   其 `prev_hwm_digest` 指向哪个 HWM？
   ⇒ 若指向旧 HWM（因为 HWM 未推进），则与正常记录同形，
     只能靠 `commitment_result` 区分。
   ⇒ 但这与 BD-B-02 的修正有关（见另一文件）。

⇒ (Q4) HWM 的 `predecessor_hwm_digest` 首条全零，
   与"该字段缺失"如何区分？
   ⇒ 按 §2，全零是 32 字节的确定值，与字段缺失（LEN=0 或 FIELD_COUNT 少一）不同。
   ⇒ 但需确认写入方不得写"缺失"。
```
