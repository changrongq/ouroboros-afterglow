## 一 · 必须先定死的三个常量

```text
⇒ 知微的限定：「格式、长度、空集合/初始根等尚未确定时，
   不能用随意生成的字节冒充规范向量。」
⇒ 所以先定这三项。
```

### 1.1 FORMAT_VER

```text
⇒ 【沿用 §2】：`FORMAT_VER = 0x0001`（2 字节大端）。
   ⇒ §2 L78 原文：「FORMAT_VER 2 字节 大端，本节为 0x0001」
   ⇒ 【不新开版本】：本轮新增的对象类型是【同一格式下的新类型】，
     不是格式变更。
   ⇒ 【理由】：FORMAT_VER 描述的是【字节布局规则】，
     不是【对象类型集合】。新增 OBJECT_TYPE 不改布局。
   ⇒ 字节：`00 01`
```

### 1.2 TAG 分段分配

```text
⇒ 【§2 既有规则】：TAG 按对象类型分段（0x0x / 0x1x / ...）。
   ⇒ 目的：误用别的对象的 TAG 表时，解析【立刻失败】，
     而不是悄悄解析出错误结构。

⇒ 【本轮新增类型的 TAG 段分配（候选）】：
   | OBJECT_TYPE | 类型名 | TAG 段 | 说明 |
   |---|---|---|---|
   | 0x01 | ATTEMPT_REF | 0x01–0x0F | §2 已定 |
   | 0x02 | RECEIPT_REF | 0x11–0x1F | §2 已定 |
   | 0x03 | KEY_TRIPLE | 0x21–0x2F | §2 定（见下核对）|
   | 0x81 | IDENTITY_REGISTRATION | 0x31–0x3F | 候选 |
   | 0x82 | EPOCH_ASSIGNMENT | 0x41–0x4F | 候选 |
   | 0x83 | GRANT_RECORD | 0x51–0x5F | 候选 |
   | 0x84 | PREPARE_RECORD | 0x61–0x6F | 候选 |
   | 0x85 | CLOSURE_RECORD | 0x71–0x7F | 候选 |
   | 0x86 | HISTORY_COMMITMENT | 0x81–0x8F | 候选 |
   | 0x87 | REVOCATION_RECORD | 0x91–0x9F | 候选 |
   | 0x88 | MAX_SCOPE_SET | 0xA1–0xAF | 候选 |
   | 0x89 | TRUSTED_HWM | 0xB1–0xBF | 候选 |

   ⇒ 【为什么每段留 16 个 TAG】：本批对象最多 12 个字段（N5），
     16 足够且留扩展余量。
   ⇒ 【段号按对象类型递增】：可从 TAG 高 4 位反推所属对象。
     ⇒ 这是一个【可自检的冗余】，与 §2 的域分离精神一致。
```

```text
⇒ 【一个需要核对的地方】：§2 的 KEY_TRIPLE (0x03) TAG 段，
   我上面写 0x21–0x2F 是【推断】。
   ⇒ 实测见下。
```

### 1.3 空集合与初始根语义

```text
⇒ 这两项此前【完全未定义】，但手写向量必须用到。

⇒ 【空集合（MAX_SCOPE_SET 的 element_count = 0）】：
   · `element_count = 0x00000000`
   · `ELEMENTS` 部分【零字节】
   · `range_start_seq` 与 `range_end_seq`【都必须为 0】
     ⇒ 理由：空集合不存在"最小/最大 seq"，
       用 0 表示"无"比用 max 更不易被误读成"覆盖到最末"
   · 摘要仍按同一公式计算（对空元素串求 SHA-256）

⇒ 【初始根（首条 HWM 的 predecessor_hwm_digest）】：
   · 固定为 **32 字节全零**
   · 【不得】用"字段缺失"表示
   · 与"字段存在但值为全零"的区分靠 FIELD_COUNT：
     必须存在该字段，长度必须为 32
   ⇒ 【这解决了我 B2-2 修订 Q4 里提的问题】：
     "全零与缺失如何区分" → 靠 FIELD_COUNT 与 LEN，不靠值。
```

## 二 · 手写规范向量的计算方式（可复核）

```text
⇒ 【方法】：
   ① 按 §2 布局手写十六进制字节串
   ② 用【工具一】算 SHA-256
   ③ 用【工具二】独立复算
   ④ 两者一致 ⇒ 向量成立

⇒ 【工具一】：Python hashlib
⇒ 【工具二】：PowerShell Get-FileHash 或 certutil -hashfile
   ⇒ 两者都调用同一 OS 加密库，【不完全独立】。
   ⇒ 【更独立的核对】：人工按规范逐字节重数一遍长度与顺序。
   ⇒ 我在下面的向量里附【逐字段字节偏移表】，
     使人工核对可行。
```
