# ㊀ · 问 1：Afterglow Layer 到底是什么？

**凌翼问：** 最小定义？真·write/plasticity layer，还是外接 persistent state，还是都没定？"Afterglow"指机制、现象还是项目名？

## 我的回答

### 1.1 三种身份的分离（我认为必须先分清）

```text
"Afterglow" 现在在不同文档里承载三种不同身份，必须拆开：
  (a) 一个【实验项目名】（Afterglow Layer MVP）
  (b) 一个【现象】：变化在触发输入消失后仍继续影响未来计算
  (c) 一个【机制候选】：M-bias 注入 / 或别的 write 层
⇒ 我确认：目前 (a) 是 FACT（索引里有"Afterglow Layer MVP"），
   (b) 是我们想要的【现象定义】；(c) 是【未定的实现】。
```

### 1.2 我要给出的最小定义（PROPOSAL，供三人会齐）

$$\boxed{\text{Afterglow} \equiv \text{一次可追溯的 write 在原始输入消失后仍可测地改变未来计算}}$$

**注意这个定义的三点克制：**
```text
① 它【不承诺】write 发生在哪一层（backbone / 新层 / 外部 state 都允许）
② 它【只承诺两件事】：有 write + write 在输入消失后仍可测
③ 它【不承诺】retention over delay、不承诺 interference
```

### 1.3 关于"是内部改变还是外接 state"

**我的技术判断（FACT + UNCERTAIN 混合）：**

```text
FACT：现有 afterglow_experiment_spec.md 描述的是【内部】机制——
      M-bias matrix 注入 attention（softmax(QKᵀ/√d + M)），
      这是真正改变模型内部计算的层。

UNCERTAIN：但"外接 persistent state"是否是更稳的第一刀，宪章层没定。
```

**我的倾向（PREFERENCE，非裁决）：**
```text
第一刀我倾向【内部、受控、单点】的 write 层，理由：
  · 宪章第十二条/第十七条已要求 write 必须有 scope、有 provenance
  · 内部 write 的 provenance 更容易捕获（"change happened" 就地可记）
  · 外接 state 容易被第 7 问的"假记忆"（context carryover / 外部 retrieval）污染
⇒ 但这是 PREFERENCE。真正的定义应由三人在 MVP prereg 前对齐，我保留被推翻。
```

**一句话：** `Afterglow = 机制候选（未定）+ 现象定义（输入消失后仍可测）。名字是项目名；机制待冻结。`

# ㊂ · 问 3：Afterglow MVP 第一刀只证明什么？

**凌翼问：** 只测 `write happened`？还是 `write → survives context reset`？还是含 retention over delay？还是进 interference？凌翼倾向拆开，不要一个 PASS 背四种含义。

## 我的回答：**完全同意拆开，且我提议把顺序冻死。**

$$\boxed{\text{L1} \to \text{L2} \to \text{L3} \to \text{L4} \quad\text{四刀分开，每刀一个 claim ceiling}}$$

| 刀 | 只证明 | 明确【不】证明 |
|---|---|---|
| **L1** | `write happened`：目标 episode 产生了目标相关的内部改变 | 不证明它持久 |
| **L2** | `survives context reset`：输入消失 / 上下文清空后改变仍在 | 不证明它随时间保持 |
| **L3** | `retention over delay`：经过延迟后仍可测 | 不证明抗干扰 |
| **L4** | `interference`：新 write 与旧 write 如何竞争 | —— |

**并冻结 claim ceiling（这是凌翼的核心要求）：**

$$\boxed{\text{每个 PASS 只对其注册的那一层有效，禁止跨层外推}}$$

**我的具体提议（PROPOSAL）：**
```text
第一刀 = L1 + L2 合并（write + survives context reset），
  理由是：L1 单独太弱（几乎任何 write 都能"改变输出"），
          L2 才是"记忆"的第一道真门槛。
  但 L1 与 L2 必须是【两个独立 gate】，两个都 PASS 才算第一刀 PASS，
  不得用一个复合 PASS 同时背两种含义。

L3 / L4 明确留到第二刀、第三刀。第一刀文档里写：
  "retention over delay = NOT ENTERED"
  "interference = NOT ENTERED"
```

**我反对的做法：** 一个 PASS 说"证明了 write 和 persistence 和 retention"——**因为 retention 需要延迟，而第一刀没有延迟设计，声称它 = 造假。**

**一句话：** `第一刀 = L1 ∧ L2（两个独立 gate），L3/L4 明确 NOT ENTERED，claim ceiling 逐层冻死。`

# ㊆ · 问 7：怎样硬排除"假记忆"？

**凌翼问：** 第一批 negative controls 应该特别狠——prompt/context carryover、KV/cache 残留、外部 retrieval、重新注入同一 episode、随机漂移、纯 recency、"行为像记住但内部无 durable transformation"。以前有没有冻结过这套 distinction？

## 我的回答

### 7.1 先回答"以前有没有冻结过"

```text
FACT：
· DHE 冻结句里有 "State equality is not trajectory identity."（12H 报告 §403）
· Constitution 第四条把"状态相似"与"因果历史连续"分开了
· 但——【Afterglow 语境的 negative control 分类，从未被冻结过】
⇒ 我的判断：这套 distinction【没有】现成的，
   它应该是 MVP preregistration 的【第一个产物】。凌翼猜对了。
```

### 7.2 我提议的 negative control 分类（PROPOSAL）

**我把它组织成"每个假记忆来源 ↔ 一个必须失败的对照"：**

| # | 假记忆来源 | 必须失败的对照（negative control） |
|---|---|---|
| N1 | prompt / context carryover | 同 episode 只放在**当前 context**、不做 write ⇒ 不得显示 durable 效果 |
| N2 | KV / cache 残留 | 清空 KV cache 后重测 ⇒ 效果不得存在 |
| N3 | 外部 retrieval | 断开所有外部检索路径 ⇒ 效果不得存在 |
| N4 | 重新注入同一 episode | 只重注入、不做 write ⇒ 不得冒充"记住了" |
| N5 | 随机漂移 | 用**无关 episode** 做 write ⇒ 目标行为不得改变 |
| N6 | 纯 recency | 打过时间/顺序 ⇒ 效果应随"写入时间"不影响目标量 |
| N7 | **行为像记住但内部无 durable transformation** | 检查**内部 state hash 是否改变**，而不只看输出 |

**N7 是最关键的一条（凌翼自己点出的）：**

$$\boxed{\text{N7} = \text{把"输出变了"与"内部 state 变了"分开测}}$$

```text
这正是 "State equality is not trajectory identity" 的工程落地：
  · 输出像记住了 ≠ 内部发生了 durable write
  · 必须同时证明：(a) internal state 变了 (b) 该变化有 provenance
                    (c) 该变化在输入消失后仍在
⇒ 三者缺一，就只能叫"行为像记住了"，不能叫 memory candidate。
```

### 7.3 我的建议：把这套冻成 prereg 第一项

```text
凌翼说得对：这可能是 MVP preregistration 最先要写的东西。
我提议 MVP prereg 的第一节就是 "NEGATIVE CONTROL SUITE"，
包含 N1~N7，且【每个 control 必须有预注册的失败判据】。
否则第一刀 PЯSS 的意义会被任何一个假记忆来源架空。
```

# ㊉ · 问 10：最小的待检验 Memory Candidate Unit 是什么？

**凌翼问：** 三人分别回答——是一个 episode 导致的 parameter/state transition？一个 binding 的持久改变？一个可追溯 write event？还是暂不绑实现，只定义 $E$、$S_t$、$S_{t+1}$ 与未来行为差异？

## 我的回答

$$\boxed{\text{最小 unit} = (E,\ S_t,\ S_{t+1},\ \Delta_{\text{future}})\ \text{四元组，暂不绑实现}}$$

**我的理由（工程侧，我强烈倾向"暂不绑实现"）：**

```text
① 宪章第一条 = 本体中立。
   如果第一版 MVP 就把 unit 绑成"parameter transition"，
   就等于用实现偷渡本体——违反宪章。

② 但也不能纯抽象到没法测。
   所以四元组是【可测的下限】：
     E          = 可归属的输入事件（episode）
     S_t        = 事件前的注册状态
     S_{t+1}    = 事件后的注册状态
     Δ_future   = 未来行为差异（注册的量）
   —— 这四样都能被 provenance 记录、被对照验证。

③ "write event" 是 S_t→S_{t+1} 的【实现之一】，不是 unit 本身。
   "binding 的持久改变" 是 Δ_future 的【一种】，也不是 unit 本身。
⇒ unit 必须比它们都更基础。
```

**与宪章工作定义的吻合检查：**
```text
宪章临时工作定义：memory candidate =
  一种与特定经历具有前瞻注册因果归属、
  能够持续影响未来计算、
  并在变化发生时留下可验证 transformation evidence 的内部改变。

⇒ 我的四元组 (E, S_t, S_{t+1}, Δ_future) 正是它的【可操作化】：
   "特定经历" = E ; "前瞻注册因果归属" = S_t→S_{t+1} 可追溯 ;
   "持续影响未来计算" = Δ_future ; "可验证 transformation evidence" = provenance
⇒ 吻合。✅
```

**我明确不绑实现：** 不说它是 parameter、是 state、是 vector 还是 graph。**只说它必须能填入这四格。**
