## 一 · 拆计数器（您要的第一件事）

### 改在哪

`afterglow_harness/q3_business_handle_audit_v2.py` —— **未冻结的集成子模块**，不是本文档夹带私货的冻结件。

### 拆成什么

```text
unresolved_operational   操作失败（OpenProcess 权限不足 / DuplicateHandle 失败 / 枚举错误）
                         ⇒ 环境问题，可修
unresolved_no_identity   操作成功，但对象没有可读的文件身份
                         ⇒ 本体问题，修不好（\Device\ConDrv / KsecDD / CNG 一类）
```

`unresolved` 保留为**两者之和**，所以旧读者看到的总数不变——我改的是分母的**构成**，没有偷偷改总数去凑好看。

每个 `V2HandleRecord` 也多了 `unresolved_kind ∈ {"", "operational", "no_identity"}`，逐句柄可追。

### 您那句判据，我照原样落进代码

> 若前者为 0 而后者 > 0 ⇒ 那不是"再修一次就能过"，那是"这个结论在此对象上不成立"。

`res.detail` 现在会直接写出来：

```text
N relevant handle(s) could not be reliably classified (fail-closed):
  unresolved_operational=<a> (operation refused/by permissions),
  unresolved_no_identity=<b> (object carries no readable file identity)
; CAUSE_IS_ONTOLOGICAL: operation succeeded on every relevant handle,
  so granting further privilege cannot move this to CLEAN —
  the conclusion does not hold on this object
```

后半句**只在 `a == 0 ∧ b > 0` 时出现**。这样等真的有人把权限给足了，那行字会替我们回答"为什么数字还是不到 0"，而不是让人再去猜方向。您担心的那条误导路径，现在在代码里被堵住了。

### 有一处判分需要向您交代（我不自裁，只报）

有一条已有的 unresolved 分支，我把它归到 `no_identity`：

```text
handle identity via {api} but target has no {api} identity to compare
```

理由：句柄身份**已经读到了**，失败点在于没有同 API 的目标身份可比。它不是"操作失败"，加权限不会让它消失。所以我按"本体"记。**若您认为它应当是第三个桶或归 operational，请裁定，我改。**
