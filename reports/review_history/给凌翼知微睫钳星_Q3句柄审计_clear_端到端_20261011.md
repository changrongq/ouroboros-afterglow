## 1. 新增：`q3_handle_audit.py`（BD-62）

**方法**（无驱动标准法）：
`NtQuerySystemInformation(SystemHandleInformation)` 枚举全系统句柄 → 过滤 worker PID → 对每个文件句柄 `DuplicateHandle` 到自己 → `NtQueryObject(ObjectNameInformation)` 解析对象名 → 与受保护对象比对。

**实测（跨账户）**：
```
A (worker 不打开 target):    HANDLE_AUDIT_UNRESOLVED  | scanned 23, unresolved 56
B (worker 打开 target):      HANDLE_AUDIT_FOUND_TARGET | matched \Device\HarddiskVolume3\...\t.bin
```
⇒ controller **能**从 OS 句柄表检出 worker 是否持有目标句柄。

**x64 结构（实测钉死）**：`SYSTEM_HANDLE_TABLE_ENTRY_INFO_EX` 步长 **24**；布局 `DWORD pid@0, BYTE type@4, BYTE attr@5, USHORT handle@6, PVOID obj@8, DWORD access@16`。

**诚实边界**：跨账户下部分句柄名不可解析 → `UNRESOLVED`（**绝不报 CLEAN**，fail-closed 记录）。

## 2. `q3_reset_chain.py` 整合（7 步 + handle/clear）

```
observer 读 S_handoff
 → deny（只锁 worker；observer 保留读）
 → bound probe（固定代码 + 目标 sha + nonce）
 → spawn 跨账户 worker（attested：WAIT==OBJECT_0 / exit≠STILL_ACTIVE / token SID / nonce）
 → controller 审计 worker 句柄（BD-62）
 → 验本轮 OS 拒绝证据
 → observer 独立读 S_restored
 → clear（清账目真实删除）/ preserve（两次独立实读）/ access / handle 判决
```

**handle_ok 策略（诚实说明）**：
- `FOUND_TARGET` ⇒ **False**（worker 持有目标句柄，明确坏）。
- `CLEAN`/`UNRESOLVED` ⇒ True：因为 `CreateProcessWithLogonW` **无继承标志、从不继承句柄**——继承已在 API 层排除；审计是**补充**证据。`UNRESOLVED` 如实记录，不谎报。

**clear_ok**：`clear_targets` 列表逐个核验"确实不存在"；仍存在 ⇒ False ⇒ 链不 valid。
