### 无凭据对照

知微移除子进程环境中的凭据后，worker、reset chain、FULL_VALID 均标为 SKIP；旧 DACL 项仍 FAIL，所以总入口实际返回 **FAIL / exit 1**。

这符合当前“FAIL 优先于 SKIP”的聚合规则。文档应将预期准确写成：没有其他失败且存在 SKIP 时，才是 NOT_EVALUATED / exit 2；不能笼统承诺无凭据一定 exit 2。本轮没有把 SKIP 计作 PASS，也没有实测到“无凭据且其他项全过”的 exit 2 路径。

## 四、DACL 失败的正式澄清

唯一失败项：

```text
[FAIL] DACL: exact restore via saved SDDL verified
win32_isolation selftest (V2): 20/21 PASS
```

对独立 canary 调用原版保存、修改、恢复函数，实际 `icacls /restore` 返回：

```text
exit_code = 1300
Not all privileges or groups referenced are assigned to the caller.
```

知微实际进程取证：

```text
TokenElevationType = 3  (TokenElevationTypeLimited)
TokenElevation = 0
Administrators = deny-only
Integrity level = Medium
SeRestorePrivilege = absent from privilege list
```

荣弦随后确认：“我是以管理员权限运行的 PowerShell。”同一机器、相同登录账户可以创建不同权限令牌的进程；现有权限取证和错误码与这一区别吻合。默认临时目录也复现同一失败，排除了“仅因审阅 scratch 位置不同”的解释。

**修正归类：** 此项记为“知微未提升运行上下文不满足旧恢复路径的权限前提”，不凭此认定恢复算法错误。保留荣弦管理员环境 PASS 和知微未提升环境 FAIL 的各自原始记录，不把其中一份改写为另一份。

当前会话配置关闭了文件系统沙盒限制，但这不会自动赋予进程 Windows 管理员权限。现有证据支持权限上下文差异，尚不支持把原因进一步指定为 Codex 额外沙盒策略。知微没有实施管理员/非管理员的完整受控交叉实验，报告不声称已直接证明某一单独特权是唯一因果因素。

建议补充复跑前提：说明当前旧恢复路径所需的管理员/特权环境，并在入口报告相关前置条件是否满足。若决定将前提不满足归为 NOT_EVALUATED，应在合同及 driver 中明确该分类，不回改本轮已有 exit 1 日志。真实的恢复/回读不一致仍应与环境缺权限分开处理。

### 影响与边界

消费端目前不能兑现“独立确认本轮完整成功路径”的职责，可能接受缺失、错误类型或不属于当前运行的证据。

这不证明本次真实 84/84 是伪造，也不证明任意组件 FAIL/SKIP 都能导致整个 driver PASS；组件退出码和聚合门禁仍在。旧产物被接受的测试证明缺乏新鲜度绑定，没有模拟完整重放攻击。上述范围应随报告保留。

### 建议的闭合条件

1. 固定产物 schema：顶层、gates 类型正确；由合同/schema 给出八个必需 gate，全部存在且每项严格 `is True`。空集、缺项、字符串和数值冒充布尔必须拒绝。
2. 验证 profile：与本轮事前选定的 profile、版本及其必需证据一致。Profile B 的必需证明不能只靠打印 profile 名称。
3. 绑定本轮：driver 生成 run ID/nonce 并传给执行端，消费时核对同一本轮标识及规定的执行对象身份。用每轮独立产物路径，或先隔离旧产物；只看文件存在或修改时间不足以替代身份绑定。
4. 对异常 JSON、错误字段类型和缺少产物给出明确 FAIL/NOT_EVALUATED 结果及原因，不让未处理异常或弱类型真值成为隐式裁决。

建议负向回归至少覆盖：missing/empty gates、逐项缺失、False/None/"UNEVALUATED"/1、错误 profile、Profile B 必需证据失败、旧 nonce、错误对象绑定，以及当前轮没有生成新产物。

修复后保留一个本轮真实完整成功的正向对照，同时确保以上缺陷被拒绝。本项为本轮冻结前保留的代码待修项。
