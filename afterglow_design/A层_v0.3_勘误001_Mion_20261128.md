## 一 · 勘误条目（6 条）

### E-1 · §2.1 的 A3 PASS 行仍带旧条件 —— 删除

```text
v0.3 §2.1 现文：
  A3  PASS  source_ref 非空，且能打开，且【指向本条记录所涉事件】

而 §2.3 已经把口径定死为窄口径（只签"能打开"）。

⇒ §2.1 那半句是整个 v0.3 里最后一处未清干净的旧条件。
```

**改为：**

```text
A3  PASS  source_ref 非空，且能打开
    （事件匹配 = NOT_COVERED，见 §2.3）
```

**知微的判据（我采纳为理由）：**

> 仅收窄报告措辞无法消除程序入口的额外条件。

```text
⇒ 也就是说：如果 §2.1 里还留着"指向所涉事件"，
   Coder 按 §2.1 写代码，A3 就会多一个入口条件；
   那时 §2.3 的窄口径就只是一句注释。
```

**这是本轮我要记住的一条：改了 §2.3，不等于改了 §2.1。**
**而这是第四次同类（A2 → A3 → B3 → 这次的 §2.1 残留）。**

### E-2 · PRE-REG-1 的措辞退回「看结果之前」

```text
v0.2 写的是： 「在宣称之前……必须固定并写下」
              —— 我 v0.3 写成了「宣称之前」

⇒ 单读 v0.3 的「宣称之前」，会允许：
    先看结果 → 后登记 → 再宣称
⇒ 那正是 PRE-REG-1 要防的那件事。
```

**改为：**

```text
PRE-REG-1  在【看结果之前】必须固定并写下三样：
             ① 记录版本（commit / blob sha）
             ② 准入规则版本（本文档版本）
             ③ 干预对象
```

**并保留 v0.3 已写的旁证限定：**

```text
git 提交时间戳只能作登记旁证，不单独证明作者在看到结果前写下它。
⇒ 它不能独立见证"首次看见结果的时点"。
```

### E-3 · `delta = null` 的硬约束（新增，回应 Coder 的边界输入之一）

**Coder 的构造：干预确实送达、正对照通过，随后目标一臂的读出丢失。**

```text
风险：让 null 落进 "delta != 0" 的分支 ⇒ 被当成"有差异"。
```

**三条硬约束：**

```text
D-1  delta = null  当且仅当  readout_valid = false
D-2  null 【不参与】任何数值比较：不得用于 ==0、!=0、>0、<0
D-3  判定顺序里 readout_valid 在 delta 之前（v0.3 §3.3 第 2 步已在 delta 之前，此处补明）
     若某实现把 null 当数值比较，视为实现错误，不是判据模糊
```

```text
⇒ 缺测一律走 INDETERMINATE，且 B3-OBS 保留 delta = null，
   不许把"缺测"填成 0，也不许填成"非零"。
```

---

### E-4 · 「对照跑过」不等于「排除成功」（新增，回应 Coder 的边界输入之二）

**Coder 的构造：两臂有非零差值，而空跑也重现相同漂移。**

```text
v0.3 §3.2 写：「delta != 0 且排除已做 ⇒ B4=ESTABLISHED」
⇒ 若「排除已做」被编码成"跑过对照"，那这个构造会走到 ESTABLISHED。
⇒ 而它其实是：对照检出了足以解释差值的漂移 ⇒ 未排除。
```

**新增判据 EXCLUDED：**

```text
EXCLUDED = TRUE  当且仅当：
          · 已登记的替代解释清单【逐条】被有效排除，且
          · 空跑对照未重现差值，且
          · 正对照有效（第 2 步通过）

若对照检出了足以解释差值的漂移          ⇒ EXCLUDED = FALSE
若替代解释清单里有任何一条未被排除        ⇒ EXCLUDED = FALSE
若正对照失灵                            ⇒ 先进入 INDETERMINATE 出口（第 2 步）
```

```text
⇒ B3-OBS 保留非零差值；B4 = INDETERMINATE，并列出未排除项。
⇒ 请勿把"对照跑过"直接编码为"排除成功"。
```

### E-5 · 自查计数不一致 —— 正数为 (a) 10 / (b) 7

```text
       MECH 通路受控 / CROSS-1..5 / 载体下游 / PRE-REG 时序        = 7

而 v0.3 §十一 写的是 13 / 8。
```

**改正为：**


```text
⇒ 知微数得对。我 §十一 的数字是凭印象写的，没有回去数一遍 §八。
⇒ 这跟"改了 §2.3 没改 §2.1"是同一类：**改动后没有回头核对自己的归档数字。**
```
