## 一 · E-18：`EXCLUDED` 空清单 ⇒ `INDETERMINATE`（我上一版判错了）

**我上一版（`6b4e3e5`）的实现：**

```text
alternative_terms 为空 ⇒ EXCLUDED = True，reason = NO_ALTERNATIVES_REGISTERED
```

**我当时的自我说明是：**

> 「我选了 True，并把 reason 单独设成 NO_ALTERNATIVES_REGISTERED，
> 让报告能区分这两种情形。」

⇒ **这个「区分」没有用。** reason 是给人看的字符串；
`EXCLUDED=True` 是给下游读的值。下游只看 True，不看 reason。
⇒ 我用一个「报告里能看见」的字段，替代了「返回值里该有的状态」。
   这跟 C-2 那条是同一件事：L4（报告）有的东西，L1（返回值）没有。

### 现在的实现

```text
E-18-1  清单为空 ⇒ EXCLUDED = None，INDETERMINATE = True
        reason = NO_ALTERNATIVES_REGISTERED
E-18-2  新增哨兵常量 NONE_KNOWN；确实没有替代解释时必须显式登记
        并显式排除，才可达 TRUE
E-18-3  空列表永远不产生 TRUE —— T-7 用 `is not True` 断言了这一条
```

⚠ **一处我做了判断、要请你确认的实现细节：**

```text
三态在返回字典里怎么放？

我选了：EXCLUDED 本身取 True / False / None，另设 INDETERMINATE: bool。

理由：如果只把 EXCLUDED 做成字符串三态（"TRUE"/"FALSE"/"INDETERMINATE"），
下游所有 `if excluded:` 都会把 "INDETERMINATE" 当成真值 —— 反而更危险。
如果只把 EXCLUDED 设成 False 并附 INDETERMINATE=True，
那「判不出」和「判为假」在 EXCLUDED 这一格里仍然不可区分。

⇒ 所以：EXCLUDED = None 表示判不出；INDETERMINATE = True 是显式标记。
   两个字段都要看。这写进了 docstring，也写进了 CLAUSE_MAP["E-18-1"]。
⇒ 但这是我的接口选择，你的条款只规定了「必须能表达判不出」，没说用哪种形状。
   若不认可，我改。
```

        返回 detected_reachable（bool）

E-19-3  describe() 里 mech_detected_assertion 指向 T-8 的函数名
        （不再是只有一句说明文字）

**本阶段 4 个调用入口，全部收敛到 INDETERMINATE：**

```text

2. 无差值 + 通路未受控
3. 有差值 + 漂移可解释
4. 有差值 + 读出无分辨力
```

⚠ **一处必须说清的边界（我写进了 `NOT_CHECKED`）：**

```text
「本阶段任何调用路径都不产生 DETECTED」这句话，
在数学上不能靠枚举全部参数组合来证（那是无限的）。

我只能枚举【本阶段实际存在的调用入口】—— 即 STAGE_CALL_SITES 那 4 条。
⇒ 若将来新增一个调用点而没有登记进这张表，
   不可达性断言就不再覆盖它。
⇒ 这是本表的已知边界，不是完整证明。
```

⇒ **所以准确的说法是：「本阶段已登记的 4 个调用入口都不产生 DETECTED」**，
  不是「任何调用路径都不产生 DETECTED」。
  你条款原文写的是后者。我按能力做到前者，并把它写在 NOT_CHECKED 里，
  不把前者说成后者。
