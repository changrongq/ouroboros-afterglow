## 一 · Q1：是【按模式】，不是逐文件 —— 你说对了，我改了

**你问：**

> 请回一句：是逐文件，还是按模式？

**答：按模式。原话是这一行：**

```python
if rel.startswith("afterglow_a/prototype/test_"):
    continue
```

**⇒ 这正是你说的那个形态：**

```text
新增一个测试文件会自动被放行，而没人看过它。
⇒ 那是「未登记」的另一种形态，与 E-22-3「已登记 4 个 ≠ 只有 4 个」同源。
```

### 改动

```text
新增 TEST_FILE_EXEMPTIONS：逐文件名 + 理由
  afterglow_a/prototype/test_blayer_batch1.py
    「用登记入口的行为做断言，不是新增生产调用点」
⇒ 放行条件从 `rel.startswith(...)` 改成 `rel in test_exempt_paths`
```

### T-11 新增 ⑥ 三条断言

```text
⑥ a) 每条豁免不得含通配符（"*" not in p）
      理由：通配符 = 按模式 = 回到原缺陷
⑥ b) 每条豁免必须【实际被扫描命中】（防过期豁免，与 ④ 同理）
⑥ c) 存在 test_ 文件调用点但不在豁免表里 ⇒ 红
      理由：这条直接模拟「新增一个未登记的测试文件」——
            若放行是按模式做的，它会被错误放过。
```

### ⚠ ⑥ b 立刻抓到了我自己的一条过期豁免

```text
我第一版豁免表放了两条：
  1. test_blayer_batch1.py
  2. test_blayer_batch1_mutation.py   ← 这条是过期的

理由（我当时写的）：「变异脚本 monkeypatch 实现以验证测试分辨力」

⇒ 但 ⑥b 报：该文件【从未被扫描命中】。
⇒ 我去核了：变异脚本确实从不写 `judge_mechanism(` 字面调用 ——
   它是用 setattr 替换函数对象（LB.judge_mechanism = bad）。
⇒ 扫描器只看 ast.Call，替换函数对象不是 Call ⇒ 扫不到。
⇒ 那条豁免不起任何作用，却让读的人以为「这里有个需要豁免的调用点」。
⇒ 已删除。
```

**这是同一族错的第三个形态：**

```text
形状一：改了消费端，产出端没改（E-21-2）
形状二：推测扫描器会扫到 def 行，没核对（上一轮 错误 B）
形状三：凭「这个文件应该会被扫到」写豁免，没核对它到底有没有被扫到
⇒ 三次都是【写的时候在推测，没去核】。
⇒ 而三次都是【断言抓到的，不是自查抓到的】。
```


