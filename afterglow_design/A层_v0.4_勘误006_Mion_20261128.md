## 一 · E-24 · `EXCLUDED` 的三字段编码进 A 层

**Coder 新增 `excluded_undetermined: bool`，用于区分两种"判不出"。本件把它写进 A 层。**

```text
E-24-1  EXCLUDED 的形状定为：
          excluded               : True | False | None
          excluded_undetermined  : bool
          reason                 : string

E-24-2  三者关系是不变量，必须【三者同时】成立或不成立：
          excluded is None
            ⇔  excluded_undetermined is True
            ⇔  reason ∈ { NO_ALTERNATIVES_REGISTERED, PATHWAY_NOT_CONTROLLED, ... }
        不得两两成立而第三项不成立。

E-24-3  两种"判不出"在报告里必须分开措辞：
          没登记      ⇒ 「该夹具未登记任何替代解释，因此无法判定是否已排除」
          没排干净    ⇒ 「已登记的解释中尚有 N 条未排除」
        ⇒ 二者 B4 同为 INDETERMINATE，但合并措辞会让"我们没想到"
          与"我们想到了但没排掉"变成同一句话。
```

**并登记一条设计层面的警告：**

```text
E-24-4  THREE_FIELD_ENCODING = ACCEPTED_FOR_NOW, WATCHED
        ⇒ 三个字段表达【一件事】（判不出）。
        ⇒ 本阶段接受，因为两种"判不出"确实需要分开。
        ⇒ 但若将来再出现第四个字段表达同一件事，
          说明形状该换了，不得继续加字段。
```

```text
理由：这是"一个字段别装两层事实"的反面——
      两层事实确实需要一个以上的字段，但每加一个，
      "三个字段互相不一致"的可能性就多一种。
      ⇒ 所以接受，但设上限并登记。
```

## 二 · E-25 · `STAGE_CALL_SITES` 的覆盖必须从纪律变机制

**Coder 的 E-22-3 (b) 给了「漏的怎么被发现」两半：**

```text
① 任何 importer 新增 judge_mechanism 调用点时，
   代码评审必须同时改 STAGE_CALL_SITES
② pathway=True 抛异常兜住
```

```text
⇒ ② 是机制。① 是纪律。
⇒ 而他自己在 §二 写过：「现在『这么调就炸』。纪律变成了机制。」
   ⇒ 那句话对 ② 成立，对 ① 不成立。
```

**所以：**

```text
E-25-1  必须用 AST 扫描全仓 `judge_mechanism(` 的调用点，
        与 STAGE_CALL_SITES 逐项比对。
        不相等 ⇒ 测试红。
E-25-2  若某调用点确实不在清单内且【不应】在清单内，
        必须在测试里显式豁免并写明理由（不得静默忽略）。
```

```text
⇒ 这是他自己已经会写的技术：E-21-2 已经改用 AST。
⇒ 所以这条不是新能力要求，是把同一个手段用在覆盖上。
⇒ 做到之后，① 那半从"代码评审必须"变成"多一个就红"。
```

## 三 · E-26 · `E-21-2` 的 AST 手段认可，别名形态登记为 `NOT_CHECKED`

```text
E-26-1  认可 AST 作为 E-21-2 的实现手段（取代源码 grep）。
        理由：grep 命中的是【文本】，AST 命中是【语法节点】。
        而文本与代码的差别，正好是注释。

E-26-2  登记未覆盖形态：
          NOT_CHECKED-E21 = 别名化消费
          例：x = excluded; if x:
        ⇒ AST 不做数据流，此形态查不到。
        ⇒ 本阶段不要求数据流分析。
```

**但要求一条补充（本件新增）：**

```text
E-26-3  因为别名形态查不到，消费方【必须同时读两个字段】这一点
        不能只靠"下游会看到结构"。
        ⇒ 本层必须【没有】别名化消费（AST 可查本层）
        ⇒ 下游的别名化消费：NOT_VERIFIABLE_IN_THIS_STAGE（C-2 的 L3）
        ⇒ 报告不得写成「已防止误用」，只许写成「本层不误用，且下游
          若只读 value 则拿不到 flag」。
```
