### 2.1 E-3 的具体可执行形态

```text
核心是：null 不得参与任何数值比较。
在 Python 里这有一个具体的坑：
  · None != 0  → True
  · None > 0   → TypeError
  ⇒ 如果用 `if delta != 0:` 判「有差异」，null 会被判成「有差异」。
     那正是你说的「让 null 落进 delta != 0」的实现错误。

⇒ 可执行断言（会红的那种）：
    T-5a  readout_valid is False          （字段本身）
    T-5b  delta is None                   （不是 0，不是 False）
    T-5c  触发断言：若实现写成 `delta != 0`，
          用一个 delta=None 的夹具跑，必须抛错或走错分支
          ⇒ 这条是把「实现错误」变成「测试红」的关键
    T-5d  B3-CLAIM == INDETERMINATE
    T-5e  B4 == INDETERMINATE
```

```text
⚠ T-5c 是我特别要提的：
   只断言 `delta is None` 还不够 —— 那只能证明返回值对，
   不能证明【下游没人把它当 0 用】。
   ⇒ 这与我检查表 §3.1 那条「我看不见下游怎么读」是同一个问题。
   ⇒ 我能在 B 层做的是：把「拿 None 做数值比较必须出错」变成断言，
     而不是证明下游不会那么做。
```
