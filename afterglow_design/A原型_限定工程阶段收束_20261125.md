## 一 · 这一份文件是什么

这是 A 原型的**阶段收口**，不是成果宣告。

```text
它回答三个问题：
  1. 做完了什么（工程验收范围）
```

## 二 · 事项 A：工程级限定验收

```text
RECOVERY_GATE_IMPLEMENTED = VERIFIED_ENGINEERING_SYNTHETIC
```

**含义严格限定为：**

```text
合成测试范围内，门禁实现、已定义拒绝条件、已执行变异验证
达到当前工程验收要求。
```

**必须同时登记（凌翼要求，逐项列出）：**

```text
RECOVERY_GATE_EVIDENCE        = SELF_TEST_REPORTED
INDEPENDENT_RECOMPUTATION     = NOT_ESTABLISHED
REAL_HISTORY_VALIDATION       = NOT_PERFORMED
EXTERNAL_SOURCE_ATTESTATION   = NOT_ESTABLISHED
ZA01_VERIFIED_READ_BINDING    = OPEN
```

### 为什么这五项是分开的

```text
如果只写一句「门禁已验证」，读者会以为上面五项都建立了。
⇒ 一个状态词携带五种含义，就是五处可能被误读的地方。
⇒ 逐项列出，每一项都回答「缺的是哪一类证据」。
```

### 三条已知边界（凌翼点名要求纳入）

**① 未提交登记身份的兼容路径，不具备独立登记证明**

```text
check_registration(reg=None) 返回 present=False / independent=False。
门禁会因此判 registration 不合格 —— 这是对的。
但代码里还有一条兼容路径：调用方可以不传 registration。
⇒ 那种情况下「没有拒赔」不等于「已登记」。
⇒ 任何把「未报错」读成「已登记」的做法都是错的。
```

**② `recovery_eligible` 不等于 `match_kind=exact`**

```text
eligible 是【门禁通过】：集合关系有定义、完整性已检查、
            登记合格、快照未失效。
exact    是【集合关系精确匹配】。

⇒ 两个 exact 记录配一份不合格登记 ⇒ eligible=False
⇒ 两个 partial_overlap 记录配一份合格登记 ⇒ eligible=True
⇒ 维度不同，不可互推。
```

**③ 读取、校验和消费不是经证明的原子事务**

```text
verify_recovery() 内部顺序是：取回 → 校验 → 判资格。
这三步之间，store 可能被别的代码改动。

⇒ snapshot_token 能【事后发现】这种改动（stale_check），
   但不能【阻止】它发生。
⇒ 「检查时一致」与「消费时一致」是两件事。
```

## 三 · 事项 B：可信链外锚点排除在本原型范围之外

```text
TRUSTED_CHAIN_ANCHOR  = NOT_ESTABLISHED
TRUSTED_ANCHOR_SCOPE  = OUT_OF_SCOPE_FOR_PROTOTYPE
```

### 内部链能证明什么

```text
✓ 第 N 版由第 N−1 版派生（prev_digest 链）
✓ 期间没有绕过链直接改内容（snapshot_token 覆盖 history 全字段）
✓ 观测记录在链内、篡改会断（_observed_chain）
✓ 这些检查在【本机此刻】是自洽的
```

### 不能证明什么

```text
✗ 第 1 版真的等于当年真实发生的那句话
✗ 篡改者没有在记录诞生之前重写全部历史
✗ 这条链连接的「过去」是真实的
```

```text
⇒ 后者需要一个【链外、不可被同一进程改写】的锚点：
   可信时间源 / 第三方签名 / 文件系统之外的存储。
⇒ 单进程原型内不存在这样的东西。
```

### 为什么不批准「临时构造一个名义上的独立信任根」

凌翼明确不批准。我理解的理由：

```text
在本原型内能造出来的「锚点」，一定也在这套代码的可写范围内。
⇒ 它证明不了任何代码外的东西，却会让报告看起来有来源验证。
⇒ 那比明说「没有锚点」更危险 —— 因为它制造了一个假的已验证信号。

⇒ 这正是这一路在治的病：把「我看不到」写成「不存在」的镜像，
   把「我造了一个」写成「我建立了一个」。
```

### 因此不得只用 `is_scientific_result=False` 代替声明

```text
一个 False 不携带任何信息：
读者无法从它得知「缺的是哪一类证据」。

⇒ 现在每条返回都带 scope_declaration，逐项写明：
   - 门禁档位（VERIFIED_ENGINEERING_SYNTHETIC）
   - 证据来源（SELF_TEST_REPORTED）
   - 锚点状态与范围（NOT_ESTABLISHED / OUT_OF_SCOPE_FOR_PROTOTYPE）
   - 三项未建立的独立证据
   - 三条已知边界（known_limits）
```

## 六 · 我给这套东西的定性

```text
它是一套【能把「没核过」和「核过了」分开】的工程实现。
它不是一套【能证明「核过的东西是真的」】的系统。

前者靠断言、变异、分类、台账做到；后者需要原型之外的东西。
```

**这句话我建议放在每一份对外报告的开头。**
因为读者最容易犯的错，就是把第一句读成第二句。
