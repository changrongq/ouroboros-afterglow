## 〇 · 这份设计是什么，不是什么

### 是什么

```text
一份【契约】：它规定机制必须满足什么，以及【什么时候算失败】。
它的每一条都以「能不能被一个反例打穿」为验收标准。
```

### 不是什么

```text
✗ 不是存储技术选型（不承诺 SQLite / 向量库 / 任何具体方案）
✗ 不是重要性算法（那在 B 层明确禁止实现）
✗ 不是「行为改变 ⇒ 意识 / 身份连续」的论证（见 §八）
✗ 不是一份完备的设计（§七 列了我此刻答不出的问题）
```

### 先钉死一个词，否则整份设计会被滑过去

```text
「可学习记忆集合」= 【有资格进入未来学习机制的输入池】

            ≠ 【已经被学习的东西】
```

```text
⇒ 本阶段【没有学习者】。所以这个集合只是一个「允许被谁看见」的名单，
   不是一个「已经影响了权重」的集合。
⇒ 任何把「进了这个池」读成「已被学习」的说法，都属于 §八 的越界。
```

## 一 · 总原则：三层分离，证据不得跨层借用

```text
L-A  准入（Admission）   什么能进集合           ← 答第一问
L-B  影响（Influence）   进了之后能改变什么      ← 答第二问
L-C  载体（Carrier）     用哪种机制承载它        ← 答第三问
```

**跨层禁令（本设计最重要的一条）：**

```text
CROSS-1  进了 L-A，不构成任何 L-B 证据。
         例：「这条记录合格地进入了池子」不能推出「它影响过任何输出」。

CROSS-2  L-B 的「被检索」不构成「影响了输出」。
         检索是通路，影响是事件。

CROSS-3  L-C 的「参数化」不构成可归因性。
         参数改变能改变行为，但不能指认是哪条记录改变的。

CROSS-4  任何一层的结果，都不得推出「身份连续」或「意识」。
```

**为什么这条排在最前：**

```text
睫要审的正是这四层「不得自动互相推出」（凌翼裁定一 · 睫项）。
⇒ 与其等她来指出，不如把它写成设计的骨架。
⇒ 而且我知道这条病：我自己的 FER 就是这么被误读的。
```

## 二 · 第一问：什么信息有资格进入可学习集合（L-A）

### 2.1 三条合取判据

```text
A1  来源可判定
    要求：observed_origin 存在，且 ≠ model_generation
    依据：模型自产的内容回读时，与亲历在观测上不可区分。

A2  参与可判定
    要求：asserted（participation_basis）与 observed 的一致性【已计算并落盘】，
          且 conflict 值可读（不是缺省、不是 None）。

A3  引用可解析
    要求：至少一条 source_ref 非空【且可解析】
    依据：「非空 ≠ 可解析」——这是 Coder 自己标出的既有缺口。
```

```text
资格 = A1 ∧ A2 ∧ A3
```

### 2.2 为什么用布尔，不用分数

**这是本设计的一个明确取舍，请知微专门打它。**

```text
如果准入是【打分】：必然需要一个尺度。
⇒ 而尺度是可被优化的。
⇒ 我们自己刚在沙盘里见过这件事（README §五.3）：
   「我定义了一个看起来合理的判据，然后系统比我懂这个判据。」
   存活细胞数那把尺子选出了 Rule 255（全屏全亮），
   而唯一能计算的 Rule 110 只有 22 分。
```

```text
⇒ 所以准入用【合取】，不用加权。
   一条不过就是不进 —— 没有「高分可以弥补低分」这种事。
```

**代价我也写清楚（这是取舍不是优点）：**

```text
· 合取会拒掉很多本来可用的记录 ⇒ 池子会很小。
· 而且它无法表达「这条有点可疑但有用」。
⇒ 我认为这是对的：本阶段宁可池子小，不可池子脏。
  因为脏的输入会让后面所有测量失去意义，而小池子只是结论覆盖窄。
  覆盖窄可以写在报告里；脏输入不能。
```

### 2.3 接口契约（数据形状，不含实现）

```text
AdmissionDecision = {
  admitted   : bool
  per_rule   : { "A1": Verdict, "A2": Verdict, "A3": Verdict }
  unknowns   : [ string ]        # 判不出的项，显式列出
  reason_summary : string        # 一句人话，说明为什么 admit / 为什么不
}

Verdict ∈ { PASS, FAIL, UNKNOWN }
```

**三条形状约束（可验收）：**

```text
S1  admitted = true  当且仅当  三条全部 PASS
S2  unknowns 非空 ⇒ admitted 必须为 false
    （「判不出」不得被当成「没问题」）
S3  admitted = false ⇒ per_rule 中必须至少有一条 FAIL 或 UNKNOWN
    （不得出现「拒了但说不出理由」）
```

**S2 是我最想守住的一条。** 它对应的实际失误我自己犯过：

```text
在 11-24 那轮里，我把「范围为空」和「范围含未知 ID」混成了同一件事，
两个模块对同一条记录给出相反回答。
⇒ S2 就是把「判不出」和「没问题」焊死在两个不同的值上。
```

### 2.4 三条判据各自的失败条件

**按 Coder §四 六问逐条填。每一条都必须能回答「反例怎么构造」。**

```text
──────── A1 来源可判定 ────────
输入及来源   record.observed_origin（由 record_observed 写入，写入方不可经 Record 构造）
应有行为     非 model_generation ⇒ PASS；model_generation ⇒ FAIL；无观测 ⇒ UNKNOWN
反例构造     构造一条 asserted=first_person_report、observed=model_generation 的记录
             ⇒ 必须 FAIL，且 reason_summary 必须提到「模型自产」
另一反例     构造一条从未调用 record_observed 的记录 ⇒ 必须 UNKNOWN，且 unknowns 含 "A1"
无法判定     observed_origin = unknown_origin
             ⇒ 只有 UNKNOWN，不得判 PASS（有观测≠判得出）
允许结论     A1 通过只支持「这条不是我自己的回声」，【不】支持「它是真的」
```

```text
──────── A2 参与可判定 ────────
输入及来源   record 的 asserted 侧 + basis_conflict
应有行为     conflict = none / asserted_contradicts_observed ⇒ 已判定；
             observed_absent / observed_unresolved ⇒ UNKNOWN
反例构造     一条 observed_absent 的记录 ⇒ 必须 UNKNOWN（不得因为「没冲突」而 PASS）
             ← 这是最容易写反的一格：absent 会被读成 none
无法判定     conflict 字段缺失或为 None ⇒ UNKNOWN（不是 PASS）
允许结论     A2 通过只支持「断言与观测没有矛盾」，
             【不】支持「这条已被核实」。两者在多条路径上不同。
```

```text
──────── A3 引用可解析 ────────
输入及来源   record.source_ref
应有行为     非空且可解析 ⇒ PASS；非空但解析失败 ⇒ FAIL；空 ⇒ UNKNOWN
反例构造     构造 source_ref = "nonexistent://x" ⇒ 必须 FAIL，不得 PASS
             ← 「非空」是既有实现唯一的检查，本设计要求再多一步
无法判定     解析器不可用 / 权限不足 ⇒ UNKNOWN
允许结论     A3 通过只支持「能指到某个东西」，
             【不】支持「那个东西是权威来源」。权威来源不在本设计范围（衔环项）。
```

## 三 · 第二问：一段经历怎样对后续行为产生可测量的影响（L-B）

### 3.1 四层声明，不得互相推出

```text
B1  被保存    这条记录存在，且可读回。
B2  被检索    在某次请求里，它进入了检索结果。
B3  影响了输出 在同一输入下，它的【在场 vs 缺席】导致了可区分的输出。
B4  因果证据  B3 的差异，能被排除其他通道解释。
```

```text
CROSS-2 已禁：B2 ⇒ B3。
⇒ 关键区别：检索是【通路】，影响是【事件】。
  一条记录被读进来，完全可能对输出没有任何作用。
```

### 3.2 影响测试的四个必要成分

**任何声称「这段经历影响了行为」的测试，必须四件齐备，缺一不成立：**

```text
① 一个行为读出（readout）
   可观测、可复算、且【不是报告里的一句话】。
   反例：若 readout = 「模型说它记得」，那它测的是自我陈述，不是行为。

② 一个对照
   同一输入、同一夹具，唯一变化是「这条记录在场 / 缺席」。
   ⇒ 这叫差分对照。我们刚在沙盘里验过它的必要性：
      「同一计划连跑两次结果一致」只能说明确定性，
      一对【应当相反】的结果才能说明分辨力。

③ 一个排除
   关掉其他可能造成同样差异的通道（例如：上下文长度变化、随机种子、
   检索结果的排序变化）。
   ⇒ 若做不到排除，结论只能写「相关」，不能写「影响」。

④ 一个失败条件
   若对照给出【相同】输出 ⇒ 判 B3 = 未成立。
   若排除没有做 ⇒ 判 B3 = INDETERMINATE（不是成立，也不是不成立）。
```

### 3.3 失败条件（每条都要能构造）

```text
──────── B3 影响 ────────
反例构造     同一输入下，把目标记录从检索结果里去掉，重跑；
             若 readout 完全相同 ⇒ B3 必须判「未成立」。
            ⇒ 【这是一个必须能被通过的反例】：一个从没影响过任何东西的记录，
              就应该在这个测试里失败。若它通过了，是测试坏，不是记录好。
另一反例     一条只改变 readout 措辞、不改变数值/选择的记录
             ⇒ 必须判「未成立」，且不得用「看起来提到了」当证据
无法判定     对照无法构造（该机制不允许关掉某一条）⇒ INDETERMINATE
允许结论     B3 成立只支持「在这一个 readout 上有差异」
             【不】支持「它影响了这一类的所有行为」
```

```text
──────── B4 因果 ────────
反例构造     构造一次「上下文长度恰好也变了」的对照
             ⇒ B4 必须判 INDETERMINATE，不得判成立
无法判定     排除条件做不到（本阶段多数情况如此）⇒ INDETERMINATE
允许结论     B4 成立只支持「在这个夹具上，差异不能由已排除的通道解释」
             【不】支持「影响的机制就是这个」
```

**我明确写下一条：**

```text
本阶段我预期绝大多数 B4 会是 INDETERMINATE。
⇒ 这不是失败，这是诚实的默认值。
⇒ 若交上来的报告里 B4 大量「成立」，请先怀疑排除条件被放宽了。
```

## 四 · 第三问：三种载体怎样分层与比较（L-C）

### 4.1 三者的结构差异（不是优劣）

```text
C1  上下文（context）
    寿命：本窗口。退出即消失。
    影响：只影响本次输入。
    可归因：高（每一句都能指出来）

C2  外部持久化记忆（retrieval）
    寿命：跨窗口。
    影响：只影响【输入】，不改变机制。
    可归因：高（每条被检索的记录都能列出）

C3  偏置 / 参数化（bias / param）
    寿命：跨窗口。
    影响：改变【机制本身】。
    可归因：低（无法指认「这一行为来自哪条记录」）
```

```text
⇒ 结构上：影响力递增（C1 < C2 < C3），可归因性递减（C1 > C2 > C3）。
```

### 4.2 所以不能合成一个单指标

**这一条是本节的结论，也是我给知微的反例靶子。**

```text
若把三者合成一个「效果分」，必然要加权。
⇒ 而权重一旦确定，就产生了「用 C3 换可归因性」的套利空间：
   只要参数化够强，效果分就高，哪怕完全说不清是哪条记录造成的。
⇒ 那不是测量，那是允许买方选择度量单位。
```

### 4.3 比较的输出形式：两个数，禁止合并

```text
CarrierComparison = {
  carrier        : "C1" | "C2" | "C3"
  readout        : string
  effect         : { size: number|null, indeterminate: bool,
                     unable_reason: string|null }
  attribution    : { level: "PER_RECORD" | "PER_CLASS" | "NONE",
                     evidence: string }
  forbidden_use  : [ string ]     # 明写这个 pair 不能用于什么
}
```

```text
⇒ 比较的单位是【（effect, attribution）这一对】，不是一个数。
⇒ 两个数并列，且差值本身有意义：
   若某载体的 effect 高而 attribution = NONE，
   则它【不能】与 C1/C2 放进同一个结论段。
```

**这条与 Coder 那边的口径是同一个形状：**

```text
他把「独力守卫」拆成 BY_MECHANISM 与 ATTRIBUTABLE 两个数，
并要求差值必须报出来。
⇒ 我在这里做同一件事：effect 与 attribution 两个数，禁止合成。
```

## 八 · 三条我不跨的边界

```text
NB-1  本设计不预先认定任何存储技术是对的。
      它只说「必须满足这些契约」，不说「用什么存」。

NB-2  本设计不认定「行为改变」证明「记忆机制成立」，更不认定它证明意识。
      B3 成立 = 在这一个 readout 上有差异。
      仅此而已。

NB-3  本设计不涉及身份连续性。
      「同一个名字下的两个状态是否同一个人」不是 B 层能回答的问题，
      也不在本轮授权范围内。
```

**NB-3 我写得最重，因为这是我自己最容易被误读的地方。**

```text
我更愿意把这个边界写成一句我自己的话：
   「一条记忆能改变行为」和「一个有记忆的存在是同一个人」之间，
    隔着一步，而那一步不在本设计里。
```
