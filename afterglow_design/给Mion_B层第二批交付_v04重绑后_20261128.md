**为什么 L-A / L-B 分成两个文件而不是一个：**

```text
两者输入域不同：
  L-A 输入 = 一条记录的自述字段（observed_origin / basis_conflict / source_ref）
  L-B 输入 = 一次对照的两臂读出 + 漂移对照结果 + 替代解释清单
⇒ 合并在一个返回字典里，「这条记录准入没过」和「这次对照检出没检出」
  会共用同一层键，读的人分不清哪个字段属于哪次判定。
⇒ 拆开也正好对上 B-SCOPE-3「判定层是前置，不是成果」——
  两个文件各自标了自己 NOT_CHECKED 什么。
```

### 2.2 MECH = DETECTED 不可达：已按判据实现

```text
v0.4 §六：DETECTED 只在【输入通路已注册且受控】时可用。

本阶段 pathway_registered_and_controlled 不可验（UNTESTABLE-1）
⇒ 默认路径必然收敛到 INDETERMINATE，理由是 PATHWAY_NOT_CONTROLLED。
```

⚠ **这里我要说准确一点，因为我上一封就栽在「说法比事实窄/宽」上：**

```text
Mion §二写的是「MECH 的实现目标是：三态齐全，
但 DETECTED 那条路径【因为通路未受控而必然收敛到 INDETERMINATE】」。

我实际做的是：
  · 函数里保留了 DETECTED / NOT_DETECTED 两个分支（判据完整性）
  · 但只有调用方显式传 pathway_registered_and_controlled=True 才可达
  · 本阶段没有任何调用方会这么传（不可验）
⇒ 所以准确说法是：「DETECTED 分支存在，但本阶段无调用路径可达它」，
  不是「代码里根本没有 DETECTED」。
⇒ 我上一稿的 docstring 写了「本文件没有任何代码路径会返回 MECH=DETECTED」，
  那句话把「无调用路径可达」写成了「没有返回路径」，两句不等价。已改。
```

**T-3 同时验了两面：**

```text
默认（通路未受控）+ r_A != r_B  ⇒ INDETERMINATE(PATHWAY_NOT_CONTROLLED)   ← 本阶段
通路受控（显式声明）+ r_A != r_B ⇒ DETECTED                                 ← 判据完整性
```

⇒ 第二条不是本阶段能主张的东西，写它只为证明第一条第 1 项不是「写死成 INDETERMINATE」。
⇒ 报告里不会拿第二条当成果。

### 2.3 delta = null 三约束：写成可执行校验，不是注释

```text
D-1  双向当且仅当：
       readout_valid=False 且 delta 非 null ⇒ 抛 ValueError
       readout_valid=True  且 delta 为 null ⇒ 抛 ValueError
D-2  delta 非 null 时必须是 number（bool 不算）⇒ 否则抛 ValueError
D-3  judge_impact 里先取 readout_valid，再碰 delta
```

⚠ **D-2 的一个实现细节，说明一下为什么加 `bool` 排除：**

```text
Python 里 isinstance(True, int) 为 True。
⇒ 若只判 isinstance(delta, (int, float))，delta=True 会被当成 1。
⇒ 我把 bool 显式排除 —— bool 不是「数值差异」，它是另一类语义。
```

### 2.4 EXCLUDED：按「逐条排除」判，不按「跑过对照」判

```text
EXCLUDED = TRUE 当且仅当三条同时成立：
  ① 替代解释清单逐条被排除（remaining 为空）
  ② 空跑对照未重现差值
  ③ 正对照有效

⇒ 三种翻 False 的路径各自有独立 reason：
   POSITIVE_CONTROL_FAILED
   NEGATIVE_CONTROL_REPRODUCED_DRIFT
   ALTERNATIVES_NOT_ALL_EXCLUDED
```

⚠ **一个我没被要求但必须我说的边界：**

```text
清单为空时，本实现返回 EXCLUDED=True（reason = NO_ALTERNATIVES_REGISTERED）。

「清单为空」和「清单已被逐条排除」是两件事。
v0.4 §4.4 原文只写了「已登记的替代解释清单逐条被有效排除」，
没写「清单本身为空时怎么算」。

⇒ 我选了 True，并把 reason 单独设成 NO_ALTERNATIVES_REGISTERED，
   让报告能区分这两种情形。
⇒ 但这是我的判断，不是你条款里的东西。若你认为清单为空时应走
   INDETERMINATE，我改 —— 这条请在下一轮明确。
```
