## 一 · E-21 · `EXCLUDED` 形状与两条不变量

```text
E-21-1  双向不变量：
          EXCLUDED is None      ⇔  INDETERMINATE is True
          EXCLUDED in {True,False}  ⇒  INDETERMINATE is False
        ⇒ 必须【双向】，不得只单向。
        理由：单向（None ⇒ flag=True）允许 flag=True 而 value=False 的坏状态存在。

E-21-2  本层内不得对 EXCLUDED 做布尔化消费：
        ✗ if excluded:
        ✗ bool(excluded)
        ✗ excluded or default
        ✓ 必须显式三路（is None / is True / else）
        ⇒ 实现手段：AST 检查（不用文本 grep，见 E-26）
```

**形状的选择理由（Coder 提供，本件采纳）：**

```text
EXCLUDED ∈ {True, False, None}
⇒ 只做字符串三态会让 if excluded: 把 "INDETERMINATE" 当真值；
  只做 False + flag 则这一格仍不可区分。
```

**本件补正一句：**

```text
⇒ 那个理由对 None 同样成立（if None: → False，与 False 不可区分）。
⇒ 所以"选 None"的理由不是"避免被误用"，而是"它能被表示出来"。
⇒ 误用问题只能靠 E-21-1 / E-21-2 守，形状解决不了。
```

## 二 · E-22 · `MECH = DETECTED` 的不可达性

```text
E-22-1  pathway_registered_and_controlled = True  ⇒ 抛 UnsupportedPremise
        （不是 ValueError，不是返回 INDETERMINATE）
        理由：这在本阶段不是一个"可以成立的输入"，而是一个【不该被提出的前提】。
              ValueError 会被读成"你传错了值"；这是"这个前提本阶段不存在"。
              ⇒ 区别在【谁来修】。

E-22-2  入口清单必须显式登记（4 个，逐个点名），并逐个断言会抛同一个异常。

E-22-3  必须写出【穷尽性的依据】，三选一：
          (a) MECH 的构造点唯一，且该构造点已覆盖 ⇒ 可断言穷尽
          (b) 不可穷尽 ⇒ 显式标 COVERAGE = PARTIAL_FOR_REGISTERED_ENTRIES，
              并说明未覆盖部分如何被发现
          (c) 两者都做不到 ⇒ 这条只是说明，不是断言
        ⇒ 选不出 (a) 就必须写 (b)，不许沉默。
```

**Coder 选 (b)，理由本件采纳为正确：**

```text
(a) 只证明「产 MECH 的地方唯一」，不证明「调用方不会传 True」。
⇒ 后者在参数空间上不穷尽。
```

## 五 · 这一件的教训（写给下一个读的人）

```text
我把一份【信里的摘要】当成了【已存在的文档】，并把它写进 BINDING。
⇒ 这不是"忘了推送"，是"以为写了，其实只写在了信里"。

⇒ 与勘误003 的 E-13 相比，它更进一层：
   E-13：文件在我本地，我没推。
   这一件：文件【从来没有】。
   ⇒ 前者的补救是"推"，后者的补救是"区分两类写作"：
     信里的段落 ≠ 可被 BINDING 引用的文档。
```

**所以新增一条（本件，E-23 之外）：**

```text
E-27  凡写入 BINDING 的文档，必须在【同一动作】里确认它在仓库中存在
      （取一次 blob / 列一次目录），不得凭"我写过"或"我提过"记入。
      理由：BINDING 是一份【指向物】的清单，指向不存在的路径，
            等于让所有下游引用悬空。
```

**而这条是被谁触发的，我也记下来：**

```text
是荣弦看到我说"推送了"，去仓里看不到，才问的。
⇒ 我没有自己发现。
⇒ 而 E-27 那条确认动作，只要做一次就能发现 —— 说明我的问题不是不知道要做，
   是【没在做】。
```
