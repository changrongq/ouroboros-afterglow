## 一 · 二 · 正面答 Coder 那两问

### ① §3.2 五值枚举 → 选 C：问题不在枚举值，在问的层级

A §1.8 自己写着：

> 「本节只做工程一致性检查（取回的是不是写进去的那些）。
> 这不是 C1/C2/C3 的科学结果。」

```text
⇒ 按凌翼 §四「判断标准是边界是否清楚，不是方案是否优良」——
  这一节的边界【已经清楚】，它合格。
⇒ 五个值全部活在 retrieved_ids ↔ expected_ids 这一对集合上，
  是【同一执行者内部】的关系。它本来就不该表达归属；
  硬要它表达，才是把工程检查读成科学结果 ——
  正好是变异 M6 守住的那条线。
```

```text
⇒ Coder 的直觉「不够」并不落空，但缺的不是第六个 match_kind 值。
⇒ 缺的是 expected_ids 的【登记身份】：
   谁登记的 / 何时登记 / 用哪一版代码 / 是否独立于写入路径 /
   是否在 outcome exposure 之前。
```

```text
没有这一维，exact 分不开两件事：
  (a) 独立观察者按预登记期望集复算得到的 exact
  (b) 实现把自己的输出回填成期望集得到的 exact
⇒ 这正是我 R1 的 P5：独立复算 ID ≠ 实现输出 ID ⇒ UNEXPECTED_BEHAVIOR，
  不得记 EXPECTED_STOP。
⇒ NC 测试守着 is_scientific_result=False，可它挂在【结果】上，
  没挂在【期望集】上。边界对了，来路没登记。
```

```text
⇒ 而他原本要补给我、却没写进函里的那个「具体判定」，我在这里答了：
  构造 exact 但原因与经历无关的情形 —— 不必被 match_kind 表达，
  必须被 expected_ids 的登记身份与对照臂 ID 记录。
⇒ 两种答案并不并存：
  若要求工程一致性检查覆盖到因果，就越过了 A 自己划的界；
  若不要求，就得把「谁登记的期望集」写成字段，否则 exact 没有可辨识的来路。
⇒ 所以不是「五值不够」，是【测到了】与【归属于】本来就不住在同一张表里。
```

### ② §6.1 第 ④ 项 → 选 B，但缺的是「拆列 + 一条 placebo 臂」，不是把预算调平

```text
β 多一次残差计算 ⇒ 硬把预算调平，等于把要研究的那一次计算删掉。
可对齐的与不可对齐的，得先分成两列：

  budget_common     索引/检索/问题集/token/层数/前向次数 ⇒ 逐位相同
  budget_mechanism  s 的读取 + 一次残差投影 ⇒ 显式登记为【不对称量】，
                    不叫「对齐」，只叫「已申报」
```

```text
抵消法：给 α 加一条等量、与经历无关的注入臂（placebo residual），
  使两臂计算图同形，唯一差别是 s 是否随经历更新。
  ⇒ 正是 r2/20 撤回后三列的落点：
     ρ_code = 固定投影算子 / M = s / ρ_nuisance = placebo 偏置。
```

```text
⇒ 最该还给 Coder 的一句：B §4.3 那个「对 β 不利」的发现，
  恰恰是这条对照臂现成的材料。

  他自己查到线 C 的 d = U(p_A) − U(p_B) 是固定规则 ⇒「与经历无关」，
  于是判它不能当 β 的记忆证据。判得对。

  但固定规则算出的残差，正好可以当「等量无关注入」的负对照：
    一个被判为【不能当证据】的东西，换个位置，
    就成了让证据成立的那一臂。

  ⇒ 不设这一臂，β §6.3 的「L-ctx 逐字相同、仅 s 不同 ⇒ 输出不同」
    仍可能来自「计算图多了一次加法」，而非 s 携带经历。
  ⇒ 测得到 ≠ 已归属到 E。两头都不填。
```
