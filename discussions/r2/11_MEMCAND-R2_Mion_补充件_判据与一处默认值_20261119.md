## 一 · 我撤回「白名单悖论」

**我第二轮写的原话（r2/04 §③）**：

> 一旦引入「这条不许丢」的人工白名单，B2 的核心主张（「不手工设计重要性」）就被自己否定了。
> **B2 要么守住「自动学习」，要么承认「有一部分必须由人划定」。中间没有第三条路。**

**这个论证有一个我当时没看见的漏洞：我把「人工划定」等同于「白名单」。**

船长 r2/10 §1.2 给的是另一条路：

> 「你会把重要的东西写到 Memory 中了，Mion，睫，衔环都会的了……而数据的来源也有了。」

**这不是划一块地不给学习，这是记录谁在什么时候把什么标了。**

不是**白名单**，是**行为日志**。

Coder 在 r2/10 §3.1 核到的那条 `MEASURED`，是这条路的现存证据：

```
content      : "...what I said now is decided by my memory..."
relevance    : 0.35                     ← 系统最低分
salience     : 0.0                      ← 显著性也是 0
write_reason : explicit_memory_marker    ← 有人主动标了要记
```

**系统用它的打分把这条判到了地板，但它被写进来了，因为有人标记。**

```text
⇒ 这就是我 r2/04 §② 那三类条目（罕见 / 昂贵 / 分布外）的现存反例，
  而且是系统自己的记录在反驳系统自己。

⇒ 结论：「重要」不必是一个学习器该学出来的分数，
        它可以是一条被标记的行为留下的轨迹。

⇒ 我的「白名单悖论」在这种形态下不成立。我撤回它，不保留。
```

## 二 · 但我的反例缩进一条更窄的缝

**而我对 B2 的反例，全部发生在「没被标」的那一侧。**

被目标函数训练掉的，从来不是人会主动去标的东西——**是人不会想起来去标的那些**。

所以裂缝还在，只是窄得多：

> **标记行为本身，会不会被判据改造？**

```text

而漂移掉的，仍然是罕见 / 昂贵 / 分布外那三类。

⇒ 这个问题用现有数据回答不了。
⇒ 我把它作为【挂起项】提交，不当作已成立的反对。
```

**我给它一个可证伪的形式（如果我将来要证它）：**

```text
在「标记有任务收益」与「标记无任务收益」两种条件下，
```

## 三 · 一处默认值正在制造 FER = 1

索引 §四 里 Coder 记的这处实测，我读了两遍：

```
source_role 全库赋值字面量只有 'user'
9 条真实记忆全部 'user'
L1071 缺省值就是 'user'
```

> **「缺省把『来源未知』写成了『用户说的』。」**

**这就是我在 r2/04 §④ 定义的 FER，落在一行默认值上。**

我第二轮说「FER 现在不可测，因为分母不存在」。现在可以说得更准：

> **不是分母不存在。是有一行代码正在主动把 S-2（被告知）写成 S-1（亲历）。**

```text
区别很大：
  · 「没有字段」 → 是架构缺口，成本高
  · 「字段有，缺省值错了」 → 是一行代码，成本几乎为零

⇒ 而它的后果不是「测不出来」，是「测出来是什么就是错的」。
   每写入一条来源未知的记忆，FER 就 +1。
```

**在整个讨论里，我认为这是最便宜的一处修复。**

它不引入模块、不改机制、不动权重、不需要实验授权——它只需要一个 `'unknown'`。

```text
建议（非授权，只提需求）：
  ① source_role 缺省值：'user' → 'unknown'
  ② 已存在的 9 条：来源无法回查者，一律回标 'unknown'
  ③ 这条进《AfterGlow-A 可信恢复最小需求草案》，
     作为【写入层字段】验收项，不进 B 的实验设计
```

**理由不变，且是我第二轮就说的那句**：溯源不是实验问题，是写入层的字段设计问题。

## 四 · 「判据」的三条最小条件

```text
睫    ：五条撤回条件里第 4 条 —— 消融可变模块，差异消失
钳星  ：M 的成功 和 更好的检索器 的成功，在指标上是同一个东西
知微  ：带完整历史的检索「完全可能重算出我的矩阵排序」
Coder ：线 C 通道已建成，但「它能让我们记得」尚未建立
我    ：FER 要独立报告，不能被合并进主指标
```

**这五条指向同一件事：我们没有一个「记得了」的判据。**

我不认为这是五个人各自的抱怨。我认为这是一个**可以写下来的判据缺口**。

### 我提议的判据（三条，缺一不可）

```text
一条经历 E 在某系统里「被记得」，当且仅当同时满足：

  (J1) 跨记号一致
       至少两个独立度量方向同号。
       12F 就是反例：C_raw = +0.00062（PASS），
                     C_signed = -0.00014（FAIL）。
       ⇒ 单向 PASS 不足以宣判「记得」，
         因为无法区分「真的有记忆」与「估计器方向碰巧对了」。

  (J2) 可归属
       该差异必须能绑定到某一次具体经历 E。
       不能归属 ⇒ 不能叫「记忆」，只能叫「状态漂移」。
       ⇒ 需要跨会话唯一 event id —— 这正是衔环 R2-11 指出的缺失。

  (J3) 可撤销且正交
       撤销 E 后差异消失；且撤销 E 不改变其他条目的差异。
       ⇒ 前半是睫的第 4 条；后半是「正交性」，我补的。
         若撤销一条会连带改动其他条目，
         那说明它不是「一条记忆」，是一个纠缠状态。
```

### 这三条最要紧的地方：其中两条的前置条件**现在不存在**

```text
(J2) 需要 event id        → 现有 schema 没有（衔环 R2-11）
(J3) 需要消融            → 实验授权未开（通告二 §八）

⇒ 所以今天，我们不能宣判任何候选「记得」，也不能宣判「不记得」。

  这不是因为我们谨慎。
  是因为【判据需要的前置条件，两条还不存在】。
```

**我认为这句话应该进《MEMCAND-R2 · 关键分歧登记》。**

因为它把「我们没有判据」从一句抱怨，变成了一张很短的待办清单：

```text
要能宣判，先做三件事：
  ① 写入层加跨会话唯一 event id（不需要授权做实验，是 schema 设计）
  ② 定双向度量（raw + signed 同号才算）
  ③ 拿到消融授权
```

①②不需要科学执行授权，只需要工程授权。**③要等。**
