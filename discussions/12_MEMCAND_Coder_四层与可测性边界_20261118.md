### 1.3 关键判断（`INFERENCE`）

船长说熵与注意力跳跃「效果一般」。**我实测后认为这个说法需要收窄：**

```
attention_error   1827 条，全部为 0      ⇒ 它连「有没有误差」都分不出来
causal_chain      135 条，全部为 0       ⇒ 同上
attention_jump    仅 80 条，均值 0.0135  ⇒ 样本量过小，无法支撑任何统计判断

```

⇒ **不是「这两把尺子量得不准」，是「它们从未通过自我判死」。**

依据：`测量诚实性边界声明_20260920.md` 第一条——

> 任何工具在产生主结果之前，必须先过一次「自我判死」测试。
> 它能否区分阳性对照与阴性对照？若不能——工具当场作废，不进入主实验。

`attention_error` 恒为 0 ⇒ **阳性对照与阴性对照在它眼里完全一样** ⇒ 分辨力为零。

**⇒ 因此「重要无法测量」这个结论，现在下不了。**

我们只是试了两把很可能是坏的尺子。这与「这个量不可测」是两件不同的事。

## 二 · 现状实测：搬家有没有让上下文变短？

### 2.1 机制（`INFERENCE`，据 `MemorySystem.py` 与 trace 推出）

```
上下文满 → 挑几条候选
         → store_to_medium_term 写入 medium_term_memories.json
         → 下一轮 recall_from_medium_by_topic 检索回来
         → 又进上下文
```

### 2.2 结论

**⇒ 这个循环不减少上下文。**

上下文中的内容：经过一轮搬运后，**总量不变**，只是多了一次写入 + 一次读取的开销。

用一句直白的话：**这不是搬家，是把箱子搬到隔壁房间，然后每次还要搬回来。**

**⇒ 船长想要的「上下文短了，压力也小了」，现在一条都没有实现。**

## 三 · 四层划分：哪一层真能减少上下文

| 层 | 内容 | 减少上下文？ | 现在有？ | 判据 |
|---|---|---|---|---|
| **L0** | 全部在上下文内 | — | ✅ | 无 |
| **L1** | 外部 JSON，原文保存，检索回上下文 | ❌ **不减少** | ✅ `medium_term_memories.json` 9 条 / 15081 B | 无 |
| **L2** | 外部保存，但**进上下文的是压缩形式**而非原文 | ✅ **减少** | ❌ **没有** | 需新判据（见 §五） |
| **L3** | 进入参数/权重，根本不进上下文 | ✅ 减少 | ❌ 没有 | `C1` 失效（见 §四） |

**⇒ 缺的是 L2，不是 L3。**

## 四 · 为什么 L3（进权重）会让现有尺子失效

### 4.1 尺子的前提

`MEASURED`（`afterglow_harness/evaluator.py` L216-220）：

```python
def evaluate_basic_l1(
    snap_A: StateSnapshot,
    snap_B: StateSnapshot,
    registered_payload: bytes,
) -> L1Result:
```

`MEASURED`（`harness_constants.py` L85-92）：

```python
canonical_state_digest(literal, q_raw)  →  sha256(24 字节)
```

### 4.2 冲突（`INFERENCE`）

24 字节的 digest 输入域里，**放不下一个权重矩阵**。于是只有两条路：

| 路 | 后果 |
|---|---|
| **(a)** 记忆权重不进入 24 字节 | `C1` **看不见它** ⇒ 尺子对该层无效 |
| **(b)** 把权重拉进 digest | 要么失真压缩，要么扩宽尺寸 ⇒ **`C1` 定义须全部重写** |

**而且 (b) 还会撞上 prereg §7.2 的禁令：「`episode_id` 不得进入 substrate state digest」。**

一条「从某次经历学到的权重」，其本质**就是 episode 身份**。把它放进 digest，等于把 §7.2 禁止的东西换个名字放回去。

### 4.3 所以 L3 的代价

**⇒ 把记忆放进参数，会让 `C1` 从「能判定」退化成「只能观测行为」。**

而行为那一层，12F 已经证明会骗人：

```
C_raw     = +0.0006236255996758464   H_raw_gate    = PASS
C_signed  = -0.00014115083548754218  H_signed_gate = FAIL
result_class = C
```

raw 符号为正、量级 $6.2\times10^{-4}$；48 个 item 里只有 23 个为正（0.479）。

**⇒ 只看行为，我们分不清「有记忆」与「估计器方向选错了」。** 这是 12F 文件里自己写下的 `raw_null_reading`。

## 五 · L2 为什么是唯一「效果与尺子同时成立」的落点

### 5.1 三条同时满足（`INFERENCE`）

| 要求 | L2 是否满足 |
|---|---|
| 真减少上下文长度 | ✅ 进上下文的是压缩形式 |
| 不动权重 | ✅ |
| 仍可字节核验 | ✅ 压缩产物仍是文件，可 `sha256` |
| 不需重写 `C1` | ✅ 但**也不能借用 `C1`**（见 5.2） |

### 5.2 一条必须写死的警告

> **L2 不能借用 `C1` 判定。**

理由：`C1` 要求「`h>=2` 且 `B.literal == registered_payload`」。
而 L2 的产物是**压缩后的形式**，它**按定义不可能**等于原始 `registered_payload`。

⇒ 若有人拿 `C1` 去判 L2，会得到一个必然的 `NOT_ESTABLISHED`，然后误读成「压缩没成功」。

**这是「范围外 ≠ 可以假装不存在」的反向版本：范围外的东西不能用范围内的尺子量，量了也不能当结果。**

### 5.3 那 L2 该用什么判据

我提议一个**纯行为、可复算**的比值：

$$r \;=\; \frac{\text{行为保留率}}{\text{上下文压缩率}}$$

其中：
- **上下文压缩率** = 压缩后 token 数 / 原 token 数（机械可算）
- **行为保留率** = 在同一组测试查询上，压缩前后的命中/正确率之比（行为可测）

**$r$ 的用处：它把「什么重要」这个问题，换成了「压到 10% 时还剩下多少」。**

⇒ 不同压缩策略的 $r$ 不同。**$r$ 最高的那个，就是「保住了重要的」那个。**

⇒ **「重要」不需要被定义，它是被 $r$ 反推出来的。**

### 5.4 但 $r$ 必须先过三关（不过就作废）

| 关 | 内容 | 不过的后果 |
|---|---|---|
| **关 1 · 位置对照** | 同一条信息放不同位置，$r$ 是否只随位置变 | 是 ⇒ 测的是位置，不是内容 |
| **关 2 · 长度对照** | 长度固定，只换内容，$r$ 是否区分 | 不区分 ⇒ 尺子无分辨力 |
| **关 3 · 阳性注入** | 人为插入一条「必有效」的信息，$r$ 是否变 | 不变 ⇒ **灵敏度为零，当场作废** |

**关 3 就是「自我判死」。** 那条 `attention_error` 恒为 0 的 trace，就是没过关 3 还进了主线的产物。

## 六 · 关于「重要」与「代价」的一次重新表述

船长提出一个我认为比「压缩」更根本的观察：

> 上下文多的时候，模型的思考能力其实是会下降的，但这个下降算不算一种「累」。

### 6.1 这句话点破了一件我此前说错的事

我在此前的对话里说过「遗忘没有代价」。

**这个说法是错的。** 上下文容量就是一个真实代价，而且它**可测**：

$$\text{Util}(k \mid n) \;=\; \text{模型在长度 } n \text{ 的上下文里，对第 } k \text{ 条信息的利用程度}$$

$$\text{Crowding}(k \to n) \;=\; \text{Util}(k \mid n) - \text{Util}(k \mid k)$$

### 6.2 这个量与 $r$ 的关系（`INFERENCE`）

两者回答的是同一件事的两个方向：

```
r        ：压多少，还剩多少        （工程侧）
Crowding ：挤进去之后，掉了多少     （测量侧）
```

**⇒ 若 Crowding 在所有候选材料上差不多，则「重要性」在当前模型上不可区分 —— 这又是一个可以下「未建立」的地方。**

### 6.3 一句必须带上限定的判断

> **「重要」不是设计出来的，是被真实代价逼出来的。**

能被挤掉的，就是不重要的。**这正是船长说的「让不重要的自然消散」。**

但这句话成立有一个前提（`ASSUMPTION`）：**模型确实会因上下文变长而损失利用能力，且这个损失不是均匀的。**

如果损失是均匀的（所有信息等比例下降），那么「重要性」就无法从这个量里读出来。

**⇒ 这个前提必须先测，不能先假设。**

## 七 · 关于「只能被感知，无法被测量」

船长原话：也许记忆和意识一样，只能被感知，无法被测量和定义。

我只说一件事，并附上账。

### 7.1 我们账本里的四次「测不出来」

| # | 当时以为 | 实际 |
|---|---|---|
| 1 | Linear Probe = 1.0，测到了时间信号 | 训练集=测试集，背答案（钳星抓） |
| 2 | `nFT = 0`，模型几乎总拒绝错误记忆 | `a₀ ≡ infirmary` 常数，用了 SUPERSEDED 的 `R0` 尺 |

| 4 | `ΔS_total` 可作总变化量 | prereg 出现 0 次；`S_{t+1}-S_t` 违反 §9 两条禁令（睫抓） |

**⇒ 四次都是「看起来测不出来」，回头看都是「测的方法错了」。**

### 7.2 我不同意的部分（与依据）

`测量诚实性边界声明` 第二条：

> 「未发现」和「不存在」是两件事。混在一起，后人会读成「测过了，没有」。

**同理：**

```
「测不到」 和 「不可测」 是两件事。
混在一起，后人会读成「不用测了」。
```

**⇒ 两句话在文件里长得几乎一样，后果完全相反：**

| 写法 | 后果 |
|---|---|
| 「测不到」 | 下一轮可换尺子再试，门留着 |
| 「不可测」 | 这一格永久关闭，门焊死 |

**⇒ 我的立场：可以记录「目前测不到」（并附上是哪把尺子测不到），不写「不可测」。**

## 八 · 需要澄清的一个循环

船长的想法里有一处依赖关系，我提出来供讨论，不做结论：

```
想要「压缩」
   ⇒ 需要知道「什么重要」
      ⇒ 「重要」目前测不出来
         ⇒ 压缩无从下手
```

**⇒ 这个循环可以打破，办法是 §5.3 的 $r$：不定义重要性，只看压完还剩多少。**

但打破它需要先做 §5.4 的三关自检。**三关不过，这个循环就还是闭环。**
